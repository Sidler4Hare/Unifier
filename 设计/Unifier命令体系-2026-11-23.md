# Unifier 命令体系设计

2026-11-23。设计基于 `0.0.8b1+refactor.8`。v0.0.8 的桌面与设备集成按现有范围验收，纯 CLI 整理从 v0.0.9 分批推进。本文中的新增入口与参数为设计项。[现有 CLI](../src/unifier/cli.py) · [现有快捷命令](../src/unifier/shortcuts.py) · [验收计划](v0.0.8-真实功能验收计划-2026-11-17.md)

## 1. 常用入口

| 任务 | 入口 | 约定 |
| --- | --- | --- |
| 首次启用 | `unifier init --target debian13` | 常用入口继续按已选目标初始化。缺少目标时显示明确的配置或准备指令。 |
| 看现在能做什么 | `unifier status`、`unifier list`、`unifier help <命令>` | `list` 展示启用、已准备和实际运行状态。增强后的 `status` 显示软件版本、有效状态根和待恢复对象。 |
| 安装并登记应用 | `unifier install ./软件.deb`、`unifier install --target arch freecad` | 本地包按已认可的格式和元数据路由，仓库包需要目标。包事务完成后沿用原有应用登记和菜单行为。 |
| 打开一个应用 | `unifier run --target arch freecad -- <参数>` | 用已登记的应用、参数和图形集成。若同一目标存在重名应用，提示列出可用 ID。 |
| 查看本机目录 | `unifier dirs`、`unifier path debian13 --files` | 分开显示项目共享目录与系统视图。路径查询保持纯查询。 |
| 修复或管理 | `unifier doctor`、各命名域的 `recover`、`unifier self` | 拟增的 `doctor` 汇总可执行建议，`self` 管理 Unifier 程序版本。恢复动作由有明确对象的现有领域入口执行。 |

双击本地包继续走 `offer`。它沿用交互确认、包路由、退出等待及 MIME 登记。批量安装脚本直接选择 `install` 或 `pkg install`，按既有语义处理退出码。[双击安装流程](CLI安装管理页-2026-11-07.md)

## 2. 管理域

下表中的“增补”表示拟新增能力。带有括号的命令组列出同一父命令下的多个动作。

| 管理域 | 现有入口 | 设计与边界 |
| --- | --- | --- |
| 环境 `env` | `list`、`inspect`、`create`、`start`、`stop`、`remove`、`run`、`export`、身份维护 | `env list` 只列实际登记的环境，`inspect` 显示运行时与登记的差异。主机策略和目标许可沿用 `compat list/check/matrix`。新增 `env remove --plan` 展示数据和应用依赖，实际删除复核身份及活跃租约。 |
| 原生包 `pkg` | `route`、`query`、`install`、`update`、`remove`、`repair-deps`、`log`、`show`、`recover`、`recover-storage` | `pkg` 管客体数据库和事务。`install` 顶层负责面向用户的安装与应用登记。增补 `pkg inventory <env>`，默认读取已记录清单及其新鲜度，明确请求现场查询才走原生观察路径。 |
| 应用 `app` | `add`、`show`、`open`、`exec`、`export`、`unexport`、`remove`、`leases`、`recover`、`cancel` | 增补 `app list --env <env>` 和 `app status <id>`。`open` 走原有受管执行而 `exec` 保留在应用上下文中执行任意 argv 的既有契约。卸载原生包与删除应用登记分别操作。 |
| 桌面与设备 | `env desktop-integration`、`env portal-bridge`、`env render-node`、`env camera`、`app file-chooser`、`app input-method` | 增补统一只读的 `desktop status --env <env>`。修复建议指向现有设置或原生补依赖入口。摄像头与渲染节点沿用明确路径和设备身份，权限和宿主策略由各自入口核验。 |
| 数据根与文件 `root/file/view` | `root add/list/show/match/remove`，`file resolve/copy/move/status/recover/access/plan/open`，`view open/list/status/revoke/recover/readlink` | `root` 管登记，`file` 管文件、操作收据和授权，`view` 管只读投影及租约。普通复制不覆盖。跨根移动需按既有 `--cleanup-source` 与受控源策略删除源。打开系统视图可以挂载，普通状态查询不挂载。 |
| 项目与处理程序 | `project add/list/show/remove/plan/run/shell`、`project session`、`project integration`、`handler add/list/show/remove` | 项目定位使用 UUID 或唯一定位符。会话可查、可精确取消、可恢复；退役会话记录前证明执行已结束。导出和撤销项目入口继续走既有集成日志。 |
| 诊断 `doctor` | `status`、`env inspect/hardware`、`res sample/series`、各域的状态和恢复记录 | 拟提供 `doctor`、`doctor --env <id>`、`doctor --json`。报告宿主准入、状态根、运行时所有权、包恢复屏障、租约、门户、设备、程序版本。缺证据返回 `unknown` 并附检查原因。 |
| 本体 `self` | `--version`、归档清单、用户级安装脚本 | 拟有 `self version/list/check/fetch/install/rollback`。按版本目录安装，再切换已登记的 CLI 和桌面入口。云端打包与发布由仓库维护者使用构建工具及托管端发布流程。 |
| 宿主授权协议 | `agent serve/request`、各 `_worker` 等下划线入口 | 继续供已有调用方使用。公共帮助显示公开承诺；内置入口在维护者文档记录协议、调用者和匹配的工作进程版本。 |

`list`、`start`、`stop`、`adopt` 等顶层快捷操作使用发行版目标和本机配置。`env` 领域面向一个具体登记环境。两者继续按各自语义解析，适合共享实现的部分共用领域服务。[管理页底层命令](../src/unifier/cli.py) · [初次配置契约](CLI首次配置与发行版专用目录-2026-10-29.md)

## 3. 状态根与标识

拟增全局位置 `unifier --state-root 路径 <命令>`。显式选择的绝对路径优先，其次沿用 `UNIFIER_HOME`。未指定时，旧快捷命令继续按用户数据目录查找，旧领域命令继续按其历史默认查找。新增命令显示实际解析结果；遇到两个均含有效记录的根时，提示为本次命令指定一个根。后台工作进程、桌面导出和回退记录固定同一有效根。[当前的根目录解析](../src/unifier/install.py)

- 发行版选择解析为目标，运行、写入和恢复解析为环境记录。运行时绑定包含环境 UUID、代次和完整容器 ID。显示时可以缩写，提交动作前校验完整绑定。
- 启动登记用应用 ID；用户友好别名按目标限定。包名、应用 ID、实例 ID 各自保留。
- 下载和版本化代码目录使用版本、归档摘要及源码身份关联。执行、文件授权、事务和会话分别沿用各自日志中的唯一标识。
- 相对文件路径按调用者当前目录解释。跨状态根的文件操作使用显式登记的源和目标。托管服务与桌面入口的路径转义接受中文、空格及普通文件名。

## 4. 交互、输出与退出码

- `unifier help` 保留常用首页，`unifier help pkg recover` 与对应的 `--help` 提供完整参数及副作用。当前 `--version` 保持与已安装启动脚本一致。中英文遵循现有语言偏好。
- 拟把 `--json` 作为共用选项。管理查询在 stdout 写一份带 `schema_version` 的 JSON，进度和可读诊断写 stderr。新增结果包括有效根、动作对象、`state`、稳定的 `reason_code` 与适用的 `receipt_id`；字段缺证据时用 `null` 并说明原因。
- 现有子命令默认 JSON、文本字段和退出码保留。新纯管理命令采用 `0` 成功、`2` 参数错误、其他非零为业务或运行错误，并以 `reason_code` 细分。执行 guest argv 的通道保留原生退出及信号语义；其 stdout 继续可接管道。
- `--` 之后按原样传递客体 argv。原生安装器的 TTY 输入、窗口变化及 Ctrl-C 继续由已有实现透传。批量模式显式启用非交互，遇到须确认的原生提示应返回可诊断的结果。
- 提示信息显示已经发生的阶段和可复查的命令。例如包已安装、应用登记成功、补依赖仍不完整可以同时记录在同一结果中。

## 5. 维护与恢复

| 场景 | 行为 |
| --- | --- |
| 查询、预检 | 在帮助中标注会访问 Podman、启动客体、打开显示、使用网络或挂载的命令。常用状态与计划本身只读，无法核验存量时显示证据来源和状态。 |
| 有风险的变更 | 环境删除、设备调整、应用菜单撤销或本体换版本前，列出确切对象、会受影响的入口及恢复位置。有计划入口的操作在提交时重新核验对象和活动租约。 |
| 包操作中断 | 继续使用原生数据库锁和事务日志。用 `pkg log/show` 定位，再由 `pkg recover` 重核清单。无法证明状态时保留 `needs-recovery` 并阻止新的写操作。 |
| 应用或项目异常退出 | 从租约或会话中定位实际执行。恢复只释放已证明停止且由当前根管理的记录。取消单项执行时按 PID、启动时刻、完整 CID 与归属校验。 |
| 文件与桌面操作中断 | 从各领域日志恢复已明确的步骤，保护目标文件和现有桌面入口。比较身份与摘要；发现用户在事务外改动时保留现场并反馈冲突。 |
| 本体升级及回退 | 默认等待本次会受影响的运行与事务正常结束。检查实际旧入口、安装清单和状态兼容性，备份原入口，再激活新版本。失败时恢复原代码与入口并留下收据。涉及已迁移状态的重大升级需要独立验证数据回退策略。 |

`doctor` 运行后可以按提示执行对应的修复。拟提供可选的脱敏诊断输出，只写到操作者选择的本机文件；媒体与账号数据由用户另外控制。

## 6. 本体版本管理

| 操作 | 设计 |
| --- | --- |
| `self version` / `self list` | 展示实际运行版本、激活版本、源码身份、归档摘要和可用回退项。 `--version` 保持原样。 |
| `self check --channel stable\|preview` | 明确发起查询。稳定渠道取已发布且标记为稳定的条目，候选渠道取明确发布的预发布条目。仓库访问失败时报告最后一次已知状态。 |
| `self fetch <版本>` | 下载到用户级缓存；通过归档摘要和内嵌逐文件清单后标记可安装。半成品与校验成功项分开记账。 |
| `self install <已下载归档>` | 支持本地离线安装。解析版本与来源，展示将切换的入口，保全可回退副本，校验后切换，并用新入口确认程序实际版本。 |
| `self rollback [版本]` | 由已验证的回退账本恢复代码与入口，包括 CLI、应用导出和双击安装器，并保全当前版本作为回退历史。 |

SHA-256 用于核对字节与预期是否一致。发布渠道提供的可信版本与摘要应一起核验；正式做独立发布签名时再补充签名验证。下载与升级是独立动作，单纯查看状态不触发网络更新。

## 7. 实现顺序与验收

1. **入口与帮助。** 盘点现有命令路径、别名、默认根和 JSON 形状，先补端到端兼容回归。统一帮助、上下文解析、参数透传和领域表。验证通过绝对路径调用旧版及从新版回退的兼容性。
2. **运行状态与恢复。** 增加 `app list/status` 和只读 `doctor`，复用现有事务和租约。用已停止、活租约、命令中断、恢复阻断、两个根同名、被用户改动的菜单等用例检验。
3. **本体版本。** 先实现已校验本地包安装与入口回退，再接入明确触发的查询下载。用旧安装升级、模拟中断、旧版读取、回退到上一条记录、包摘要不符和断网用例验收。

每批通过现有离线入口与兼容测试后，再在适用的既有专用实例核验真实调用。已验收的大纲和迁移收据记录新旧 CLI 实际输出、退出码、状态根、完整绑定、相关进程与最后释放的租约。阶段结束时保留原日用数据与回退入口。

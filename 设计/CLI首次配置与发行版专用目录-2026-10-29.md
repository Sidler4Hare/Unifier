# 纯 CLI：首次发行版选择、单发行版容器与专用目录

日期：2026-10-29。状态：**已实现并完成本机受限 CLI 验收**。本方案取代之前的图形页面、多实例和数量配额设计。dsh Command Code 实施、主控独立修复和验收结果见 [验收报告](../evidence/cli-installation-2026-10-29/report.md)。

## 1. 用户操作模型

安装 Unifier 后，第一次在终端选择需要的跨派系发行版。**每个获准的发行版对应一个日常容器，同发行版的所有应用共用它。** 宿主同派系目标不列入选择；例如 Ubuntu/Debian 不建 Debian 容器，Arch 不建 Arch 容器，显式指定也应在拉取前拒绝。容器数量由选中的发行版数量决定，不另设数量输入、容器池、任意实例名或按应用建容器。此规则于 2026-10-30 随宿主关系策略版本 2 修订；此前的同派系机制通过不作当前设计验收。

当前可选客体为 Debian 13、Fedora 44、Arch rolling，对应 target 为 `debian13`、`fedora44`、`arch`。宿主白名单中的 Ubuntu 等不自动加入客体选项。新增客体按 [远期规划](远期规划-2026-11-08.md) 排在这三个目标收口之后，不在本页提前加入选择列表。

用户只操作“发行版”；UUID、代际、CID 和部署路径由内部登记管理，不要求用户选择 scope。保留现有底层 CLI 作为诊断入口。

## 2. 首次安装配置

命令入口：`unifier init`，在当前终端内进行普通交互，不启动图形窗口或网页。当前机器已安装 `~/.local/bin/unifier`；新机器可在源码目录执行 `python3 tools/install_unifier.py` 注册入口。桌面应用在初次配置时加 `--desktop`，无桌面服务器使用默认配置。

```text
$ unifier init

选择要安装的发行版（可多选）：
  [x] Debian 13
  [ ] Fedora 44
  [x] Arch rolling

将准备 2 个发行版容器：Debian 13、Arch rolling。
专用目录：/home/user/.local/share/unifier/containers/
继续安装？ [Y/n]

Debian 13     准备镜像 → 创建容器 → 就绪（已停止）
Arch rolling 准备镜像 → 创建容器 → 就绪（已停止）
```

交互可用数字编号选择或多选提示实现；按键方式实现时定版，业务模型不依赖全屏 TUI。非交互调用使用重复 target 参数：

```text
unifier init --target debian13 --target arch
```

规则：

- 只准备选中的发行版；未选中的发行版不拉取镜像、不建容器。允许全部不选，此时只安装 CLI，容器数为 0。
- 当前 `tools/lab.py pull` 面向所有已准备 target；施工时须先补 target 过滤，不能用“先下载全部，再只显示部分”代替自选安装。
- 重复运行先核对登记与实际 CID；已就绪发行版原样复用，不重装、不重复创建。并发初始化同一 target 时也只允许一个实例。
- 唯一性也在服务层落实：同一安装根的 `env create --id` 不能通过改名复制 target，承接引用和停用保留记录同样占用 target；跨进程创建锁持续到验证与登记完成。历史重复记录保留并提示冲突。
- 某项失败分别记录“已就绪/失败/未开始”，下次可继续失败项；不因 Arch 失败而重装 Debian。
- 初始化结束默认停止容器；安装或运行软件时再按需启动，保留现有共享租约与最后任务退出后的停机机制。
- 镜像、包管理器和版本继续遵守既有 target/lock 契约，不能混用系统依赖。普通项目目录继续使用 preserve-host。启用 SELinux 的宿主上，只对 Unifier 自建、路径无符号链接且属于当前用户的专用 files 目录使用容器访问标签；不重标记原项目目录，也不关闭整个容器的 SELinux 标签隔离。

## 3. 发行版选择就是数量配置

```text
unifier configure    # 重新选择启用哪些发行版
unifier list         # 查看发行版准备情况与容器状态
```

示例输出：

```text
发行版          配置状态    容器状态
Debian 13       已启用      已停止
Fedora 44       未安装      —
Arch rolling    已启用      运行中

已启用 2 个发行版；实际保留 2 个容器。
```

新增勾选的发行版准备一次已有或新容器；已勾选发行版不重复创建。取消勾选表示停用后续快捷安装/启动，不直接删除系统层、私有 HOME 或专用目录，也不突然终止正在运行的应用。已取消但数据保留时列为“已停用，容器保留”，分别报告启用数与实际保留数；重新启用复用原实例。

真正移除某发行版采用独立明确操作，展示私有数据影响并保留恢复路径。首轮不扩展成批量清理系统。由取消选择引起的数量减少不能隐含永久删除。

## 4. 每个发行版一个可从终端查看的专用目录

建议默认位置为 `$XDG_DATA_HOME/unifier/containers/`，未设置时为 `~/.local/share/unifier/containers/`。仅给已初始化发行版建立子目录：

```text
~/.local/share/unifier/containers/
├── debian13/
│   └── files/       # Debian 专用用户文件
└── arch/
    └── files/       # Arch 专用用户文件
```

`files/` 是每个发行版独立的普通宿主目录，创建该发行版容器时显式绑定；Debian 不自动挂载 Arch 的 files，反之亦然。用户可直接用 `ls`、`cd` 管理自己的专用文件。需要跨环境共享项目时继续使用既有显式共享，不把三套系统文件混到一起。

系统树由 `unifier ls` 按需访问；不在专用目录里制造一份空的 rootfs 冒充系统内容。只读挂载点由 view 管理，不让用户直接操作 Podman 私有存储。`ls` 当前列出子目录，包括能解析为目录的链接；它不等同于完整 GNU ls 的所有文件显示和选项。

承接既有部署时会创建管理侧专用目录，但不热改旧容器的冻结挂载。因此 `dirs` 会明确显示新 files 是否真实挂入该容器；未挂载时不把空专用目录当作旧容器的数据，原项目和私有 HOME 保留原位置。

终端快捷命令拟定为：

```text
unifier dirs                       # 列出各发行版的专用目录及状态
unifier dirs debian13               # 显示 Debian 专用目录和系统视图状态
unifier path debian13 --files       # 只输出 Debian files/ 的绝对路径
unifier ls debian13                 # 列出 Debian 系统根目录的分目录
unifier ls debian13 /usr            # 列出 Debian 内部 /usr
unifier ls arch /home               # 列出 Arch 内部 /home
```

`unifier dirs` 的示例：

```text
debian13  /home/user/.local/share/unifier/containers/debian13/  已停止
arch      /home/user/.local/share/unifier/containers/arch/      运行中
```

`unifier ls debian13` 的示例：

```text
bin  boot  dev  etc  home  lib  proc  root  run  sbin  sys  tmp  usr  var
```

这里的目录名以实际客体结果为准，不是固定生成的假树。命令里的 `/usr`、`/home` 相对所选客体解析，不落到宿主同名路径。

实现沿用现有边界：运行中的容器通过其执行命名空间完成只读列目录；停止的容器使用既有只读 view。单次列目录默认自动获取/释放自己创建的短期 view，不启动应用环境；用户已持有的 view 不被该命令擅自撤销。view 活动与容器启动仍保持互斥。长时间浏览仍可使用底层 `view open/revoke`，无需新增页面。系统树写入和包安装继续在容器内执行。

专用 files 目录本身不依赖容器运行；`unifier path` 只查登记，不启动或挂载。未安装的 target 返回“该发行版尚未配置”，不静默创建。路径不存在、后端失效或权限错误如实报告，不能返回假空列表。

## 5. 快捷安装与启动：只选发行版

```text
unifier install ./软件.deb
unifier install --target arch freecad
unifier run --target arch freecad
```

- 本地安装包先复用 `pkg route` 识别格式，再在用户已启用的发行版中选择。当前 DEB 对应 Debian 13、RPM 对应 Fedora 44、Arch 包对应 Arch。原生包管理器仍验证架构、签名和依赖。
- 省略 target 时，交互列出匹配且已启用的发行版；只有一个也要显示将用哪个发行版。没有匹配项时提示通过 `configure` 启用对应发行版，不私自创建额外容器。
- 仓库软件可以先在终端选发行版，或用 `--target` 明确指定。包名按该发行版原生仓库解释，不提供跨发行版混源或失败后自动换环境。
- 安装和启动固定使用该 target 的唯一登记容器；同发行版装十个软件仍然是一个容器。
- `run` 选择已登记的应用入口，并传递其参数；同包多程序时先选明确入口，不把包名直接猜成可执行文件。可以另提供安装完成后“立即启动？[y/N]”的交互选择。
- 保留“包已安装/维护钩子有警告/入口待选择/启动已发出”等真实状态，不以包事务退出码代替应用可用性。

容器启停仍可使用发行版作快捷选择：

```text
unifier start arch
unifier stop arch
```

内部解析唯一的 target → 环境 UUID/代际/CID 映射；用户无需输入实例名称。有任务占用时列出占用，不强停共享容器。已有手动常驻状态与按需启动状态继续分开处理。

## 6. 对现有 CLI 的复用与必要增量

**上述快捷接口已实现。** 安装入口为 `python3 tools/install_unifier.py`，运行入口为 `unifier`；源码入口 `python3 tools/unifier.py` 和原有 `env ...`、`pkg ...`、`app ...`、`view ...` 等诊断命令继续保留。直接使用源码诊断入口时默认兼容原工程状态；安装后的入口使用用户级安装根。`UNIFIER_HOME` 可显式选择隔离安装根。

| 用户操作 | 复用当前实现 | 必要增量 |
| --- | --- | --- |
| 首次选择发行版 | target 目录、compat 检查、镜像锁、`env create` | 多选提示、按所选 target 拉取、初始化记录/续跑、每 target 唯一性 |
| 后续调整选择 | `env inspect` 和现有身份核对 | 已启用集合、保留未启用状态、目标唯一映射 |
| 看发行版与专用目录 | 环境登记、共享挂载契约 | `list/dirs/path` 输出、首次创建独立 files 目录 |
| 看系统分目录 | `env run ENV -- ...`、`view open/status/revoke` | 按运行状态选择列目录后端、路径语义与短期 view 释放 |
| 安装软件 | `pkg route/install/log/show` | target 到唯一环境解析、程序入口发现/登记 |
| 启动软件 | `app add/show/open`、共享租约 | 按 target 查找应用入口的快捷命令 |
| 启停容器 | `env start/stop` | target 快捷别名、占用预检 |

当前两个日常应用的独立部署已通过 `adopt` 登记真实 UUID/代际/CID 引用，形成统一安装入口；原容器与文件未移动。若同 target 存在其他旧对象，列出冲突而不自动合并包数据库、覆盖 HOME 或删除历史容器。

## 7. 施工顺序与验收

1. **首次配置**：选 Debian+Arch 只准备两套；未选 Fedora 无下载/容器；重复运行与并发运行不重复建容器；部分失败可续跑。
2. **专用目录**：每 target 一个独立 files 目录；CLI 直接列出位置和客体实际分目录；停机读取不启动容器；运行态读取不错误指向宿主；视图使用后正常释放。
3. **快捷安装/启动**：按 target 安装并运行两个应用时 CID 始终相同；选择未启用发行版有清楚提示；不暗中新增容器。
4. **既有安装承接**：保留日常应用包、数据、UUID/CID 和菜单；重新选择不重装；停用不删除数据；重复旧实例显式处理。

本轮先在隔离安装根验收，再以身份引用承接日常部署；保留原有包、私有数据和菜单，不重建已有日常容器。当前验收范围为 Fedora 宿主上的 CLI；新入口的真实 GUI、其他宿主和 Arch 全量软件包安装仍有独立验收边界，详见报告。

## 8. help 与中英文

```text
unifier help
unifier help init
unifier help install
unifier --help
unifier install --help
unifier language
unifier language zh-CN
unifier language en
unifier language auto
```

`help`、`-h`、`--help` 提供一致的命令说明和示例。命令名、target ID、文件路径和 JSON 字段不因语言变化而改变；提示、交互、状态标签和面向用户的错误说明提供中文、英文两套。原生 apt/dnf/pacman/系统返回的诊断保留原文，外层补所选语言的说明。

中英文范围是新增用户快捷命令。原有底层诊断子命令的详细参数帮助保留原英文文本，避免破坏已有诊断协议。

默认根据安装目标 Linux 的 locale 判断，而不是凭 Debian/Fedora/Arch 名称猜测语言。显式 `language zh-CN|en` 优先并持久保存；auto 使用 `LC_ALL → LC_MESSAGES → LANG → 发行版 locale 配置（/etc/locale.conf 或 /etc/default/locale）→ 英文`。中文 locale 选择中文，其余选择英文；命令显示当前生效语言与来源。切换 guest target 不突然更改母系统 CLI 语言。

`language`、`help` 不拉镜像、不创建/启动容器；切换语言只修改语言偏好。非交互模式缺失必要选择时清楚报错或要求显式参数，不挂起等待输入。英文/中文都须验证帮助、初始化、目录查看、安装/启动和失败路径。

### 2.1 新 CLI 的扩测合同

测试入口统一使用本次锁定代码的 bin/unifier，并显式设置独立 UNIFIER_HOME。新入口默认状态根是 XDG_DATA_HOME/unifier；源码诊断入口在未设置 UNIFIER_HOME 时仍可能使用源码根。所有子进程、恢复命令和采样器都必须按记录使用对应测试根；adopt 引用外部 fixture 时，低层命令与 worker 按回执中的 source_root 使用真实源根，不能误读管理根。不得误用本机默认安装根中的日常部署引用。

| 用例 | 必测内容 |
| --- | --- |
| CLI01 | help、help COMMAND、-h/--help 的位置、未知命令与参数；无 runtime 时帮助和 language 不产生容器副作用 |
| CLI02 | 中文/英文/auto；显式偏好优先于 LC_ALL、LC_MESSAGES、LANG 和宿主 locale 文件；切换客体发行版不改变宿主界面语言 |
| CLI03 | 首次 0/1/全部准入发行版选择（当前为 2）；显式同派系及全 3 目标请求按策略拒绝，不能创建第三套客体；无 TTY 的显式参数、失败项续跑；只拉取选中摘要、不准备未选发行版 |
| CLI04 | 重复 init 复用同一 target 的 UUID/代际/CID；不同 ID 的并发 env create 仅一条记录/容器成功；保留、missing、adopt 引用仍占用 target，等锁后复查策略；多应用/Agent 共享 |
| CLI05 | configure 新增、停用、重新启用；分别报告启用数和保留数；取消选择保留容器与文件，不突然停任务；policy_blocked 与停用、保留状态分开，不改写原选择 |
| CLI06 | dirs/path 的真实专用目录与 files_mounted；SELinux 上新建专用 files 的写回/属主；普通项目 preserve-host |
| CLI07 | ls 的运行/停止态、/bin 链接、相对链接及 ..、根限制、权限/FD 错误和短期 view 回收；只要求列子目录，不要求目录非空；被策略阻止的运行态 ls 不得 exec，停止态只读恢复保留；受限链接不遮住可读兄弟目录 |
| CLI08 | 真实 DEB/RPM/Arch 包元数据、错误目标修改前拒绝、路径特殊字符、Arch 原生安装及全系统升级规则；不只验证读取包名 |
| CLI09 | 原生软件包成功但入口缺失/多入口待选择的区分；完整 desktop argv、套件组件及跨 target 同名别名各自指向真实程序 |
| CLI10 | run 原样 argv、UID/HOME、退出码/信号；共享租约和最后退出停机；stop 对活动会话、包事务、损坏/未知租约拒绝强停 |
| CLI11 | adopt 的 UUID/代际/CID 重验证、同名替换和冲突；旧容器不热增挂载，未挂新 files 时如实报告 false；仅用本轮独立 fixture |
| CLI12 | 安装根隔离、worker 根一致、登记损坏显式失败；init/list/dirs/ls/install 的 JSON stdout 与进度 stderr；run 的应用输出另存，不预设 stdout 是单一 JSON |
| CLI13 | --version 与包清单；源码/全局/旧别名/worker/日常入口身份一致；隔离 fresh install→upgrade→rollback→卸载入口，保留数据与旧代码；未知启动器拒绝覆盖。只验证现有入口切换，不宣称跨版本 schema 迁移 |
| CLI14 | 同派系 init/pull/create/adopt/start/run/pkg/运行态 ls 的全入口拒绝；无客体执行、无宿主 fallback、无越权副作用；检查/停止/停止态只读恢复/精确退役按现有合同保留 |

### 3.3 包格式限制怎么测

- 官方原生包走对应驱动：DEB→apt/dpkg，RPM→dnf/rpm，Arch 包→pacman。读取包内真实元数据；不能只按文件后缀认定可安装。
- 明确选择错误目标时应在修改前拒绝，包数据库、项目文件和其他环境均不变；自动路由入口则应选中已登记的匹配环境，并保留真实目标回执。
- WPS/Beyond Compare/飞书的 Arch 官方原生包本轮未确认。不用 alien、强制解包或 AUR 重打包补成“官方 Arch 支持”；可以通过匹配的 Debian/Fedora 环境向宿主提供应用，另算跨环境使用结果。
- AppImage/社区封装若以后加入，单列运行后端和来源，不能与原生包验证混算。
- 安装、依赖完整、包钩子、应用功能、升级及卸载分别记结果；缺依赖、架构错误、签名问题、上游不支持、网络失败与产品路由错误分别归因。
- 快捷安装、启动使用 unifier install/run；更新、卸载使用已有 pkg update/remove，具体应用/环境 ID 从回执获取。当前没有统一 unifier update/uninstall 快捷命令，不在脚本中假定存在。
- 新 CLI 已验收真实 DEB/RPM 元数据安装与同名入口，Arch 本轮只读取了真实包名；Arch/Zoom 仍需完整原生安装、启动、使用和保存证据。全部阶段记录实际包事务，不以早期机制通过直接填本计划 PASS。

## 4. 真实可用性的验收方法

每个安装单元至少完成一个主工作流和两次保存/重开周期。记录实际窗口/首个可用画面，不只记启动器退出或进程存在。统一步骤：

1. 完成 G-SHARED-MOUNT 和桌面预检后，在隔离环境中通过新 CLI 安装，记录包事务、应用实际 ELF/解释器与依赖来源；软件格式/目标和 GUI 选择失败必须保留真实状态。
2. 先以 unifier run 启动，再分别测试受管菜单、显式项目入口和文件管理器双击/默认打开。快捷 install 只登记应用，不自动完成 handler/project/menu 绑定；按已有低层 app/project/handler 接口明确登记并保存回执，不把原生 GIO 对照或手动修正路径算成统一路由。
3. 使用中文、空格、相邻资源和嵌套目录 fixture，核对输入法、剪贴板、拖放、文件选择器、默认保存位置及权限。
4. 在宿主项目原路径保存，同时检查备份/临时文件和文件所有者；关闭应用、停止环境，再启动并重开原件和新建件。
5. 卸载/重装只影响应用与其私有配置，项目原件保留；同名重建后的旧 handler/授权拒绝。

WPS 文件用内容结构/公式、重新打开的 GUI、导出结果三类证据核对；不能要求 OOXML 二进制哈希完全不变，也不能以 ZIP/XML 可解析代替排版正常。字体版本和替换情况进入证据。

媒体用例必须有用户可见且持续变化的画面和真实声音/共享接收结果；V4L2 能取帧、PipeWire FD 已传递不能代替画面可用。账户、对端或设备缺失时对应能力标 BLOCKED，离线窗口通过不等于会议可用。

## 5. Agent：从容器内执行到跨环境操作

### 5.1 执行布局

先使用同版本 dsh/Command Code 作为真实 Agent 对照，按宿主矩阵分别安装到本轮准入的隔离环境，跨轮覆盖三种客体，在各自私有 HOME/配置/缓存中运行普通用户进程。先核对其实际官方/现有受信安装方式和版本；不把宿主可运行文件简单 bind 进去就算原生安装。第二种 Agent 实现作为后续复验，不据一个 Agent 外推所有产品。

10 月 27 日历史盘点已确认宿主 `dsh`、`claude`、Node/npm 等命令路径存在，可复用作宿主执行来源对照；这不代表认证已就绪，也不替代容器内安装。尤其要区分实际用户桌面、当前 agent 检查进程及客体的 PATH，不能把执行进程命中的内置运行时 wrapper 当成宿主原生应用或客体工具。

每台当前宿主复用 **两个准入发行版环境**，每个环境可以有多个 agent/session；不为每个进程再启动一套发行版。用已登记的 project run/shell 监督运行，记录 CID、start 事件、session/lease、各进程树和定向取消。测试数据共享，venv、node_modules、原生扩展、构建输出和可变工具链按环境分开。普通用户 Agent 不自动具有原生包管理权限；维护任务使用明确授权的受管管理操作，不临时开放宿主管理 socket 或假设 sudo 可用。

凭据仅通过执行时的专用引用注入，不复制整个宿主 HOME、现有登录目录或容器管理 socket；证据不保存原值。尚未提供可用测试凭据时，Agent 认证能力标 BLOCKED_AUTH，文件系统确定性探针仍可先跑。

### 5.2 两种能力分别验证

**数据互写**：同一宿主的 host 与两个准入客体对同一个已登记项目按 6 个有向边逐一接力。先用固定脚本校验字节，再让真实 Agent 完成等价任务；保存实际工具调用和产物，不接受只生成建议命令。

**控制请求**：每台宿主的两个容器内 Agent 各以 host、自己、另一个准入容器为目标，共 **6 个来源—目标单元**。历史 12 关系模板按宿主实例化，不要求在一台宿主运行三客体。自身操作、已授权跨客体操作、母发行版操作都要有正例，未授权拒绝另列，不能只测“都不允许”。

| 任务 | 具体正例 | 目标证明 |
| --- | --- | --- |
| 本环境维护 | 在本环境安装/卸载测试工具，创建私有 venv，编辑共享项目 | 本环境原生包记录、UID/HOME、私有产物与共享文件 |
| Agent A 操作客体 B | 在已登记项目中调用 B 的处理器/解释器；受控安装 B 的测试工具后再移除 | B 的 UUID/generation/CID、实际 argv/cwd、包事务与输出；A/其他客体/宿主包数据库不变 |
| Agent A 操作母发行版 | 读取宿主系统信息；在专用 host-work 根执行非特权转换/文件操作 | 宿主 namespace、真实 PID/命令回执、专用目录副作用；不能用另一个 Fedora 容器冒充宿主 |

`uname` 在共享内核下不能证明执行目标。必须组合目标身份、namespace/mount/cgroup、私有 sentinel 和结果；不能只看模型回答或 `/etc/os-release`，也不能把禁止的同派系客体构造出来充当宿主正例。

宿主包管理、系统服务和系统目录写入不属于首轮宿主正例；需要时另建明确的管理测试关口。本计划不通过创建被禁止的同派系“宿主克隆容器”验证宿主管理；若以后使用独立虚拟机实验，单列后端，不能计为真实母发行版操作。

### 5.3 跨环境入口的前置工程关口

截至本次源码核对，已交付的是宿主发起的 CLI/项目会话与受管文件操作，没有确认可交付的 guest-origin 受控请求接口，工程状态为 **NOT_IMPLEMENTED_IN_REVIEWED_SOURCE**。P0 针对实际运行指纹复核：若新版本仍缺失，则只阻塞依赖桥接的跨环境请求、授权和维护子例，先完成本环境用户任务及共享互写；补最小桥接后另轮验收。不能把宿主测试脚本读请求后代执行当成产品能力，也不因这一缺口阻塞全部应用/文件测试。

## 6. 文件系统实测矩阵

### 6.1 后端配对

| 配对 | 本轮计划 | 关键限制 |
| --- | --- | --- |
| host Btrfs ↔ 本机准入 guest 的共享 bind | 同一底层数据的视图/权限/锁对照 | 不是三种不同文件系统；挂载 ID 也要记录 |
| Btrfs ↔ tmpfs | 双向真实跨文件系统复制、移动、锁与故障 | 使用专用限额 fixture，不填满宿主 `/tmp` |
| guest 私有 overlay ↔ shared Btrfs | 各准入客体做双向 native 和受管出口对照，跨宿主覆盖三种客体 | 从客体真实路径/正式接口访问，不裸改 Podman upperdir |
| 持久卷 ↔ shared Btrfs | 记录实际设备、挂载和覆盖图再测 | 卷名不同不自动表示不同文件系统 |
| 停止环境只读 FUSE ↔ 可写测试根 | 读取/复制出口、只读拒绝、视图租约 | **FUSE 当前只读，不能拿它充当互写通道** |
| ext4 映像经 fuse2fs ↔ Btrfs/tmpfs | 工具已存在，先验证非特权独立挂载与清理 | 这是用户态 ext4 映像路径，不是原生内核 ext4 性能 |
| 原生内核 ext4 loop ↔ Btrfs | 独立能力关口 | 挂载能力未确认；只用专用映像，不用 `/boot` |
| 外接 exFAT/NTFS ↔ Btrfs | 外部待办 | 等独立测试介质；不使用现有 EFI 分区代替 |

每个路径记录 `st_dev/st_ino`、statfs、mount ID、挂载选项、UID/GID 与实际读写身份。跨挂载和跨文件系统分别记录；是否 EXDEV 由原生系统调用对照确认，不仅凭 st_dev 推断。

### 6.2 语义与数据集

20 组文件系统用例 FS01–FS20 见 plan.json：内容/大小、原子替换/旧 FD/mmap、symlink 与根限制、hardlink、ACL/xattr、特殊路径、稀疏文件、锁、SQLite/Git、监听、目录分页/回收、fsync+rename、受管事务中断、ENOSPC/权限/后端失效、只读投影、busy revoke、数据根生命周期及性能。

| --- | --- |

严格快照/多卷一致性目前无保证；并发修改下的 live view 如实记录观察范围。复杂目录/链接/元数据先测原生对照及能力拒绝，再按未来实现范围验收，不能把缺失能力从总矩阵中删除。

首批合成数据采用：零字节、普通文本与 CSV、10,000×4KiB 小文件、128MiB 顺序文件、256MiB 逻辑大小稀疏文件、中文/空格/长名、相邻资源与多层目录。大文件和小文件树分轮装载，不在小容量 ENOSPC fixture 中混跑；ENOSPC 使用独立小限额区。预计规模是规划值，执行前根据实际可用资源调整并记录。

共享互写每宿主先测 6 个有向边的直接写、原地写、原子保存 3 种模式，每种 3 轮，初始每宿主 54 个确定性回放；四个当前宿主全做为 216 个带宿主身份的回放，各机独立判定；再增加并发与 Agent 任务，不直接把所有维度做无界笛卡尔积。

注意三个保证：

- 未协调的多个写入者可能覆盖彼此，这是需要测出并报告的原生保存风险；不能宣称共享目录自动提供版本冲突保护。受管路径则按实际契约验证冲突保留与源清理。
- SQLite/Git/flock 对真实可写后端测试；只读投影不承担可写数据库角色。文件被原子替换后 advisory lock 所针对的对象也可能变化，不能把观察版本当作 CAS。
- 当前受管复制/移动的验收范围是受限普通文件。目录树、链接图、复杂元数据能力缺失时标 NOT_IMPLEMENTED/明确降级，不用外部 `cp -a` 的成功冒充产品能力。

停止目标的 FUSE view 活动期间不能启动该环境中的 Agent/维护会话。用例必须验证这个拒绝，再正常释放 view 并继续目标任务；不通过强制卸载绕开冲突。真实挂载默认放私有临时路径，默认工作区挂载点的外部扫描/busy 单独测并记录持有者。

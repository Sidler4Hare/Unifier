## 备份与恢复演练

第一批使用仓库外的通用备份池 `/home/omg/文档/Unifier-backups`，或 `UNIFIER_BACKUP_POOL` 指定的外部池。新备份使用私有目录（0700）和唯一 ID，先在池内临时目录完成校验，再原子改名和登记。私有元数据使用 0600，恢复载荷保留源文件模式、可执行位与链接目标。开工时按实际数据量核对资源、空间和期限。备份内保存 `MANIFEST.json`、`SHA256SUMS`、恢复说明和 `RECEIPT.json`，池内 `INDEX.jsonl` 登记已校验的备份及其回执。

| 保存对象 | 恢复所需内容 |
|---|---|
| Git 和工作树 | 保存主工作树的 Git 对象、refs、原始索引及用 `git bundle create <备份包> --all` 生成的全引用包，记录 HEAD、分支、`git status --porcelain=v2 --branch`、`git ls-files --stage`、暂存与未暂存的二进制差异。保存现场工作树，包括未跟踪文件、受跟踪但已删的路径清单，以及 `.lab` 中需恢复的绑定、锁、租约、事务和视图记录。清单记录相对路径、类型、模式、文件摘要或链接目标。旁支未合入的工作树另行保全。 |
| `artifacts/` | 本次核对时 `git ls-files artifacts/` 有 **1,391** 条，开工时重列。受跟踪内容应能从已保存的对象、索引和工作树差异还原。对未跟踪且回退必需的候选原包、manifest、验证回执及发行输入，留存原字节或登记独立副本的位置、大小与摘要。其余历史证据可只列身份清单，并注明恢复范围。 |
| 发布输入与运行身份 | 记录 `.media.1`、`.desktop.1` 的来源、归档和清单摘要，四项 WPS 资源实际从包或独立副本读回。记录日用命令及菜单目标、原管理根和绑定。排除清单列出 Podman 镜像和可写层、宿主桌面注册、用户目录、密钥与凭据。socket 等特殊文件只记类型和位置。 |

**演练方法。** 在空的私有临时目录附上保存的 Git 元数据，明确将 Git 目录与工作树指向该副本。用已保存的 Git 对象复原跟踪路径，装回原始索引，并按备份重放工作树差异、删除和未跟踪文件。重算 manifest 与 SHA-256，在副本中执行 `git bundle verify <备份包>`，对照 HEAD、索引项、暂存与未暂存差异、状态、文件模式及符号链接。核对复制前后源状态一致，再从保存的位置读回候选原包、WPS 四项和关键回执。恢复记录列出任何遗漏。临时演练只验证文件和 Git 状态，绑定实例的恢复另外核对原管理根、完整 CID 和代际。

### 指标复现口径

- 模块行数：`len(Path.read_text().splitlines())`。
- 函数/参数/复杂度：`ast.walk` 统计 `FunctionDef/AsyncFunctionDef`；复杂度 = 1 + If/For/While/ExceptHandler/IfExp/Comprehension + BoolOp 额外分支。
- 重复块：每函数按源码顺序展开语句，取连续 6 条语句的 AST dump 哈希，要求跨函数/文件且行跨度 ≥8 行。
- SCC：解析所有 `unifier.*` 导入（含函数内导入）后 Tarjan。
- 符号引用：全仓 `Name/Attribute/ImportFrom` 引用 + 文本词元；zero-ref 结果必须再排除字符串/路径动态引用。
- 本文件所有行号基于 HEAD `f2a7cee3`；后续提交可能漂移，复核时以函数名定位。

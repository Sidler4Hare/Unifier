# v0.0.8 真实功能验收计划

2026-11-17，规划稿。本文定义新一轮验收，全部用例初始为 `NOT_RUN`。现行测试准入见 [全项目测试禁令与规范](../docs/测试禁令与规范.md)。历史结果继续见 [当前状态](../docs/当前状态.md)、[剩余工作台账](../docs/测试剩余工作-20261109.md) 和 [扩大测试矩阵](扩展可用性与Agent跨环境测试计划-2026-10-27.md)。

## 1. 通过意味着什么

- 从用户实际使用的入口开始。应用验到安装或明确选择已安装、发现入口、打开、完成业务动作、保存或交付、正常退出、再打开后核对内容。命令验完整参数、标准流、退出码、结果及收尾。服务验启动、业务请求、异常、停止和重启后读取持久结果。
- 正常操作包含选择发行版、确认安装、通过设置界面作显式选择、登录、选择文件、按预定按钮。默认设置和显式改过设置的流程分别记录。例如 WPS 的 `stop-children`、XWayland 应用的 `host-xim` 都要记录来源及适用条件。
- 用例中途若必须进容器补库、改挂载、手补菜单、改状态 JSON、删锁、手动停止辅助进程或借用同一工作目录的残留才能继续，冻结原始失败。补救后的表现可用于定位，原始用例保持失败或部分完成。进入恢复专项时，产品向用户公开且文档规定的恢复动作属于受测流程，仍需证明恢复后原任务可经原入口完成。
- 修复时先保留原版本首次失败步骤和最小输入。定向回归后，从可证明的用例起始状态在修版上重放**原完整流程**，包括冷启动和二次打开，再重跑同入口的正常邻例和相邻失败分支。首次安装用例要求原应用、入口登记及目标依赖处于用例定义的起点。既有专用夹具达不到起点时记录阻断，另开修复后的用例记录。
- 历史探针、临时源码、独立候选包与日用安装各自记结果。先用 `readlink`、发布清单和源码路径记录实测入口及文件摘要，再记录版本。规划时日用入口指向 `0.0.7+wayland.4`，工作树版本标记为 `0.0.7.dev0`，HEAD 为 `cac42d9f` 且有未提交改动。执行时另采实际哈希。声称用户可用须在实际使用的入口完成相应工作流，候选包验收单独记录。

## 2. 宿主、客体与样本分配

| 宿主与客体 | 优先覆盖 | 实际准入 |
| --- | --- | --- |
| 本机 Fedora → Debian 13 | WPS、GTK 选择器、终端、包管理、项目和文件交付。QQ/钉钉只按实际原生包路由分配 | 复用非日用专用 CID。重 GUI 和厂商应用先核实既有挂载、独立显示和进程树预算 |
| 本机 Fedora → Arch | FreeCAD、Qt 文件对话框、实际保存重开，Wayland 和文件集成。允许硬件的专用实例可测应用级图形及视频 | 日用 FreeCAD 容器保留。只在符合该用例的专用 CID 上运行 |
| Ubuntu 服务器 → Fedora 44 | 仓库 RPM、原生应用 CLI、服务、项目、同根包事务、只读库存、CUDA 和媒体命令 | 无桌面是已知主线。真实 Fedora GUI 另需合规的非 Fedora 宿主及已准入私有桌面，或服务器私有显示满足所选应用的要求 |
| Ubuntu 服务器 → Arch | 复用固定 Arch 做 CLI/项目、包清单或同根场景。AMD/V100 的应用负载只进入各自批准的专用 GPU 夹具 | 已验收的 GPU 夹具按现有创建契约选用，运行前仍须核对设备、应用依赖和份额 |
| 同派系、未实现客体 | Fedora→Fedora、Ubuntu→Debian、openSUSE/Alpine 等尝试得到明确拒绝 | 逐入口核对拒绝时的副作用。正向只排实际 `compat check` 允许的组合 |

每条用例在执行登记填写完整 CID、环境 UUID/generation、管理根、镜像摘要、网络和挂载、应用版本、依赖来源、起始状态以及实际操作者。上表是候选分配，包与目标以 `pkg route`、原生元数据和宿主准入为准。每阶段选固定实例，容器新增预算默认 0，最多运行一台测试容器。共享场景中的并发只安排在同一已限额实例内。原有重 GUI、会议和账户数据保留，独立展示或媒体用例按现行规范准入。

| 样本组 | 代表应用及实际任务 | 输出判据 |
| --- | --- | --- |
| 小型 CLI | `jq` 转换中文 JSON、ripgrep 搜索带中文和空格的项目、SQLite 导入查询。终端另测 stdout/stderr、管道与 Ctrl-C | 固定结果、边界退出码、原文件和外来会话状态 |
| 文字、表格、演示 | Debian WPS Writer、Sheet、演示逐项执行。跨应用候选为可准入的 LibreOffice | DOCX 段落和字体、XLSX 公式重算和样式、PPTX 页数和文字逐项核对，保留可重开的文件 |
| CAD / 图像 | Arch FreeCAD。签名仓库中可获得的 GIMP 或 Krita 用作图像编辑候选 | FCStd 参数、对象数及 STEP 重新导入几何。图像图层数、尺寸、指定色块与导出文件 |
| 差异比较 | 既有 Beyond Compare 版本或签名仓库中的 Meld。验旧问题时固定 Beyond Compare 对应版本 | 只合并选择的差异，重开后比对两侧哈希，不选内容保留 |
| 聊天和会议 | QQ 与钉钉测本地输入、选文件及实际附件。腾讯会议优先验证一条本地两端媒体流程，飞书/Zoom 分别保留各自用例 | 接收端看到指定文字/文件/图像和声音。账号、下载失败、应用自行退出、媒体功能按应用分开记 |
| 播放与转码 | 真实可准入的播放器，例如 mpv，配合 FFmpeg/ffprobe 固定短片 | 播放、定位与退出可观察，转码后独立解码。实际设备和路径与申请相符，软件回退单独记录 |
| 项目与后台服务 | 小型 Make/C 或 Python 项目，`python3 -m http.server` 服务与 `curl` 客户端，服务数据用 SQLite 或固定响应文件 | 产物可执行，源代码未被测试工具改写，HTTP 响应字节和重启后数据一致，在本阶段仅绑定客体回环 |
| 桥接与自动化 | 真实客体客户端先提交 `host-info`，再提交一个宿主授权且可核对产物的 `project-run` | 一次业务结果对应一次请求和一次执行，原生模型的实际工具调用另有结果 |

候选应用在执行批次固定包名、版本、架构、来源、哈希、许可证适用范围及依赖闭包。开源替代品可覆盖同类功能，原厂应用的问题仍挂在原用例。跨发行版互操作使用复制后的同一组样本，应用各自产生并再打开真实输出。

## 3. 执行用例

优先级采用 P0（首批必须判定）、P1（本轮扩大覆盖）、P2（独立条件满足后执行）。实机任务分级仍用项目 T2/T3/T4。下表的失败分支是测试内容，涉及主动故障注入的用例按规范另行准入。

## 4. 第一轮执行顺序

1. **冻结本轮基线与实例。** 先登记日用安装、当前树、候选包和应用来源。使用宿主准入、历史文件和只读容器清单锁定各用例的实际 CID。配置或镜像标签只有与完整身份匹配时才采用。登记各阶段允许写入的测试目录和资源预算。
2. **先跑能定位底层失败的小任务。** 依次做入口与路由、CLI 原生包/进程、同根隔离和回环服务。每种目标至少留下一个真正安装、运行、二次运行的正向用例和相应失败分支。同时复核项目与文件入口的最小成功、拒绝和清退。
3. **集中做日用问题的原入口复现。** 按 QQ 新装菜单、Wayland 二次启动、真实输入法上屏、FreeCAD 保存重开、WPS 生命周期、实际附件交付的顺序。先跑确定样本再扩到另一种应用。当前阶段若遇到共同路径故障，先冻结失败，再修复并重放受影响的用例和公共邻例。
4. **补齐实际应用、服务和发行候选覆盖。** 继续文件方向矩阵、办公组件、图像/差异比较、Agent、实际设备及候选包的重复启动和回退。媒体、重 GUI、故障注入或长时用例在各自准入下执行。宿主或应用条件欠缺时记录具体阻断，并推进其余独立用例。

用户要求执行本批或其中一项后，按[全项目规范 §1.1](../docs/测试禁令与规范.md)承接该目标所需的 T2 和私有 T3。比如验收 WPS 保存重开，主控可自行备齐签名依赖，在独立显示完成编辑、保存、关闭、重开和内容比对；附件用例可先完成私有选择和客体读取。实际发送时核对账号、接收端、数据和发送许可，缺项时只暂停发送，继续其余用例。

阶段资源与隔离沿用测试规范。15 秒连续准入、1 GiB 宿主可用内存保留、250 ms 独立监测、整棵进程树覆盖与有限期限。按[测试运行器](../docs/测试运行器.md)首轮选用合适的包准备或私有 GUI 档。下载、包写入、编译和测试串行。修复后重放沿用同一目标及隔离边界，配额调整按规范 §4.2 登记。

## 5. 回执与手工任务交接

每条用例保留一条可独立重放的记录，状态采用 `PASS / FAIL / PARTIAL / NOT_RUN / BLOCKED / UNKNOWN / INVALID`。同时记产品能力预期和实际结果，明确拒绝可使对应的负向用例通过。首轮汇总逐项列必测、已通过、失败、阻断和未跑，避免按应用窗口数或单元测试数量统计真实可用性。

| 执行记录字段 | 内容 |
| --- | --- |
| 版本和实例 | 用例 ID、实际安装入口、构建或文件哈希、宿主、客体、完整 CID、UUID/generation、应用和驱动版本 |
| 用户任务 | 起点、点击/命令步骤、输入样本摘要、期望业务结果、是否需要测试者本人操作或第二端确认 |
| 实际结果 | 首次失败步骤、原始错误和退出码、实际应用/进程、日志与状态记录、输出路径和独立校验，截图采用测试数据 |
| 人工干预 | 记录谁在何处执行何种额外操作、为何需要、是否绕过原入口。正式正常按钮和故障补救分别填写 |
| 修复与复验 | 补丁/构建标识、最小复现、原全流程重放、冷启与复开、相邻测试，链接首次失败回执 |
| 收尾 | 包三方清单、进程树/租约/会话、文件授权、FUSE/存储引用、GPU/音视频上下文、其他实例/数据、待恢复状态 |

交给用户的手工任务卡保持短小，每张写清测试应用和版本、要打开哪个入口、要操作和保存什么、看到什么算通过、出现哪一步异常就报出来。用户账号和真实附件只在相应场景明确授权后使用。用户点击与判断属于产品操作，后台保护、日志、输出校验与修复复验由测试方留存。发现必须手动补救的步骤时，先记录原始状态和操作路径，避免丢失重复复现的起点。

| 手工任务卡示例 | 可直接执行的动作与通过条件 |
| --- | --- |
| QQ 安装与菜单 E2E-06 | 在私有会话的文件管理器双击已登记的测试安装包，按弹窗确认安装。软件列表出现 QQ 后，从列表打开、关闭、再打开。若列表缺项，记录安装完成时显示的提示和步骤，再由测试方查看包与登记。 |
| 中文上屏 E2E-12 | 打开测试输入框，输入拼音并在候选中选择“测试”，继续输入中文逗号和“已保存”。切换焦点回来后复制最终文本，核对为 `测试，已保存`。分别记默认配置和项目明示的 XIM 配置。 |
| FreeCAD 保存重开 E2E-16 | 打开任务卡指定的合成 FCStd，把矩形宽度从 20 mm 改为 25 mm，另存工作副本，关闭软件后从文件重新打开，检查尺寸仍为 25 mm，再导出 STEP。原模板、工作文件和导出件各自核对。 |
| 附件交付 E2E-21 | 从应用的附件按钮选择指定的中文名合成文件，向已获准的测试接收端完成传输，接收副本的 SHA-256 必须等于源。记录失败是在选择、读副本、发送还是接收，便于重跑原步骤。 |

首轮结束时，以各用例实际证据逐条结案。保留端到端仍需要人工修理的产品问题、发行版包外的私有驱动修复、尚未发布的候选验证，以及受限的账号、设备或宿主场景。报告可直接作为下一轮用户手工任务与边测边修的台账。

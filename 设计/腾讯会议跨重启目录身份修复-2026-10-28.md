# 腾讯会议跨重启目录身份修复

这是 2026-10-28 的专项修复说明，不是产品路线。现行顺序见 [远期规划](远期规划-2026-11-08.md)。

## 问题与行为

2026-10-28，腾讯会议菜单启动在运行应用之前退出：

```text
ml: project root path was replaced since registration
```

登记目录的 inode 仍为 `2584287`，但宿主重启后 Btrfs 的 `st_dev` 从 `53` 变为 `52`。旧实现将持久化的设备号与 inode 同时当作跨重启身份，因设备号变化误判目录被替换。

新建 Btrfs 数据根现在保存文件系统 UUID、子卷 ID、子卷 UUID；解析数据根时，先通过同一目录 FD 查询并验证这些身份和原目录 inode，再使用本次观察到的设备号。解析不重写登记文件。目录、子卷、文件系统或符号链接替换仍被拒绝；已登记身份无法读取时也拒绝。其他文件系统保留设备号与 inode 的原有检查。

旧登记不会凭相同 inode 自动接受新的设备号。`DataRootRegistry.pin_identity()` 只在原有设备号、inode 均匹配时显式增加持久身份；已过期的旧登记必须先独立核对恢复。腾讯会议本次沿用此前已经核对恢复的登记完成迁移，保留 root/project/app/integration/container 的原身份及菜单内容。

## 实现范围

- `src/unifier/root_identity.py`：经打开的目录 FD 读取 Btrfs 身份，校验路径在观察期间未变化，拒绝符号链接。
- `src/unifier/registry.py`：新登记保存身份，查找与最长路径匹配返回验证后的当前设备号；提供旧登记的显式迁移。重复根判断区分文件系统、子卷与 inode，避免复用设备号产生冲突。
- `tests/test_root_identity.py`：12 项回归，覆盖设备号变化、项目启动计划、目录/符号链接/文件系统/子卷替换、设备号复用、别名冲突、读取失败、损坏登记和旧登记迁移。

持久身份来源为只读的 `BTRFS_IOC_FS_INFO`、`BTRFS_IOC_GET_SUBVOL_INFO`。ABI 常量、缓冲区大小和字段偏移经本机 `<linux/btrfs.h>` 编译探针核对。参见 [Btrfs ioctl 官方文档](https://btrfs.readthedocs.io/en/stable/btrfs-ioctl.html) 与 [Btrfs 子卷身份说明](https://btrfs.readthedocs.io/en/latest/Subvolumes.html)。

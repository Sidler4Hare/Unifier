日期：2026-10-23。里程碑：`architecture-experiment-2026-10-23`。项目名称：**Unifier**。私有仓库：<https://github.com/Sidler4Hare/Unifier>。

本次冻结当前实现、实验材料和架构决策，作为下一阶段开发的可回溯基线；不是完整产品 1.0，也不是所有发行版、应用或宿主组合的兼容承诺。定档包含前期尚未提交的生命周期、安装状态、并发、文件层探索以及本轮契约修复与真实 GUI 证据，不将它们统一归因于某一个模型。

## 确定的架构方向

1. **宿主掌握项目与用户数据。** 共享项目按相同绝对路径直接挂载，让应用对宿主原件读写；不默认复制成容器私有副本，不把所有 I/O 强制经过代理。
2. **原生发行版负责包与运行环境。** Debian、Fedora、Arch 各自保留 apt/dpkg、dnf/rpm、pacman 数据库和依赖体系。环境目录契约、包驱动选择与执行共用验证入口；可以描述的目标不等于可以创建的目标。
3. **环境按上下文共享。** 同一环境中的多个应用共享容器与启动状态，通过租约维护生命周期；不为每个进程启动独立发行版。共享环境不是应用级隔离边界。
4. **环境身份与数据身份分开。** 包更新可原地进行；发行版、基础镜像、用户命名空间、桌面和共享目录等冻结契约变化需要新环境。独立数据根及环境代际迁移按 v2 设计后续实现。
5. **私有文件按需暴露。** 停止环境中的文件视图使用受控 namespace 服务的设计方向；必须处理宿主跟随绝对符号链接的语义，不能只凭服务端 chroot 成功宣告完成。
6. **保存与移动需要可验证的恢复契约。** 区分原地写、临时文件替换、另存、复制、跨域移动；数据发布成功后再处理源清理。普通文件机制探针不代表产品已经提供断电恢复或并发防覆盖。

具体接口与交付关口见[文件与执行控制层 v2](../archive/notes/设计/文件与执行控制层-v2.md)。其中两个契约缺口的当前状态以[修复报告](../evidence/contract-freecad-gui-2026-10-23/report.md)为准。

## 更名兼容规则

面向用户、仓库和后续文档统一使用 **Unifier**。新命令入口为 `python3 tools/unifier.py`，它是 `ml.py` 的相对符号链接，两者使用相同实现和参数。原 Python 模块 `multilinux`、`ml` 帮助/错误前缀、容器标签、环境名、MIME 和已导出的启动项保留兼容，不在一次品牌更名中迁移持久身份。

当前机器新增 `/home/omg/文档/Unifier` 目录入口，指向原物理目录 `/home/omg/文档/多兼容linux机`。路径参与环境身份计算，直接搬动物理目录会改变身份；后续目录迁移应作为单独的可验证迁移实现。历史材料中的旧名称、路径和命令原样保留，以免破坏证据哈希。

## 备份与复核

本地完整工作区备份位于相邻 `Unifier-backups/` 的本次时间戳目录，包含 Git bundle、完整工作树压缩归档、逐文件哈希清单、未提交差分、容器/镜像目录清单和恢复说明。归档包含忽略的 `.lab` 状态；不包含项目目录外的 Podman 镜像层、容器可写层与桌面注册文件。临时 Unix 套接字仅记录路径，不能恢复为活动连接。

GitHub 保存可版本化的代码、设计、测试和实验材料。机器运行状态仍留在本地备份，云端仓库不等于整个宿主运行时的镜像。历史检查器中存在当前机器绝对路径，克隆后不能把无法访问原路径的检查误报成模型损坏。

## 行为变化

| 范围 | 实现与边界 |
| --- | --- |
| PD-01 请求超时 | 保持 300 秒期限。尚未返回句柄时发送方法错误；句柄已交付时发送一次 `Response(2)`。经原 upstream 连接向原 Portal owner 发异步、无需回复的 `Close`。晚到句柄仍用于关闭宿主请求；晚到 Response 丢弃；晚到复制结果撤销。 |
| 序号与请求关联 | GIO 为所有上游消息分配序号，最多保留 4096 个回复关联，向客体恢复原 reply_serial，内部/未知回复不泄漏。拒绝活动/已退休路径冲突；过期路径记录达到阈值后拒绝新选择。超时不强行换连接，否则会改变 Portal 请求主体。 |
| PD-02 异常重建回收 | 活 bus 配合失效 delivery 时，先终止匹配 PID/starttime 的旧交付进程，按登记目录及 dev/inode 回收旧快照，再启动替代进程。新记录绑定环境 UUID/generation；已有代际字段不符则拒绝。删除相对于已核验目录 FD，不跟随替代链接。 |
| 恢复失败 | 旧快照不存在允许幂等重试；身份缺失/不符、越界、删除失败则明确报错，保留旧归属记录，不覆盖成新实例。正常停止中 delivery 回收失败，仍尝试停止自有 bus。PID 已复用时不发送信号。 |
| PD-03 队列预算 | 全 relay 默认 32 MiB，覆盖全部连接待分派消息及等待句柄的提前响应，估算消息头、正文和对齐开销。保持单条正文 16 MiB、每连接待分派 256 条限制。超额安排一次关闭，分派、错误、遗忘、关闭释放额度。 |

32 MiB 是上述保留帧的计费上限，不是精确 RSS 或整个进程内存限额；不包括 GIO 内部缓冲、Python/GObject 开销和复制任务。小配额测试验证逻辑边界，没有进行宿主耗尽测试。

## 离线验收

所有运行串行使用主项目 `tools/offline_test_guard.py`，512 MiB / 96 任务 / 1 CPU / swap 0 / 300 秒，独立保护器 64 MiB；保持宿主至少 1 GiB 可用内存。用例仅涉及 fake runtime、临时文件、私有 D-Bus 与私有 xdg-dbus-proxy，不接入用户桌面或容器。

| 尝试 | 结果 | 说明 |
| --- | --- | --- |
| targeted-1 | FAIL，112 项中 3 项 error | 旧生命周期 fixture 使用字符串启动戳，新生产校验要求与真实 `/proc` 一致的正整数。另发现非法 `set_serial(0)` 导致 GIO 临界警告；该警告不是这 3 项错误的原因。原回执保留。 |
| targeted-2 | PASS，112 项，无跳过 | 修正 fixture，已退出的模拟 PID 不再查询宿主同号进程；删除非法 setter，使用 GIO 自动分配序号。启用 `G_DEBUG=fatal-criticals`，未出现临界错误。 |
| full-1 | PASS，938 项，5 项条件跳过 | 同时通过 243 个 Python 文件语法、42 个兼容模块别名和 5 个 CLI 入口检查。检查的是当前工作树，含原有其他未提交模块，不是隔离提交快照。 |

本轮新增 19 个回归用例：9 个请求/队列/私有总线用例，10 个重建/身份/停止清理用例。覆盖句柄前后超时、早到 Response、晚到复制撤销、普通回复序号还原、跨连接字节上限、提前响应计费、分派及 idle 注册异常、幂等回收、PID 复用、inode/代际不符、链接/目录越界、旧记录字段缺失与清理失败。

私有总线短期限用例实际经过 `xdg-dbus-proxy`，确认自动 `Close` 的 sender 与原 `OpenFile` 相同，收到失败终态且没有发布快照。此证据验证协议路径，不等同于真实 KDE 关闭窗口或钉钉上传验收。

三次测试均完成本轮 cgroup 和临时根回收，无 OOM、硬内存上限或任务数上限事件。全仓运行峰值 470024192 字节（约 448.3 MiB），有 91 次软 `memory.high` 事件，无保护中止；本轮不据此声称性能改善。

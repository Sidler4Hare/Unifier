# Unifier v0.0.5

v0.0.5 保留日常 r6 已部署的运行时、包事务收尾、请求/存储恢复、共享目录显示与 FUSE worker 软 FD 限额处理，并纳入原生 Portal 文件交付。经宿主 Portal 确认的可交付文件会映射到客体可读路径，必要时在桥接租约内生成只读快照。启用方法与适用范围见 [GTK 原生选择器兼容](GTK原生选择器兼容.md)。

## Portal 修复

三项修复单独保存于 `7d622c658f4d56f00e3b3511ed32cef07e1f0564`；日用基线保全与版本元数据分别提交。未部署的 HostShareView / FUSE direct_io 改动不进入本版。

- 请求达到 300 秒期限后向客体发出一次终态。句柄已返回时发送 `Response(2)`，否则返回方法错误。桥接通过原上游连接异步请求宿主关闭，丢弃晚到响应并撤销晚到复制结果。
- 交付进程异常退出而 bus 仍活动时，先按登记身份回收旧快照，再建立替代交付进程。归属不符或清理失败时保留原记录供恢复。
- 全桥接默认按 32 MiB 计费，覆盖待分派消息和等待句柄的提前响应。超限只安排一次连接关闭，分派或释放时归还额度。该数值按消息头、正文和对齐开销估算，覆盖范围见 [首批修复验收](Portal首批修复验收-20261111.md)。

## 发布、验收与回退

便携源码包和校验产物的输出目录为 `~/.local/share/unifier-code/packages/0.0.5/`。构建使用隔离的发布提交，验收记录应核对源码清单、解包后入口版本和实际发布包。精确提交、包 SHA-256、隔离验收结果、日常目标和回退入口记录在该目录的 `release.json`；原始运行证据保留在项目外的维护目录。

前一轮工作树通过定向 112 项。全仓 938 项中 933 项通过、5 项条件跳过。私有 D-Bus 用例确认超时 `Close` 经同一上游身份到达模拟 Portal。此前的钉钉人工上传成功发生在日常 r6，v0.0.5 的真实工作流验收状态以发布回执为准。

升级后，已运行的应用与桥接继续使用启动时的代码。应用正常退出后再启动，新建的桥接才会采用新代码。回退时恢复本次发布保留的旧 r6 入口，并在应用正常结束后重新启动。具体入口与切换对象以发布回执为准。

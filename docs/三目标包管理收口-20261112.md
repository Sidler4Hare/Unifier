# 三目标包管理收口

本轮先统一源码及状态，再实现三个后端，并在本机 Debian 和 Tailscale 连接的 Ubuntu 既有 Fedora/Arch 实例验收。开发实现、T1 数据库契约和真实包事务分别判定；此文不放宽测试规范。

## 只读清单设计

- 保留现有管理根协调锁、每环境生命周期锁、完整 CID/代际、挂载引用日志及前后停止态核验。不启动或 exec 同伴，不读取缓存冒充当前库存。
- Debian 保留 dpkg 原生 POSIX 共享锁及有界 status 读取。
- Arch 接入现有 desc 读取器，先修正原生 `var/lib/pacman/db.lck` 路径与 `local/ALPM_DB_VERSION` 处理。每个 desc 及目录身份在返回前复核；锁出现、原地修改、换路径或超预算明确拒绝。仍只声明停止态变化检测，不声明原子运行态快照。
- Fedora/RPM 首版仅支持标准 `usr/lib/sysimage/rpm` 或旧式实际目录 `var/lib/rpm` 中的 checkpointed SQLite 数据库。逐层 nofollow，持有现存 `.rpm.lock` 的 POSIX 共享锁，在有界私有副本上读取 SQLite `Packages` 并使用宿主原生 `rpm.hdr` 解码，绝不执行客体程序或维护脚本。源库不创建文件、不恢复日志、不 rebuild。
- 非空 WAL/rollback journal、缺原生锁、未知后端/布局、缺宿主 RPM Python 库、异常 schema/header、预算超限明确拒绝。SQLite 只对私有副本用 immutable，不能对仍可能变化的源库跳过锁。
- RPM 数据库总输入仍限 32 MiB，单个原生头限 4 MiB；Ubuntu 上的既有 Fedora 实库包含 1,402,996 字节的头，首轮实测据此修正了过小的 1 MiB 限制，并增加大头回归。输入预算与宿主测试硬预算分别约束，测试硬预算未提高。
- 旧式 `gpg-pubkey` 头可能缺 ARCH；按原生 rpm 查询保留 `(none)`，其他包缺 ARCH 仍拒绝。已加入原生查询对照回归。
- 挂载遮蔽检查覆盖所有受支持数据库路径、祖先及子路径；运行态同伴继续 unsupported，不能把两次相同哈希称为一致快照。

边界：该实现支持标准停止态数据库；外部写者绕过原生协议、自定义数据库宏/布局、运行态快照不在首版支持承诺内。

## 离线与真实验收

T1 使用合成的小数据库、原生解码/查询对照及 fake runtime：验证三个正式入口分派，损坏/忙/链接/替换/超额在包写入前拒绝；精确释放一次挂载引用，失败日志可恢复；三目标安装、升级、删除、本地包和中断后恢复按相同契约执行。

真实矩阵独立要求 PRE02/PRE03、固定实例清单、签名 fixture、备份与恢复条件。本机 Debian 与 Ubuntu 上既有 Fedora/Arch 均完成三轻量 CLI 与停止态原生等价。Debian/Fedora 已完成正式升级、仓库安装、删除和缺包失败；Arch 全量升级触及原有 384 MiB 客体硬限额，保留 INVALID 和恢复屏障，不重跑升级、不提高配额。具体矩阵及本地包/恢复结果见 [开发候选与验收](v0.0.7.md)。

## Arch 恢复屏障修正

本轮真实升级触及客体硬限额后，`pacman -Dk` 返回成功，但 `db.lck` 仍在。旧恢复入口因此误报成功；停止态读取器继续正确拒绝。开发树现于原生数据库审计前检查锁文件和悬空链接，不删除锁；审计失败持久保留 `needs-recovery/unknown`。Arch 显式恢复即使没有 pending 事务也重新审计，以识别旧成功记录遗留的锁。新增两项回归，包管理 70 项通过；真实拒绝结果见本轮回执。

锁仍存在时明确 BLOCKED，需要单独可审查的原生恢复方案；本轮不删除数据库锁、不重跑升级、不提高容器配额。Debian 本地包阶段因本机 PSI 中止，正式恢复已通过，不能把恢复通过算作本地包工作流通过。

## 技术依据

- [Arch ALPM desc 格式](https://man.archlinux.org/man/alpm-db-desc.5.en)：NAME/VERSION 字段及原生数据库语义。
- [RPM 原生锁实现](https://github.com/rpm-software-management/rpm/blob/master/lib/rpmlock.cc)：POSIX 读写锁；不能只看锁文件存在判断忙闲。
- [RPM SQLite 后端](https://github.com/rpm-software-management/rpm/blob/master/lib/backend/sqlite.cc)：Packages/header blob、WAL 与关闭时 checkpoint。非空恢复材料不丢弃。
- [RPM Python 接口](https://github.com/rpm-software-management/rpm/blob/master/python/rpm/__init__.py)：原生 header 解码；无需打开宿主或客体事务集。

主控另核对本机 `/usr/lib/rpm/macros` 的 `_dbpath`、`_db_backend`、`_rpmlock_path`，但本机配置不自动证明所有客体版本一致。本轮 Ubuntu 上标准 Fedora 实库 153 条与原生查询一致；该证据不外推所有 RPM 后端。

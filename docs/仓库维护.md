# 仓库维护

当前最低运行版本是 Python 3.11，使用标准库 `tomllib`。从仓库根目录运行以下命令。

先遵守 [全项目测试禁令与规范](测试禁令与规范.md)。以下命令说明检查功能，不提供资源隔离；运行回归须在有预算、有期限的测试作业内。文档变更只需相称的静态核验，不因本页列有命令就启动全套测试。

## 固定检查入口

实际 T1 执行使用统一保护入口，回执目录必须是新目录：

```bash
python3 tools/offline_test_guard.py run --out "artifacts/offline-$(date +%Y%m%dT%H%M%S)" -- python3 tools/check_repo.py
```

预算、短目录、退出码和诊断见 [测试运行器](测试运行器.md)。下面保留内部检查命令；单独执行不提供资源保护：

```bash
python3 tools/check_repo.py --quick
python3 tools/check_repo.py
python3 tools/check_repo.py --staged
```

快速检查覆盖 Python 语法、五个 CLI 入口、兼容别名的文件与导入身份，以及调用方按路径启动或复制的组件。完整检查再运行离线 unittest。检查会固定英文 locale、关闭真实容器集成测试，并为 CLI 使用临时安装根。

[仓库入口清单](../config/repository-contract.json)记录调用方、受保护文件和行为测试。迁移入口时一并核对替代路径和相应测试。静态依赖检查允许减少已登记的依赖，拦截新的产品→工具、产品→旧包名依赖和新导入环边。清理完成后随改动缩减清单中的依赖基线。

Git 空白检查继续约束现行文件。`.gitattributes` 对冻结的 `archive/evidence` 关闭空白报错，保留正常 diff；归档补丁的空白上下文行属于原始内容，不为格式检查改写它们。

`.gitattributes` 中逐项列出的历史 `artifacts/<轮次>` 回执目录也按此规则保留原始字节，包括终端回车、补丁上下文和原生测试数据。2026-11-03 至 2026-11-05 的续测、测试规范、共享容器和架构修复回执已列入同一例外。v0.0.4 的两份组装记录同样列入，只保留原始日志字节。现行 `src`、`tests`、`tools` 不在例外范围。

`--staged` 从 Git 索引导出独立目录后执行同样的检查，不借用工作树里未跟踪或未暂存的文件。整理包名、抽出模块和新增入口后，提交前运行这个命令，避免工作树通过而提交内容缺模块。工具不自动暂存或提交。

需要真实 Podman/FUSE/GUI/GPU 的验收仍按对应计划单独执行，默认跳过的集成测试不计为通过。GPU 实机用例同样需要显式 `MULTILINUX_INTEGRATION=1`；可访问 render 节点不等于 GPU 能力通过。无 Git 的正式源码包先核对 `BUNDLE-MANIFEST.json`；`--staged` 仅用于 Git 工作区。

`MULTILINUX_INTEGRATION=1` 只是代码开关，不是本轮实机授权。旧 `tests/podman_test_support.py` 使用新临时管理根和普通运行时，旧用例可创建新容器；按现行新增预算 0 的规则，未经复用/保护适配或具体新建授权不得启用。归档探针和 `tools/lab.py` 同样先审查实际副作用，不因为名称是 check/smoke 就直接执行。

发布版本在 `src/unifier/__init__.py`。`python3 tools/build_release.py` 生成版本化包并对独立解包执行完整检查，拒绝覆盖已有包和日志。安装/回退见 [v0.0.1](v0.0.1.md)。

## 归档探针复跑

```bash
python3 tools/run_archived_probe.py \
  evidence/code-quality-2026-10-30/projection_rename_probe.py
```

入口同时接受 `archive/evidence/<轮次>/<脚本>.py`。它在临时工作区复制当前 `src/tests/tools/config/fixtures/bin` 与选定轮次的证据，恢复旧的 `evidence/<轮次>` 层级。脚本及同轮次依赖的原字节保持不变，运行时安装根也位于该工作区。默认结束后清理工作区，只保留输出和原退出码。

需要检查生成文件时，先用 `--workspace /绝对路径/新目录` 指定仓库外尚不存在的目录，它会被保留。需要其他轮次的脚本或数据时，在脚本参数前重复指定 `--include-run <轮次目录名>`；脚本自身的参数写在脚本路径后，可用 `--` 分隔。

这个入口解决归档层级变化。它运行的是当前源码，独立工作区的路径和环境身份不同于原安装；旧脚本的历史 API、旧容器身份、已压缩数据和宿主条件仍需逐项确认。它不是容器或 GUI 操作的沙箱，也不会把归档成功结论直接沿用到当前代码。临时工作区里的产物不能当作原证据被更新。

## 当前源码与发布流程

主工作树标记为 0.0.8b1，正式基线为 v0.0.7。状态唯一入口为 [当前状态](当前状态.md)，未完成验收见 [剩余工作](测试剩余工作-20261109.md)。主树汇合已发布生产代码，并保留原有较新测试/保护器；其他工作树不自动覆盖主树。

`config/release-baseline.json` 保存已发布 v0.0.7 的文件清单与包哈希，用于说明构建来源。后续包由本树 `tools/build_release.py` 生成，实际 manifest/源码摘要描述本次内容。开发包使用独立版本号，构建保留旧包和日常入口。完整构建日志及包放在仓库外维护目录。

正式提交前仍需独立暂存快照检查；现有索引须保留，不能为方便打包暂存全部工作树。当前工作树通过、候选包通过、提交快照通过、部署和实机验收各自记录。不得用 dirty HEAD 作为唯一来源身份。

代码整理按故障恢复、锁序、租约和持久日志的行为保持验收；现阶段先完成三个目标的包管理，不按源码行数推断可靠性。历史投影/扩测回执保持原有边界。

## 2026-11-11 历史产物清理

旧 `archive/evidence` 已退役，恢复方式见 [历史材料说明](../archive/README.md)。上文归档复跑示例须先按该说明恢复相应材料；现行测试使用自建最小 fixture，不依赖整棵归档。旧 artifacts 的原始日志/截图/过时包已从索引移除，Markdown/JSON 摘要与当前 v0.0.4 发布文件保留；未提交的近期回执保持原位。

新增原始日志、截图、解包目录和重复源码快照存放在仓库外的运行目录，按 run ID 维护期限/容量。Git 仅保存实现、现行测试、最小 fixture 与必要的脱敏验收摘要。不要以“所有证据都进仓库”替代可追溯的清单，也不要按文件年龄删除仍覆盖现行契约的回归测试。

`artifacts/` 下的新运行目录默认忽略。审核后可用 `git add -f -- <确切的摘要文件>` 提交脱敏报告与核对汇总。原始材料保留在本地运行目录或私有归档，见 [验收材料说明](../artifacts/README.md)。

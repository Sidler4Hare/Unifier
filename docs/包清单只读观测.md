# 包清单只读观测与协调

2026-11-05 工作树实现说明；未部署，真实数据库等价性与多环境分支仍待验收。按 [架构修复计划](架构问题修复计划-20261105.md) 和 [全项目测试规范](测试禁令与规范.md) 执行。

## 协调与兼容

同一物理管理根的 `.lab/state/operations/management.lock` 使用跨进程 flock。锁顺序为管理根协调锁 → 环境包锁 → 生命周期锁；创建为协调锁 → 创建锁，身份迁移为协调锁 → 身份锁。删除同样先协调再取环境包锁和生命周期锁。应用 lease 锁只向生命周期锁或非阻塞环境包锁前进，不回取协调锁；包事务不回取 lease 锁。内部 stop 显式复用已持有的环境包锁。

默认排队期限 30 秒；`PACKAGE_COORDINATION_TIMEOUT/CANCELLED/BUSY` 表示未进入写入阶段。进程异常退出由 OS 释放 flock，锁文件保留；事务和 `needs-recovery` 状态不删除。该锁只协调正式产品入口，无法阻止外部 Podman 或原生包管理操作；外部库存、实例代际或环境集合变化仍使隔离验证失败。

事务原有字段不移除。`other_environments` 每项新增 `binding_before/after`、`observation_before/after`；原清单格式及哈希口径不变。

## 观测契约及首版范围

runtime 的 `read_inventory_readonly(record)` 返回 `InventoryObservation`，包含 `status`、原因、完整实例绑定、发行版、数据库、方法、时间、一致性证据及规范化清单。状态为 `supported/unsupported/unavailable`；只有本次独立读取成功才有清单。注册哈希或缓存不能代替观测。fake 返回同一类型，但证据明确标记 `offline fake only`，不据此推断真实后端可用。

| 后端/状态 | 当前工作树行为 | 验收边界 |
|---|---|---|
| 停止态 Debian/dpkg | 实现有限文件读取和原生共享读锁；有更新日志、非标准状态、缺字段、损坏或路径间接时拒绝 | 离线 fixture 已覆盖；与目标发行版 dpkg-query 的真实等价性尚未验收 |
| 运行态/转换中的同伴 | `unsupported`，不以两次相同读取冒充一致快照 | 尚无运行态快照适配 |
| Arch/pacman | `unsupported` | `db.lck` 的创建式锁不能由只读 flock 替代；尚未适配 |
| RPM | `unsupported` | 后端版本及可用宿主工具尚未适配，不安装宿主依赖凑支持 |

dpkg 库最多 32 MiB，输出最多 4 MiB、50,000 个包，数据库读取阶段最多 5 秒。目录逐层以 `O_NOFOLLOW` 打开，文件只接受普通文件，拒绝符号链接/FIFO及路径替换。锁住现有 `var/lib/dpkg/lock`，不创建原生数据库锁；`updates` 非空即拒绝。架构和状态用于验证身份；清单继续使用 `${Package}\t${Version}`、保留多架构重复行并排序，不改变既有哈希口径。`not-installed` 等首版未证明等价的状态明确拒绝。

原生锁只覆盖遵循 dpkg POSIX 锁协议的写者；忽略锁的外部写者不受本产品控制。读前后同时核验文件、目录与容器身份，普通变更被拒绝，不能宣称抵御任意敌对写入。

## 存储引用和中止

真实读取使用 `podman unshare` 内的宿主 Python helper，取得一次精确完整 CID 的 `podman mount` 存储引用，读取后释放一次。它不 start/restart/exec 容器，也不在宿主运行客体程序；但**存在存储挂载引用副作用，属于 T2**，不是普通 T0 查询。源数据库被容器挂载覆盖时拒绝，不猜测卷内文件。测试须先满足 PRE03 的完整覆盖，不能因没有 guest exec 而免除准入。

引用日志位于原管理根 `.lab/state/inventory-observations/<完整CID>.json`，只允许已确认 `released` 后开始下一次观测。`mounting/mounted/releasing/release-failed`、损坏日志或超时一律保留并阻断后续包写入；不删除日志、不猜测 umount、不自动重试。一次读取失败但已确认释放会返回 `unavailable`，旧失败事务保持失败。

当前没有自动处理模糊引用日志的恢复入口。遇到该状态必须核对该完整 CID、token、helper 身份和实际存储引用，交付具体恢复动作后处理；不能将 `pkg recover` 当成存储引用已恢复。后续真实验收必须同时证明准入、读取等价性和存储释放。

## 本轮边界

原有 CLI 反例改为期望正确行为并重放；跨进程锁、超时/取消、前后窗口、外部变更、数据库忙/损坏/替换及引用失败使用离线 fixture。真实固定池只做版本、完整 CID、状态与存储驱动的只读 inspect；不执行本 helper 或挂载。

固定池的 Debian 和 Arch 分属不同管理根，不能证明同管理根多环境分支。没有合规 fixture 和 PRE03 证明时，`FIX01-05` 继续 `BLOCKED`；不新建、迁移或克隆容器补齐。S3 执行所有权、S4 实际加载验证及 GUI 保存重开不因本轮离线通过而完成。

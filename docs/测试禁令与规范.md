## 1. 范围、优先级与授权

适用于本仓库及其安装版、旧入口、归档探针、临时脚本、dsh 子任务、远端执行和定时任务涉及的所有测试活动，覆盖准备、下载、解包、编译、测试、观察、停止、恢复和清理。主控对委派行为及实际影响负责。

- 用户当前明确指令优先。本规范是全项目安全基线；专项计划可进一步收紧，不能默默放宽。旧报告、旧授权、旧脚本和 `MULTILINUX_INTEGRATION=1` 均不自动授权本轮创建容器、操作桌面或破坏性清理。
- 用户要求“看看”“审计”“写计划/规范”时，执行只读检查及所需文档工作；不顺便启动模型、应用、包事务、容器或压测。
- 小型只读查询、文档编辑和文档结构检查可以直接完成；启动应用、模型客户端、安装/解包、编译、回归套件等负载须先满足本规范的准入和预算。
- 文档规则不会自动给产品增加默认 CPU/RAM 配额。本规范约束测试装置；产品资源策略、已安装版本和工作树安全适配器分别核验。
- 安全条件不满足就记录 `BLOCKED` 或中止。不得以赶进度、减少模型 token、测试已获泛化授权为由跳过边界。

配套文档：[本机测量与功能验收细则](本机测试规范.md)、[扩测历史保护器及恢复](扩测保护与恢复.md)、[2026-11-04 共享容器与依赖专项计划](共享容器与依赖专项测试计划-20261104.md)、[仓库维护](仓库维护.md)。冲突时遵守本规范的安全要求，保留旧证据原文。

### 1.1 T2/T3 按验收目标授权（2026-11-18）

用户要求“测试这个功能”“继续这批验收”或指定某项实机工作流，即授权在该目标需要的既有专用测试环境中完成常规步骤。用户指定只测 CLI、只观察或只用某一台机器时，以该范围为准。主控根据用例和当前清单自行登记宿主、完整 CID、允许写入的测试目录/包、必要的私有显示和已有设备范围。填写执行记录、新建回执、冷启动后换 PID，以及在同一工作流从 T2 进入私有 T3，均由主控办理。用户只要求调研或修改规范时仍按 T0 范围处理。

| 场景 | 主控如何处理 |
|---|---|
| 已有测试实例的 T2 包、CLI、服务、文件 | 自行做只读盘点、签名和闭包核验，按用例启停目标、安装所需包和依赖、执行和复查，卸载本轮测试包、处理测试副本、检查清单与租约并恢复起始状态。写包走正式事务；超出用例的系统升级、移除既有用户包另计。 |
| 私有 T3 工作流 | 自行建立私有显示、配置和 IPC，操作该显示内的应用和文件选择器，使用合成数据编辑、保存、关闭、重开、读回；可在该会话采集测试窗口截图、通过虚拟音视频端点核验合成素材。产品正常的确认按钮由测试方操作，遇到用户需亲自接受的条款或登录凭据再转人工。 |
| 已批准的设备或人工环节 | 精确设备、权限、测试端、接收方、数据和动作在本轮已有明确许可时，按原边界继续。只覆盖一次的 ACL、发送或恢复许可按原次数和对象执行。 |
| 缺依赖、配额不足、回执中断 | 在原范围内自行补签名依赖、拆分阶段、按 §4.2 首轮选档或纠正预算、重取只读回执。保护中止后先执行 §5 收尾，再登记一次有明确修正的复试。资源暂不足可在既定期限内被动等待；终止后的原作业保持终止。单项卡住先推进允许的独立项。 |
| 包事务恢复 | 已授权用例的本轮事务，可自行取证、备份、执行正式恢复入口及其已登记的恢复步骤，并核对原生/登记/停止态清单。恢复方案已精确包含锁的保全改名与签名包重放时，核对独占、归属和回退条件后连续执行。遇到活锁或归属不明、需要额外手工移动数据库条目或既有文件时，保全现场，只就新增动作询问。 |

需要用户决定的是**尚未获准的影响**，例如新建或删除环境、切入日常实例或活动桌面、接入真实账号/麦克风/摄像头、向外部接收端发送、提升宿主权限或修改全局配置、破坏性清理，以及 T4 故障注入。已有明确许可且仍在其目标、对象和期限内的动作直接执行。确需询问时，一次说清新增影响、具体对象和可选处理；同一批其余已授权步骤继续。守卫拒绝身份、资源或隔离时记录技术阻断，依现有规则恢复或修复守卫。

## 2. 禁令清单

| 编号 | 禁止行为 | 必须采取的做法 |
|---|---|---|
| B01 | 无预算启动负载；依靠 swap/zram 或 OOM killer 承受超量内存；因为未发生 OOM 就继续加压 | 预检余量，核验实际进程树的硬预算及独立监测；不够就不启动 |
| B02 | 多个测试作业、模型调用、包事务、编译、解包、重 GUI 无计划并行 | 本机一个活动测试作业，阶段串行；专项并发仅限已定义的小负载 |
| B03 | 通过关闭用户应用、重启服务、杀掉“看起来多余”的进程来腾资源 | 只终止本轮登记且重新核验身份的测试执行；其他负载保持原状 |
| B04 | 按进程名、模糊命令行、用户 UID 或目录前缀批量杀进程 | 禁用 `killall`、`pkill -f`、`kill -9 -1`、`loginctl terminate-user` 及同类广域清理；具体规则见第 6 节 |
| B05 | 每次测试、应用或失败重试独立新建项目根、容器、pod 或虚拟机 | 默认新增预算 **0**，先复用明确登记的现有测试环境；第 7 节规定例外 |
| B06 | 为查看状态/包清单启动非目标环境；以“随后会停掉”为理由唤醒它 | 只读检查；无法核验就保持 `UNKNOWN/BLOCKED`，不能顺带启动 |
| B07 | 使用活动桌面的输入、窗口、KWin 脚本或 Wayland/X11/DBus/音频/设备作为默认测试设施 | 独立显示、独立配置、私有 IPC；真实桌面/媒体验收单独明确授权 |
| B08 | 删除中止锁、租约、包事务日志，换普通 runtime/worker、换根或放宽宿主保护阈值绕过拒绝 | 保留失败，核验停止和恢复状态，按新尝试重新准入；单阶段预算调整须符合第 4.2 节 |
| B09 | 全局 prune、全量 stop/rm、容器 reset、Git reset/clean、覆盖脏文件、批量删除宿主 IPC/缓存 | 保存现状与证据，仅操作清单中确定归属的对象；破坏性操作另获精确授权 |
| B10 | 为测试改宿主 locale、KDE、swap、内核/sysctl、SELinux、网络/防火墙、登录会话或系统包 | 只用测试子进程环境和私有文件；宿主变更另列具体方案、备份和回退 |
| B11 | 无限采样/重试、全量抓日志回灌模型、海量 `capture_output`、内存中一次性处理大包 | 有界批次、流式处理、磁盘落盘、输出限额、期限和停止条件 |
| B12 | 将保护中止、跳过、窗口出现、模型自报或旧回执改称本轮通过 | 结果按第 11 节分级，保留原始退出码、无效样本与未完成项 |

以上禁止行为不能由脚本、子代理、归档回放或定时任务间接执行。测试用例本身需要验证拒绝时，优先使用 fake runtime，不实际触发宿主级危险行为。

## 3. 测试分级与最小执行

| 等级 | 内容 | 进入条件 |
|---|---|---|
| T0 只读/文档 | 定向源码、Git 差异、已有证据阅读；小型文档检查 | 不运行被测产品，不启动容器或探测应用；搜索与输出有界 |
| T1 离线 | 语法、相关单元测试、fake runtime 回归 | 私有临时根；关闭真实集成；有资源和总期限；先相关模块 |
| T2 真实 CLI/包/文件 | 复用容器、包事务、真实 FUSE、共享文件与生命周期 | 按 §1.1 承接测试目标，预检实例、保护器与恢复路径 |
| T3 GUI/媒体 | 私有显示 GUI，或已有具体许可的桌面/音视频/设备集成 | 由主控登记同一目标所需的私有会话和合成输入；真实账号、设备或外发按 §1.1 核对已有许可 |
| T4 压力/长时/故障注入 | 并发、长跑、资源耗尽、断电/网络/进程故障等 | 单独批准目的、机器、预算、最大时长和退出方式；默认专用机/隔离环境 |

本机禁止主动逼近宿主 OOM、fork bomb、耗尽宿主 swap/磁盘/FD 或重现桌面崩溃。必要的边界注入先用模拟或远低于宿主余量的独立测试预算验证，不把宿主拖垮作为验收方法。

只跑能回答本轮问题的用例。文档变更做引用、内容与保全检查即可；代码修复先复现失败，再验证受影响路径。验收已满足且没有具体待修问题时结束，不为增加“通过数量”反复全量回归。提交时仍执行仓库要求的暂存快照检查，但须在本规范预算内。

## 4. 启动前清单与资源预算

### 4.1 一轮一份执行记录

开始 T1–T4 前写入 `artifacts/<run-id>/` 的执行记录，私密恢复材料放受限目录，不混入公开日志。至少记录：

1. 目标、case ID、范围、允许修改的文件/包/数据、完成条件；不确定部分明确列出。
2. 时间/时区、源码 HEAD、相关文件哈希、脏文件、Git 索引状态、实际产品入口；工作树、安装版和发布包不混用。
3. boot ID、可读取的 KWin PID/start、宿主 MemTotal/MemAvailable、swap/zram 和 memory PSI 基线；无此桌面则记不适用。不能把历史机器快照当实时数据。
4. 本轮允许的完整 CID、原管理根、环境 UUID/generation、所有权标签、镜像 digest、挂载/设备、网络/IPC/PID 模式、原限额和开始状态；未选中的环境保持原样。
5. 实际负载及辅助进程、cgroup 覆盖图、峰值估计、硬上限、任务数、CPU、swap、输入/磁盘/日志预算、最大时长、监测器和停止对象。
6. 数据/配置备份、恢复命令及条件、包事务和租约状态；谁创建的资源、谁拥有停止权限、收尾核验方式。

离线用例不涉及的容器、GUI、账号等字段标为不适用；不得为了补齐表格启动环境或访问用户会话。监测与身份信息仅采所需范围，敏感字段脱敏。

没有峰值数据时，先在小输入、低上限的单组件 pilot 中估计；pilot 同样不能跳过保护。不默认按历史某个应用的峰值推算所有负载。

### 4.2 本机默认保留线与预算

以下为默认的**测试预算**。有专项预算时优先采用。对已授权的阶段，可用同机同类负载的有效回执直接选档，记录输入规模、进程树范围及峰值的可比性。新瓶颈按以下条件提高该阶段的测试配额，或调整该阶段配套的命令期限：

1. 用回执、cgroup 指标或有界试跑确认触及的瓶颈，先排除产品故障、配置错误和失控增长；记录原上限、实测峰值、新上限及选择依据。只调整与瓶颈直接相关的配额，采用满足用例的最小增量。
2. 以调整后的最坏新增预算重新计算宿主准入，计入独立保护器和余量。维持至少 1 GiB 宿主可用内存、连续准入、PSI、中止判据、身份及收尾保护；观察到明显影响日常负载时立即停止。GPU 显存余量、温度及单次提交界限继续按专项规定执行。
3. 将新配额限定在本轮的工作 cgroup 或已授权测试对象的临时 scope 内，核验实际覆盖与硬限额。原尝试已中止时，先完成收尾及恢复，保留回执和中止锁，按第 5 节另立有依据的单次复试。

并发数、环境数量、日常实例或宿主全局配置变更仍走各自的授权规则。工具无法核验新预算时，先补齐保护能力或记录阻断。

| 项目 | 默认约束 |
|---|---|
| 宿主保留量 R | 至少 **1 GiB MemAvailable**；不能用 swap/zram、缓存估算或“用户可以关应用”抵扣 |
| 启动门槛 | 连续 15 秒低压力；`full avg10 < 2%`、`some avg10 < 5%`；`MemAvailable >= R + 本阶段尚需新增的最坏内存预算 B + max(128 MiB, 10% × B)` |
| 小工具/准备 | 每阶段总内存 128–512 MiB、任务数最多 96、CPU 最多 1 核；单线程/有界线程池；小步骤通常不超过 300 秒 |
| T1 离线检查与构建 | 两机默认 512 MiB / 1 CPU；小模块可选 256–511 MiB，已知较重的单阶段可直接选 513–1024 MiB。已调研的 Xeon 服务器可给有两个独立编译单元的阶段使用 2048 MiB / 2 CPU。均为整组上限，96 任务、swap 0、最多 300 秒。选档和启动门槛见[测试运行器](测试运行器.md) |
| 实机小负载 | 默认作业总内存最多 1 GiB、总 swap 最多 128 MiB、总任务数最多 256、CPU 最多 1 核；包含控制器、显示、转发和容器，不能逐个对象各领一份总预算 |
| 已测 T2 包准备 / T3 私有 GUI | 服务器绑定的 Fedora/Arch 包准备可首轮按闭包和同类回执选至 900 秒。绑定的 Debian 私有 GUI 可首轮用 384 个汇总任务、600 秒；客体须核对现有 192 或 256 任务硬限。两档的整组内存仍为 1 GiB，按 §1.1 执行。[具体规格](测试运行器.md#固定实例的包准备与私有-gui) |
| 既有受保护客体 | 历史 fixture 为 768 MiB RAM、128 MiB swap、192 任务；只有实际满足所选装置的约束才能复用，不擅自改旧容器或产品默认限额 |
| 独立保护器 | 在负载预算之外拥有小额保留预算，建议 RAM 最多 64 MiB、任务数最多 16；其成本同样计入宿主准入，不依赖被测进程响应 |
| 时限 | CLI 单用例通常最多 120 秒，GUI 最多 600 秒，包准备单步骤最多 900 秒；一段实机执行最多 45 分钟，到期保存未完成项 |
| 准备与证据磁盘 | 每阶段新增下载最多 200 MiB、额外写入/解包最多 1 GiB；宿主相关文件系统保留至少 max(5 GiB, 容量的 10%)；超出先报告，不能自动继续 |
| 日志与采样 | 默认每命令日志最多 20 MiB、本轮日志最多 200 MiB；大输出流式落盘并限速/限量，终端只返回必要摘要。预先声明的 fixture/截图另计并设总额 |

B 使用已验证的剩余最坏新增量；已有驻留量不得重复计入，也不能只按当前 RSS 低值忽略已换出工作集的回迁成本。估不准时保守使用完整作业硬上限。禁止向用户承诺这些阈值能消除一切宿主故障；它们是拒绝和停止条件。

`TasksMax/pids.max` 计入**线程和进程**，不能只数 PID。包管理、CEF、字体缓存、解压、Podman Go 线程、模型客户端、显示转发都占预算。Qwen 服务端是否在本机加载权重以实际路由/部署为准，不能仅凭 provider 名称推断。

### 4.3 必须核验保护的实际覆盖

- 有增长风险的测试负载必须同时有整棵进程树的硬预算、独立宿主监测及总期限；硬预算还应有低于硬上限的预警线。不能仅凭 `timeout`、`ulimit -v`、一次预检或外层 `systemd-run` 宣称资源已受控。
- 核对实际 `ControlGroup`、控制器及所有 worker 的 `/proc/<pid>/cgroup`、容器 init 的祖先路径和实际 `memory.max/memory.swap.max/pids.max/cpu.max`。容器可能被 Podman 放进另一个 scope；限制命令行代理不等于限制容器。
- 默认采用一个独立测试汇总 cgroup；监测器不放进可能被负载耗尽或整体停止的同一组。确有多个不相交分组时，逐项证明覆盖并汇总上限，禁止重复使用同一份预算。
- 现有容器没有合适硬预算且无法安全纳入本轮汇总组时，阻断相应实机测试。符合第 4.2 节的调整只作用于已核验的临时测试 scope；禁止自动 `podman update`、重新创建或给日常环境改配额。
- 明确核验 OOM/任务数事件和 CPU 节流。触及测试硬上限的样本为 `INVALID`，不得直接定性为产品缺陷。性能比较应在满足安全条件的机器上采用可比限制；条件不够就延期，不取消保护。
- 不改变宿主 OOM 策略、全局 swap、zram、drop_caches、overcommit、CPU governor 或系统服务以获得测试通过。

## 5. 连续监测与强制中止

独立保护器在准备和执行全阶段至少每 **250 ms** 采样宿主 MemAvailable、memory PSI、负载存活和任务数。正常情况下可较低频率采 PSS/完整进程树，避免监测本身制造压力；发生异常先停止，不为补采样拖延。

满足任一条件就停止提交新动作、持久记录中止原因并定向收尾：

- MemAvailable < 1 GiB 连续两次；memory PSI `full avg10 > 5%` 或 `some avg10 > 20%` 连续 10 秒。
- 本轮任务数达到预定上限的 80% 时禁止再开新工作；达到 90% 持续两次，或仍持续增长且无法解释时中止。本轮内存达到硬上限的 95% 持续 2 秒也中止，不能等 OOM。
- 出现 OOM/OOM-kill、`pids.events max`、分配失败、明显交换风暴、磁盘/日志预算耗尽、被测环境反复重启或不可解释的子进程扩张。
- 指标不可读、监测器失联超过 2 秒、控制器退出、总期限到达、命令超时；外部监督须能发现监测器失联，控制器异常也不能留下无人管理的应用。
- 非目标环境发生 create/start/restart/exec、出现未核准挂载/设备访问、宿主桌面异常、用户数据变化或无法核验停止对象身份。

保护器须在负载启动前就绪；信号处理、控制器 finally 和外部期限共同负责退出。不能只启动一个与被测进程同生共死的 daemon 线程便声称独立保护已完成。

中止锁持久保存在客体不可写的位置；保护触发后禁止立即重试、自动重启、延长当前尝试的期限或降低宿主保护门槛。保留原尝试和中止锁，确认本轮进程已停止、事务状态可恢复、至少重新满足 15 秒低压力窗口，并解释修正点后才能明确登记新的尝试。按第 4.2 节调整单阶段预算属于新尝试的修正点。同一失败修正后仅允许一次有依据的复试；再次触发同类保护即结束该阶段，转离线/合适机器或报告阻断。

## 6. 进程控制与停止权限

目标是防止失控进程出现，并及时终止本轮失控负载；**不是在宿主上“杀掉占用高的程序”。**

1. 启动即登记 owner、run ID、宿主 PID/starttime/boot ID、PGID/SID、cgroup/unit；客体还登记完整 CID、环境代际和客体 PID/start/session。命令行只作辅助，不作唯一身份依据。
2. 正常退出优先使用应用退出/测试控制协议，给出有界保存或事务收尾机会；资源危险时不无限等待。发信号前再次核验 PID starttime 和所属 cgroup，防止 PID 复用误伤。
3. 普通清理只针对本轮执行；先 TERM，默认最多等待 10 秒。仍有残留时，仅在重新核验该组全部属于本轮后，才可对该精确进程、专用组或单元升级 KILL，并记录原因。不得向共用的用户会话组发信号。
4. `podman exec` 的宿主代理退出，不代表客体程序退出；须核验客体真实身份和执行结束。脱离原父进程、`setsid`、后台守护及自动重启路径同样纳入预算与收尾。
5. 只有容器已登记为本轮专用、其中没有日常/外来租约或未保存用户数据，并核对完整 CID 和所有权后，才可用“停止该容器”作为紧急兜底。共享实例中关闭一个应用，不得停掉其他应用；共享清理的破坏边界先用 fake runtime 验证。
6. 身份不符或无法确认时，不扩大清理范围，不按相似名称猜测；停掉动作队列，对已核准的本轮单元定向收尾，记录 `CLEANUP_UNKNOWN` 和需要人工核对的精确对象。禁止尝试停止用户桌面、Codex、输入法或无关服务来恢复测试。
7. 收尾核验正常退出/被信号停止、全部工作线程与子进程、监听/socket、独立显示、lease/事务及自动重启源。不能只报“主 PID 消失”。若取证会加重危机，先停止本轮负载再补最小证据。

不按 `%MEM` 排名批量杀进程，不使用 `podman stop --all`、`podman rm -af` 或对整个用户 slice 发送停止。清理许可不能外推为修改账号、卸载公共库或删除应用资料。

## 7. 容器和项目根的冻结规则

自本规范生效，**后续测试默认新增项目容器数为 0**。同一管理根内同发行版应用共享既有完整 CID；另起管理根、复制项目、`podman run/create`、Compose/pod、build 临时容器、克隆虚拟机或转到远端新建，均属于新增执行环境，不能用来绕过数量规则。普通 T1 临时文件目录不属于容器，但必须隔离、有限、可归属，不得变成新的真实安装/管理根。

- 先只读盘点，建立允许清单。当前专项池最多选 **2 个既有测试 CID、每发行版 1 个**，本机同一时刻最多运行 **1 个测试容器**；其他历史容器不自动接管。用户自有日常容器不计入“可随意使用的测试池”。
- 每次使用都核对完整 CID、原管理记录、UUID/generation、标签、镜像、挂载和账号数据。镜像相同、名称相似或共享目录相同均不等于同一实例；不要搬动参与身份计算的项目物理根。
- 容器不适合复用、原管理记录缺失、同派系准入拒绝、限额/挂载不安全时，记录具体阻断；不得自动换另一个历史实例、重建环境、改标签/记录或清空状态。
- 查询、指纹、doctor 和交叉验证不得唤醒非目标环境。非目标状态发生变化即中止；不能“停回去以后就算未触碰”。
- 如确实需要新环境，先交付可审查方案：复用失败证据、所需发行版/数量/用途、资源和挂载、数据保护、到期停止/保留/删除方式及恢复路径。**只有用户明确批准这次新建后才执行**；过去的扩大测试或下载授权不覆盖此例外。
- 记录容器前后总数与状态，逐个给出 owner、用途、最后使用时间、保留理由和复用条件。关闭应用后按租约/所有权收尾，本轮独占启动的测试容器默认恢复开始状态；容器停止不等于删除。
- 容器、镜像、卷、账号与历史测试数据删除需要精确对象清单、备份与恢复方案及明确授权。禁止全局 prune/reset 或为了减少数量直接删旧环境。

## 8. 宿主、数据、GUI 与包管理边界

2026-11-11 用户另行选择了「使用现有登录会话，由用户手动重启钉钉并点击上传，不发送文件」。此类明确授权的人工日常诊断可运行有硬预算、独立监督和期限的只读观察器，读取目标 PID/start、已定位的少量状态标量、窗口身份及相关 Portal 调用元数据。不得采集聊天正文、凭据、文件内容或无关窗口标题，不自动启动/停止/调试附加/注入用户应用，不扩大到其他应用或桌面输入。观察器的预算仅覆盖观察器及其查询子进程，用户手动运行的日常应用不因此被宣称受控；结果标为「人工工作流观察」，不算 T3/PRE03 通过，也不放行后续自动化 GUI 或包事务。需要完整自动冷启动/断点追踪时仍按 T3 准入。

- 私有显示不得占用已有 socket 或显示号；显示/转发默认不对外监听，不把用户 X0、Wayland、KWin 脚本、音频、GPU、摄像头或账号配置暴露给测试。禁止操作活动桌面焦点、窗口和键鼠。

- 宿主安装、网络、locale、服务和桌面设置变化均单列；子进程 `LC_ALL=C` 不等于修改宿主 locale。出现事故先停止本轮负载、保全证据并只读核查，不自动“修复”用户已恢复的桌面。

### 11.3 每轮必须交付的收尾回执

1. 用例状态与未完成项、源码/fixture 指纹、有效/无效样本、原始证据位置和保护触发记录。
2. 本轮进程、线程、单元、显示/转发/监听和自动重启源是否退出；客体真实执行与租约是否结束；未知对象精确列出。
3. 容器数量变化（默认新增 0）、所选 CID 前后状态、非目标环境是否发生事件、日常容器/账号/文件是否保全。
4. 宿主资源最低余量/压力、boot/KWin 身份变化及实际安装/配置变化；没有现场采集就明确未核验，不从历史快照填表。
5. 包事务/数据库/投影/会话恢复状态，备份与回退位置，临时文件/测试包/缓存保留原因；只删除已确认归属且授权范围内的对象。

回执不完整或状态未知时标为 `PARTIAL/UNKNOWN`。暂停依赖该状态的用例；宿主、保护器或残留进程的安全状态未知时暂停该宿主的增长负载。其余可安全独立执行的工作继续。用户没有要求部署、提交、推送或清理，就不把这些动作作为收尾附带执行。

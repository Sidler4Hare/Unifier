# 测试运行器

2026-11-09。遵守[测试禁令与规范](测试禁令与规范.md)。本页不授权容器、包事务、GUI 或压力测试。

## T1 统一入口

```bash
python3 tools/offline_test_guard.py run --out "artifacts/offline-$(date +%Y%m%dT%H%M%S)" -- python3 tools/check_repo.py
```

定向回归把末尾命令换成 `python3 -m unittest discover -s tests -p 'test_reuse*.py' -v`。中文复查在 `run` 后加 `--locale zh_CN.UTF-8`。`--out` 必须是尚不存在的目录；已有尝试均不覆盖。

`check_repo.py` 仍固定英文；中文复查应直接使用 unittest 命令，不能把外层 locale 选项当成仓库检查已覆盖中文的证据。

按[双机调研](双机测试预算-20261118.md)选当前阶段。已有同机可比回执即可首轮选用，已知小模块和重编译分别登记实际峰值、输入及线程数。

| T1 阶段 | `run` 参数 | 工作组 RAM / CPU | 宿主 MemAvailable 准入 |
|---|---|---|---|
| 已知轻量单测或小输入检查 | `--memory-mib 256` | 256 MiB / 1 CPU | 1472 MiB |
| 普通回归、尚无更精确数据 | 默认 | 512 MiB / 1 CPU | 1728 MiB |
| 已知较重的单阶段，如 Mesa NIR | `--memory-mib 1024` | 1024 MiB / 1 CPU | 2240 MiB |
| 已调研 Xeon 服务器上的双路离线编译 | `--server-build`，构建命令最多 `-j2` | 2048 MiB / 2 CPU | 3348 MiB |

单核档可在 256–1024 MiB 之间按阶段取值。双核档由守卫核对服务器主机名、CPU 型号、物理内存及可用 CPU，再验证实际工作 cgroup。各档均使用 96 任务、swap 0、最多 300 秒，`memory.high` 为硬限额的 7/8。监督器另有 64 MiB / 16 任务。令 B 为工作与监督硬预算之和（MiB），门槛为 1024 + B + max(128, ⌈B/10⌉) MiB，连续满足 15 秒。宿主 FUSE 专用入口固定为 512 MiB / 1 CPU。扩大 CPU 配额时，构建命令也须显式限制并行度。

工作进程启动前核验实际 cgroup 限额、单位 InvocationID 和进程身份，再发出 go。监督器在组外每 250 ms 采样；工作进程检查监督心跳，systemd BindsTo 和总期限处理监督退出。宿主保留线仍为 1 GiB；准入 PSI full < 2%、some < 5%，运行 PSI full > 5% 或 some > 20% 持续 10 秒中止；作业内存达到硬限额 95% 持续 2 秒中止。80% 任务数关闭队列，90% 任务数两次触发中止，OOM/硬限额事件仍立即判无效。参数按 2026-11-11 用户授权调整。只结束本轮精确登记单元，不停止用户程序。

`check_repo.py` 和固定实例监督器统一使用 `/tmp/ut-*` 短临时目录。T1 HOME、XDG、安装根均私有，XDG runtime 也位于短路径；显示及会话环境清空，集成开关固定为 0。固定实例控制器保留宿主 Podman HOME/XDG，客体环境仍走产品独立传递路径。

两种新入口共享仓库测试作业锁。旧回执脚本保留原字节，后续不复制出新的临时保护器。此锁不证明第三方手动命令或历史脚本已被强制纳入保护。

## 证据和退出码

- `spec.json`：命令、目录、期限和预算。
- `worker-ready.json`、`command-identity.json`：实际身份及限额。
- `admission.jsonl`、`samples.jsonl`：宿主 PSI，工作组 PSI、swap、anon/file、页回收及缺页计数。
- `command-result.json`、`worker-final-cgroup.json`、`receipt.json`：原始退出码、最终事件及收尾。
- `abort.json`：保护中止，保留后不自动重试。

离线与固定实例监督器共用退出判定：0 表示本次命令成功且收尾可核验；1 表示命令失败；2 表示保护、指标、身份、收尾或证据问题。原生退出码保存在回执中，子命令失败不再由监督器返回成功。回执中的工作单元可能因监督器结束其等待清理循环而显示 `failed`；应结合真实 `command_result`、保护原因和最终 PID/cgroup 判读，不能将单元标签替代应用退出码。

PSI 记录等待压力。同步的宿主和 cgroup 数据帮助定位范围，不单凭可用内存或缓存大小判断泄漏，也不自动将压力归因于用户其他程序。必需诊断缺失时明确失败，不补零。

## 实机边界与当前验证

固定实例监督器按完整 CID、原管理根、UUID/generation、挂载及汇总预算准入。三目标轻量 CLI、合成应用隔离 GUI 和固定 Debian 的 WPS SH10 各有对应回执。按[当前状态](当前状态.md)和[剩余台账](测试剩余工作-20261109.md)核对本次负载的覆盖。

### 固定实例的包准备与私有 GUI

用户要求执行验收后，主控写入当次新规格和证据目录，即可按下表选档。规格由 `tools/reuse_test_guard.py` 核验；整组 RAM 1 GiB、CPU 1 核、swap 128 MiB。每次在启动前选定期限，工作单元按该期限停止。外层独立监督须覆盖准入和收尾。

| 用例 | 新规格字段 | 守卫实际检查 |
|---|---|---|
| T2 服务器正式包测试中的准备阶段 | `fixture_profile: remote-package-prepare`，`seconds` 取 1–900，按预估闭包和时长选用 | 只接受原 Fedora 44 / Arch 登记的 CID、UUID、代际、名称和管理根；客体 384 MiB / 128 任务，汇总 256 任务。原 `remote-package-20261112` 规格维持 300 秒上限。 |
| T3 固定 Debian 的私有 GUI | `task_profile: debian-private-gui`，新 `unit` 形如 `unifier-private-gui-writer-02`，`seconds` 取 1–600 | 复用原 SH10 绑定的 CID、UUID、代际和管理根，汇总任务由 256 提到 384。默认要求客体现有 192 任务；已配置为 256 时写 `guest_tasks: 256`。启动前查保存值、运行时查生效值，守卫不负责改动客体配置。 |

固定实例由已核验的独立监督入口运行。私有显示、私有配置和合成输入由用例建立和核对。旧 SH10 规格保留原单次运行名，新规格使用独立的运行名和回执。新 GUI 档收尾时在作业锁内确认汇总组已空，恢复并回读原任务上限，结果保存在 `gui-slice-tasks-after.json`。有残留任务或发现外部改动时保留现场，标记 `CLEANUP_UNKNOWN`。授权范围适用[全项目规范](测试禁令与规范.md)第 1.1 节。

固定实例规格可显式选择 `guest_memory_high: 536870912`：仅向已核验 CID、StartedAt、PID/start 和覆盖路径的当前客体子组写入更紧的 512 MiB 回收线。默认不启用，已有更紧值拒绝放宽，不改 HostConfig、硬限额或宿主全局设置。此设置不保证 GUI 能在原预算内完成；本轮一次重试虽避开原内存线，仍因 PSI 中止。不得用它自动重试、提高硬限额或修改现行保护阈值。

# 仓库布局

现行代码和历史证据分开存放。证据路径不改内容，已有容器上的标识也不改。

## 现行树

| 路径 | 作用 |
|---|---|
| `src/unifier` | 现行 Python 包 |
| `src/multilinux` | 旧包名的导入转发。每个文件转到同名的 `unifier` 模块 |
| `tests` | 回归测试，导入 `unifier` |
| `tools/unifier.py` | 诊断和快捷命令入口 |
| `tools/ml.py` | 指向 `tools/unifier.py` 的符号链接。已导出的桌面项和旧命令仍可调用 |
| `tools/check_repo.py` | 离线检查工作树或独立导出的暂存快照 |
| `tools/run_archived_probe.py` | 用当前源码在独立目录复跑归档探针 |
| `bin/unifier` | 用户启动器，执行 `python -m unifier` |
| `config` | 三个目标发行版和镜像锁 |
| `fixtures` | 资源探针等小夹具 |
| `设计` | 仍在用的定档、CLI、白名单、验收步骤和未完成测试计划 |
| `archive/notes` | 已完成的阶段说明和早期调研。索引见 `archive/notes/README.md` |

`python3 tools/unifier.py` 和 `python3 -m unifier` 是现行入口。`python3 tools/ml.py` 与 `python3 -m multilinux` 进入同一实现。

2026-11-05 的包清单、协调锁、执行租约、加载核验和请求桥原型都在 `src/unifier`：`package_inventory.py`、`inventory_probe.py`、`operation_lock.py`、`application_leases.py`、`application_supervisor.py`、`loader_verification.py`、`agent_bridge.py`、`bridge_client.py`、`exec_control.py`。这些模块及 `dependency_diagnostics.py` 纳入 2026-11-07 重新组装的 v0.0.3 源码包和日常安装。`unifier-0.0.2.tar.gz` 以及 `backup/` 里的旧安装不包含它们。

## 证据

历史证据的原文件在 `archive/evidence`。仓库根的 `evidence` 是指向它的符号链接，原来的 `evidence/...` 文件路径仍可读取。旧报告的校验和仍针对原字节；验证时需使用原清单要求的工作目录，并恢复已经压缩的工作负载。

符号链接不能保住脚本中 `Path(__file__).resolve().parents[2]` 的旧含义。复跑这类归档探针时用 `tools/run_archived_probe.py`，它复制当前代码和选定的证据目录到独立工作区，恢复原来的层级，不改归档脚本。用法和能力边界见 [仓库维护](仓库维护.md)。旧报告里已经移走的设计稿链接仍保留原文，按 `archive/notes` 索引查找。

不要改 `archive/evidence` 里的文件内容，也不要在那里改旧名字。那些副本的校验和记录的是归档时的字节。证据报告里的 `设计/`、`调研/` 链接保持原文；已经移走的阶段稿在 `archive/notes`。

## 名字改到哪里

这次改的是现行源码里的旧包名和命令名：

- 包名 `multilinux` 改为 `unifier`。异常类是 `UnifierError`，`MultilinuxError` 仍指向同一个类。
- 诊断命令的程序名和错误前缀由 `ml` 改为 `unifier`。
- 新启动的 worker 和新导出的桌面项调用 `tools/unifier.py`。

下面这些拼写已经写进容器、桌面文件、操作日志或投影身份，这次没有改：

- 容器标签 `multilinux.project`、`multilinux.env`、`multilinux.role`
- 容器名 `ml-<令牌>-<环境 id>`
- MIME `application/x-multilinux-*`
- 桌面 ID `multilinux-<令牌>-<应用>` 和 `X-Multilinux-*` 字段
- 容器内路径 `/tmp/ml-xauthority`、`/tmp/ml-incoming`、`/home/multilinux-<uid>`、`/run/multilinux-portal`
- 临时文件和日志前缀 `.ml-`
- 投影 inode 盐 `ml-view-inode-v1`
- 进程标记 `MULTILINUX_APP_WORKER`、`MULTILINUX_FILE_WORKER`、`MULTILINUX_PROJECT_SESSION_WORKER`
- 集成测试开关 `MULTILINUX_INTEGRATION`、`MULTILINUX_EVIDENCE`
- 探针线协议 `multilinux.dmabuf-roundtrip.v1`，以及 `tools/probe_*.py`、`tools/prepare_*.py` 里的 `multilinux.*.v1` 记录格式。这些工具仍按归档证据里的旧模式解析，不跟着包名改

历史报告里的 `src/multilinux` 和 `tools/ml.py` 保持原文，因为那是当时的路径。

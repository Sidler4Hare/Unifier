# 依赖自动化迭代

起点：v0.0.3。目标是把可确定的诊断、查库、修复、验证和恢复变成产品协议，让用户与 AI 都不必逐个猜包名、修改 wrapper 或拼接修复命令。以正式入口的可复现证据推进，不靠扩大重试或取消隔离换取通过。

## 本版已交付

- 静态 ELF 扫描和客体仓库唯一提供者补装继续作为安装默认步骤。
- `repair-deps --from-log` 从明确 loader/dlopen 缺库错误生成提示，进入同一事务并复查；`--diagnose-only` 只解析，不查询提供者，也不接触容器。`library_repair_candidate=true` 只表示日志适合进入查库阶段，不证明存在提供者或环境能够安装。
- 诊断输入有限额和一致性检查；保存固定类别、库名、哈希，拒绝把 ABI、权限、命令或未定位插件故障混为缺库。
- 包事务协调、执行树租约和依赖证据分层一并纳入本版；真实能力仍按各自验收状态记录。

## 下一批的顺序和完成条件

| 顺序 | 要减少的人工工作 | 产品实现与完成条件 |
|---|---|---|
| 1 | 为跑测试手工拼保护脚本 | 完成 PRE03 的真实进程树/cgroup、非目标事件及保护注入验收；统一入口自动准入和精确收尾。未通过不启动客体 |
| 2 | 多环境安装时改登记或换根绕过 | 完成停止态 Debian 的原生清单等价性和存储引用释放验收；定义可审计的引用对账/恢复命令；Arch/RPM 分别适配，运行态采用一致快照或明确拒绝 |
| 3 | 手工保存日志和选择补库参数 | 受管应用失败时记录有上限、可脱敏的诊断与执行身份；在下一次显式修复请求中消费同一份记录，关联版本/包哈希，旧记录过期即拒绝。原应用不因修库自动重放 |
| 4 | 手改路径、wrapper 和插件设置 | 对可信 fixture 验证目标加载器搜索图、符号版本、wrapper 环境与 dlopen；只将已证实且可回退的应用适配做成版本化规则。无法建立证据时保留 GAP，不全局设置 LD_LIBRARY_PATH |
| 5 | 人/AI 每次重新编排恢复 | 将诊断输出变成带前置条件、精确对象、预算和幂等状态的修复计划；仅支持明确的内置动作。中断后核验实际状态再 resume，不重复安装或删除未知租约/锁 |

外部命令、Python/其他语言模块、Qt 插件、桌面服务、符号 ABI 和厂商缺陷分别建适配与 fixture，不能由 SONAME 查库器猜测。AI 可以解释固定诊断和选择已授权计划，产品正确性不能依赖模型临时生成任意 shell 命令。

## 每批必须留下的结果

保留原失败、修复前后同一输入、正式入口事务、原生退出码、实际库存/加载与工作流证据、未知项及恢复路径。离线 fake、本机微型机制、目标客体和 GUI 分层验收。新增容器预算仍为 0，不修改日常配置，不删除冻结回执；通过本批验收后结束，不无限探索。

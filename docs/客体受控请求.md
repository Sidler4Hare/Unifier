# 客体受控请求

工作树提供 `unifier agent serve` 和 `unifier agent request`。宿主签发策略，客体只能提交 action ID、随机请求 UUID 和凭据；目标项目、环境实例、cwd、argv 和超时全部由宿主预先固定。此入口不暴露 Podman socket。当前动作只有只读 `host-info` 和受管 `project-run`，没有通用宿主命令或包管理维护动作。

## 签发和连接

策略是宿主所有的 0600 JSON 文件，直接父目录必须是宿主所有的 0700 目录。策略文件不应放进客体可写共享目录。`origin.session_uuid` 来自已经运行的受管项目会话；`origin.environment_binding` 必须包含该会话的 environment ID、UUID、generation、完整 container ID。每次请求重新核对来源客体执行仍活着、租约仍存在、运行实例仍相同。

策略字段示意（UUID、CID、scope、期限和凭据均须替换成宿主实际生成或核对的值）：

```json
{
  "schema_version": 1,
  "token": "<secrets.token_hex(32) 生成的随机值>",
  "socket": "/宿主明确共享的私有目录/bridge.sock",
  "expires_at": 1794000000,
  "origin": {
    "session_uuid": "<来源会话 UUID>",
    "environment_binding": {
      "environment_id": "arch",
      "environment_uuid": "<环境 UUID>",
      "generation": 1,
      "container_id": "<完整 CID>"
    }
  },
  "actions": [
    {"action_id": "host-info", "type": "host-info"},
    {
      "action_id": "build-approved-project",
      "type": "project-run",
      "project_uuid": "<宿主登记的目标项目 UUID>",
      "environment_binding": {
        "environment_id": "debian13",
        "environment_uuid": "<目标环境 UUID>",
        "generation": 1,
        "container_id": "<目标完整 CID>"
      },
      "argv": ["/usr/bin/make", "check"],
      "cwd": "/宿主登记且已挂载的项目目录",
      "scope_sha256": "<project plan 得到的 scope 摘要>",
      "timeout_seconds": 60,
      "request_ttl_seconds": 90
    }
  ]
}
```

来源和目标可以不同。宿主对每个 `project-run` 重新执行项目准备和宿主发行版准入检查；创建会话后再次核对实例、argv、cwd 和 scope。策略修改不会热更新现有 broker，应关闭旧 broker 后重新签发。

```bash
UNIFIER_HOME=/宿主安装根 unifier agent serve --policy /宿主私有目录/policy.json
# 已被宿主明确授予 UNIFIER_AGENT_TOKEN 的客体会话里：
unifier agent request --socket /私有共享目录/bridge.sock --action host-info
# 只有 Python 客户端代码时也可使用：
python3 -m unifier.bridge_client --socket /私有共享目录/bridge.sock --action host-info
```

凭据通过来源会话的显式环境变量白名单交付。项目执行使用匿名环境文件描述符把值交给 Podman，参数中只有描述符路径。值不会写入磁盘或因并发执行而改变父进程的环境。凭据应保存在宿主私有策略中，测试回执和命令历史应省略凭据值。同一客体内拥有凭据且能访问 socket 的进程可以使用授权。socket 为 0600，父目录为 0700，Linux 还检查连接方的宿主 UID。对于超过 AF_UNIX 长度上限的路径，通过已核验父目录 FD 的 `/proc/self/fd/N/文件名` 连接，进程 cwd 保持原值。

## 期限、重放和失败

`expires_at` 是授权的绝对 Unix 到期时间，每次请求在登记和执行前检查。`request_ttl_seconds` 是进行中请求占用日志的期限，不能替代授权到期。撤销文件可逐行放入 token 的 SHA-256；读取失败时拒绝。

请求先原子登记，再执行。相同 UUID 在进程重启后仍拒绝；重发不会重复执行。异常失联不能保证客户端收到结果，应由宿主检查持久请求日志和项目会话后决定下一步，不自动换 UUID 重跑。响应、回执和请求日志递归去除本策略的凭据值。

正常零退出返回 `ok`；目标非零退出保留原退出码并返回 `failed`。客户端分别用退出码 0、1、2、3 表示成功、传输/用法故障、请求被拒绝、执行失败或未解决。输出仍走宿主受管会话的 stdout/stderr，不把任意输出塞进 socket 帧；每帧最多 64 KiB。

超时通过项目会话取消机制按客体 PID、启动时间和会话定向发信号。未证明客体已退出时，请求保持 `unresolved` 并保留租约。未收尾的线程及同一来源会话的持久 `claimed` 或 `unresolved` 记录会阻断后续运行。SIGTERM、SIGHUP 和 SIGINT 触发 broker 定向收尾，SIGKILL、断电或未知客体状态可能留下待恢复记录。

使用原策略和管理根运行 `unifier agent serve --policy /宿主私有目录/policy.json --recover`。该入口不开监听，也不重放请求。它核对原 broker、项目会话、实例绑定、客体退出和租约；能证明从未提交或客体已退出时才完成恢复。活跃和身份不明的对象保持原状，恢复后相同请求 UUID 仍不能重新执行。

已停止的原容器可以作为客体执行结束的证据，但必须同时核对原环境 UUID、generation、完整 CID 和所有权标签；替代容器、未知实例或无法 inspect 保持未知，恢复不会为查询而启动旧 GUI。

## 验证边界

离线回归和真实客体客户端分别记证据。可运行 Python 客户端不等于已安装、配置并验收客体原生 dsh/其他 Agent 的完整模型工具调用。宿主维护动作、跨主机传输、图形交互与媒体没有由这个桥自动获得支持。

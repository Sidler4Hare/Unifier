## 修改后的执行标准

| 任务 | 笔记本 | 服务器 |
|---|---|---|
| 轻量 T1 | 已知小模块可选 256 MiB / 1 CPU，现场准入 1472 MiB，比旧最低门槛少 256 MiB；本轮 9 项守卫合同实际只用 28.8 MiB 峰值 | 同一轻量档 |
| 常规回归 | 默认 512 MiB / 1 CPU，准入 1728 MiB。原 Beta 1 独立回归的整组采样峰值约 258 MiB，整套仍用常规档 | 同一常规档 |
| 已知较重的单阶段 | 依输入和既有峰值，首轮可选 768 或 1024 MiB / 1 CPU，准入 1984 或 2240 MiB | 单个重编译同左。两个可并行编译单元可显式使用 2048 MiB / 2 CPU，准入 3348 MiB；构建工具限两个工作线程或 `-j2` |
| T2 包与文件 | 同一验收目标可连续完成依赖准备、签名校验、正式事务、清单复核及范围内的恢复。Arch 原 384 MiB 客体按已证实的闭包分阶段执行 | 原固定 Fedora/Arch 实例可显式选包准备阶段最长 900 秒；原规格限 300 秒。依赖闭包和同类回执决定实际给多少时间 |
| T3 私有 GUI | 原固定 Debian 的 WPS SH10 曾用到 251 个任务、约 800 MiB 汇总内存。相同实例现在可以从首轮选 384 个汇总任务，仍按 1 GiB / 1 CPU 准入；192 或 256 个客体任务取决于实际配置。[WPS 实测](../artifacts/wps-close-regression-20261112/report.md) | 已纳入目标的私有显示、合成媒体与读回按同轮授权执行；设备、显存和其他服务依专项核验。双核编译档只供 T1 |

准入连续 15 秒须同时满足所选档的可用量、memory PSI full < 2%、some < 5%。运行中，MemAvailable < 1 GiB 连续两次，或 full > 5% / some > 20% 持续 10 秒，即中止。容量选错时申请适当的作业硬上限，先核对哪一层触线；性质明确的准入阻断、客体硬限额、宿主压力和产品命令失败分别记录。判断 PSI 和 memory.high/max 所依据的计数口径见 [Linux PSI](https://docs.kernel.org/accounting/psi.html) 与 [cgroup v2](https://docs.kernel.org/admin-guide/cgroup-v2.html)。

## 包事务恢复

每次原生命令执行前持久保存事务、参数和执行状态；真实 Podman 执行还保存客体 PID、启动时间、session/group 及环境 UUID/generation/CID。超时、SIGTERM、SIGHUP、SIGINT 会尝试定向清理，并保留输出尾部及清理结果。SIGKILL、断电等不能由信号处理器恢复的中断，由持久进行中记录在下次操作时识别。

确认原命令已结束后，重新核对包清单和原生数据库。包集已改变就更新摘要与内容版本。无法证明执行已结束、清单不可读或原生数据库不干净时，返回 `needs-recovery` 并阻止下一次包修改；旧摘要只是上次记录，不能被视作当前状态。`env inspect` 同时显示未知状态与待恢复事务。

```bash
unifier pkg log 实际环境ID
unifier pkg show txn实际事务ID
unifier pkg recover 实际环境ID
```

`recover` 在包操作锁内核验同一环境/容器身份，审计 Debian `dpkg --audit`、Fedora `rpm --verifydb` 或 Arch `pacman -Dk`，再刷新清单；原失败事务保持失败，记录恢复时间。它不会偷偷重跑厂商维护脚本。

如果客体执行仍活着、身份未知或清理无法确认，命令会要求先明确停止该测试环境。停止环境不会删除其数据。原生数据库损坏或包尚未配置时，先检查保存的诊断，使用该客体的原生工具完成所需修复，再运行 `pkg recover`。不要清掉事务记录来绕过保护。

## 原生交互

真实终端保留包管理器的确认、输入和尺寸传递。交互 apt-get 采用 `Dpkg::Use-Pty=0`，让 dpkg 维护脚本看到更新后的终端尺寸；APT 自带的嵌套 PTY 进度样式会改变。非交互和 JSON 模式不改该选项。自动依赖范围见 [自动依赖与原生安装交互](自动依赖与原生安装交互.md)。

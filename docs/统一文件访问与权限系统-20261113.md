# 统一文件访问与权限系统

2026-11-13。设计与实现说明；本轮仅修改开发工作树，测试与部署状态见末尾。

## 目标与资源约束

每个发行版维持一个共享容器和一套原生包数据库。应用共同复用依赖；不引入每应用容器、重复包安装或跨容器依赖同步。文件访问控制独立于依赖管理，不为每次选择启动新的常驻服务。普通项目仍走已经核验的直接挂载，选择共享范围之外的单个文件才按需复制。

统一的是授权判定、对象身份、交付契约、生命周期、诊断与恢复。现有静态共享、只读文件副本、停止态只读投影、受管复制/移动成为有明确能力的后端。后端继续承担各自的文件系统安全机制；源删除仍需显式受控移动授权。

## 主体和权限

访问主体的强制边界是环境 UUID/generation/CID。同容器中的应用共享 Unix 身份和挂载；应用标识用于来源记录，不作为独立隔离的证明。依赖仍由发行版包管理器统一解决。

每次操作明确用途和权限：读取、编辑、创建/保存、目录浏览、复制源、复制目标、受控源删除。请求路径只是定位，授权来自宿主配置、已登记的数据根/项目，或已核验的 Portal 成功响应。客体提交的 app_id、URI、旧计划 JSON 和旧 grant 都不能单独获得访问权。

共同判定顺序为：主体/代际 → 权限配置版本 → 用途 → 根/项目限制 → 拒绝路径 → 后端能力 → 实际对象/挂载核验。只读配置不得被可写项目覆盖；用户选择不得绕过显式拒绝。路径按组件判断，拒绝非规范路径、歧义映射、链接逃逸和被遮蔽的挂载。

静态挂载提供环境级权限：已有可写挂载上的“只读请求”不构成操作系统只读保证。禁止把普通软件层拒绝表描述成隐藏了已经挂入容器的路径。收紧与既有挂载相冲突的权限必须明确指出冲突；旧挂载须经过环境迁移才能真正撤销。撤销已交付路径也不保证收回应用已打开的 FD 或已读取的数据。

## 模块与接口

| 模块 | 职责 |
|---|---|
| `file_access` | 权限策略、用途、统一路径与静态映射、后端选择；纯判定与可审计决定 |
| `file_access_store` | 宿主侧版本化策略、授权账本、配额预留/提交/释放与故障状态 |
| `portal_delivery` | 统一 broker 的选择交付适配器；固定源 FD、有界复制、原子发布 |
| `portal_file_bridge` | 验证请求/响应归属、取消与唯一终态；把已授权选择交给 broker |
| `file_routes` / `project_sessions` | 登记根与项目的授权来源，复用共同权限与挂载判定，执行前重新核验 |
| `file_operations` | 复用共同权限判定；保留已有锚定 FD、持久复制/移动及源清理事务 |
| `views` | 只读投影后端；保留精确所有权、挂载与恢复协议 |

选择交付授权记录包括：schema、grant_id、环境 binding、交付租约、策略版本、用途、后端、实际权限边界、源对象身份、客体路径、字节数、状态和失败原因。记录在宿主私有状态目录，不能置于客体可写的桥接挂载。日志只用于诊断；就绪使用独立的版本化控制通道。

## 交付能力

| 后端 | 读取 | 编辑/保存 | 目录 | 回收 |
|---|---|---|---|---|
| 已核验静态映射 | 原件 | 仅真实可写挂载 | 已共享目录 | 撤销中介授权；挂载暴露仍需迁移处理 |
| 有界文件副本 | 初始 0400 的独立副本 | 拒绝，不把修改副本宣称写回原件 | 不支持任意目录复制 | 按租约/对象身份撤销副本 |
| 停止态投影 | 客体只读树 | 拒绝 | 只读浏览 | 现有视图租约定向卸载 |
| 受管复制/移动 | 锚定源对象 | 经登记的目标发布 | 沿用现有能力 | 现有操作日志与显式源清理 |

不在现有能力内的用途返回稳定的能力拒绝。新系统不默认创建可写 FUSE、目录镜像或同步回写器。

## 入口统一

GTK、Qt、kdialog、zenity 的选择结果全部通过同一 `files-bus` 交付服务。命令选择器只解析参数、发送请求并输出已经交付的客体路径；不再次把 URI 当宿主路径翻译，不另建权限规则。所有入口共享取消、超时、对象/字节预算和配额错误。

副本不会写回宿主原件，但同 UID 客体可修改副本权限及内容；0400 不是应用隔离或不可变保证。

FileRef 与项目会话通过同一静态映射和权限接口。直接启动仍保留重新解析与身份核验，不把 plan 当 capability。受管复制/移动在准备、发布和源删除边界重新核验共同策略及已有数据根权限。

## 状态、配额与恢复

授权状态为 `preparing → ready → revoking → released`，失败进入 `failed` 或 `needs-recovery`。先持久预留，再物化并记录对象身份，最后发布路径。取消与失败释放已确认的资源；清理失败保留配额占用和恢复状态，不用忽略删除错误制造“已释放”。静态映射不消耗复制对象和字节预算。

同一交付租约采用有限对象数、累计字节、单文件大小和排队预算；副本随租约结束回收。账本记录中断窗口，恢复只接受精确环境/租约/目录 inode，不因目录名称相同就删除。未知记录不覆盖，未知占用不补零。

策略和记录版本独立于容器代际。旧环境、项目、应用与文件操作记录保持可读；新入口补充新字段。旧桥接进程通过协议版本判定兼容性，不把存活当作已经运行新代码；仍有租约时不能为了刷新而终止其他应用。

## 管理入口与兼容

`unifier file access policy` 显示完整策略；用 `unifier file access policy --set <JSON文件>` 更新，必须保留当前 `revision`，成功后加一。策略存于管理根的 `.lab/state/file-access/policy.json`；缺省沿用现有授权来源，不增加静态共享范围。损坏、未知 schema、未知字段与过期版本均拒绝。

- `read_roots` / `write_roots` 为绝对宿主路径列表或 `null`；`null` 表示不额外缩小已有后端/注册根权限，空列表表示不允许相应用途。写入同时受读范围约束。
- `denied_roots` 优先拒绝指定路径及后代；目录请求若覆盖被拒绝的后代也拒绝。
- `selected_read` 控制选择交付的读请求；默认 `true`，不是编辑/保存权限开关。
- 更新针对后续授权。已授予的副本、已运行的项目会话、已打开的 FD 不自动消失。与既有静态共享矛盾的配置拒绝；创建新环境时同样检查共享范围，拒绝把宿主权限账本共享给客体。

`unifier file access list` 列出选择交付租约、环境 binding、各 grant 的决定与状态。`unifier file access revoke <lease_id> <grant_id>` 持久请求撤销；返回 `revoking` 不等于已经回收，现有桥接循环完成精确清理后才变成 `released`。静态 grant 撤销只是停止此次中介授权，不卸载共享目录。

`unifier file access recover <lease_id>` 恢复已死亡交付进程的孤立副本。先核对 boot ID、PID/starttime、环境 UUID/generation/CID、桥接目录与 selection inode；活进程、身份变化或未知记录均拒绝。只删除该租约目录，不启动容器、不发进程信号、不删除新桥接 socket。可以幂等重复恢复。FileRef 复制/移动、项目会话和只读投影仍使用各自现有的持久记录与恢复命令，统一策略不替代它们的资源所有权。

版本 2 交付桥通过继承的私有 FD 报告就绪，审计文件不再承担启动控制。仍有应用使用的旧版本桥不会被自动替换，须等待其租约自然结束。无需迁移原有环境/应用/根/项目的登记格式。

`unifier app leases` 显示应用、项目租约与文件交付桥已记录的 `worker_version`，`unifier project session show` 显示执行该会话的 worker 版本。字段由运行中的 worker 写入。旧记录缺少该字段时显示 `null`，读取时不改写记录或更换进程。

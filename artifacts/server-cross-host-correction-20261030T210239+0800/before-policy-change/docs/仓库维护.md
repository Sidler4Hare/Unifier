# 仓库维护

当前最低运行版本是 Python 3.11，使用标准库 `tomllib`。从仓库根目录运行以下命令。

## 固定检查入口

```bash
python3 tools/check_repo.py --quick
python3 tools/check_repo.py
python3 tools/check_repo.py --staged
```

快速检查包括现行 Python 源码语法、全部旧包名转发，以及五个 CLI 入口。完整检查再运行离线 unittest。检查会固定英文 locale、关闭真实容器集成测试，并为 CLI 使用临时安装根。语法检查使用当前解释器，不代表已经完成最低版本或其他宿主的运行验收。

Git 空白检查继续约束现行文件。`.gitattributes` 对冻结的 `archive/evidence` 关闭空白报错，保留正常 diff；归档补丁的空白上下文行属于原始内容，不为格式检查改写它们。

`--staged` 从 Git 索引导出独立目录后执行同样的检查，不借用工作树里未跟踪或未暂存的文件。整理包名、抽出模块和新增入口后，提交前运行这个命令，避免工作树通过而提交内容缺模块。工具不自动暂存或提交。

需要真实 Podman/FUSE/GUI 的验收仍按对应计划单独执行，四项默认跳过的集成测试不计为通过。

## 归档探针复跑

```bash
python3 tools/run_archived_probe.py \
  evidence/code-quality-2026-10-30/projection_rename_probe.py
```

入口同时接受 `archive/evidence/<轮次>/<脚本>.py`。它在临时工作区复制当前 `src/tests/tools/config/fixtures/bin` 与选定轮次的证据，恢复旧的 `evidence/<轮次>` 层级。脚本及同轮次依赖的原字节保持不变，运行时安装根也位于该工作区。默认结束后清理工作区，只保留输出和原退出码。

需要检查生成文件时，先用 `--workspace /绝对路径/新目录` 指定仓库外尚不存在的目录，它会被保留。需要其他轮次的脚本或数据时，在脚本参数前重复指定 `--include-run <轮次目录名>`；脚本自身的参数写在脚本路径后，可用 `--` 分隔。

这个入口解决归档层级变化。它运行的是当前源码，独立工作区的路径和环境身份不同于原安装；旧脚本的历史 API、旧容器身份、已压缩数据和宿主条件仍需逐项确认。它不是容器或 GUI 操作的沙箱，也不会把归档成功结论直接沿用到当前代码。临时工作区里的产物不能当作原证据被更新。

# 发行版派系白名单与容器关系

日期：2026-10-28。策略版本：1。首版配置为 `compatibility.mode = "whitelist"`。

## 1. 分组依据与范围

按原生包管理、依赖与系统目录布局、更新和部署机制划分派系。派系表示可以复用宿主集成策略，原始发行版 ID、版本、软件源和环境身份始终保留。Ubuntu 宿主与 Debian 宿主共用 Debian 系适配；这不授予 Ubuntu 包在 Debian 13 中的安装资格。

这是项目的**机制白名单**，不是已完成的跨宿主兼容认证，也不承诺所有历史版本、内核、桌面和硬件可用。旧系统缺少适用的 Podman、cgroup 或桌面接口时，依然需要修复对应能力。宿主包管理器字段描述所属机制；产品不据此执行宿主安装或升级命令。

唯一权威清单是 [`src/unifier/compatibility.py`](../src/unifier/compatibility.py) 的 `FAMILIES`；CLI 直接展示这份清单，避免文档和实现各自放行。新增发行版需显式加入 ID、说明机制和增加正反例，不能仅填写 `ID_LIKE`。

| 派系 | 首版显式宿主 ID | 基本操作依据 | 边界 |
| --- | --- | --- | --- |
| Debian / Ubuntu | `debian`、`ubuntu`、`linuxmint`、`pop`、`elementary`、`zorin` | APT/dpkg、DEB、glibc/FHS | 原 ID/版本/源保留；Mint 的 Ubuntu/LMDE 基底均属此组；桌面和安全策略独立检查 |
| Fedora | `fedora` | DNF/RPM、glibc/FHS | 传统可变系统；Atomic/CoreOS/IoT 不按此组放行 |
| RHEL | `rhel`、`centos`、`rocky`、`almalinux` | 当前 DNF/RPM 系统的宿主集成策略 | 与 Fedora 分开；不能混源，不能把历史 yum 系统视作已通过 DNF 验收 |
| Arch | `arch`、`endeavouros`、`manjaro` | pacman/libalpm、glibc/FHS、系统整体更新 | Manjaro 保留自己的仓库；派系不意味着与 Arch 仓库互换 |
| SUSE | `opensuse-leap`、`opensuse-tumbleweed`、`sles`、`sled` | Zypper/libzypp、RPM、glibc/FHS | Leap/Tumbleweed 的更新规则仍不同；MicroOS/Aeon/事务式部署需另适配 |

同为 RPM 不足以合并 Fedora、RHEL、SUSE。派系也不合并同名应用实例、项目授权、用户命名空间或桌面会话。

## 2. 首版宿主—容器矩阵

宿主侧有五组候选；**已实现的客体目标仍只有 Debian 13、Fedora 44、Arch**，继续使用既有 digest 锁、严格客体 ID/版本验证及原生包驱动。

| 宿主派系 | Debian 13 容器 | Fedora 44 容器 | Arch 容器 |
| --- | --- | --- | --- |
| Debian / Ubuntu | 同派系 | 跨派系 | 跨派系 |
| Fedora | 跨派系 | 同派系 | 跨派系 |
| RHEL | 跨派系 | 跨派系 | 跨派系 |
| Arch | 跨派系 | 跨派系 | 同派系 |
| SUSE | 跨派系 | 跨派系 | 跨派系 |

“同派系”再区分：宿主原始 ID 与客体 ID 相同，报告 `same-distribution`；例如 Ubuntu → Debian 13、Manjaro → Arch，报告 `same-family`；其他组合为 `cross-family`。`same-distribution` 不声称版本或 ABI 相同。

矩阵中所有候选都通过同一 rootless Podman 后端运行显式请求的容器。共同规则：

- 宿主管授权、默认应用、共享数据、设备和生命周期；共享宿主内核。
- 显式容器操作始终在指定容器内执行。派系不把容器命令静默转成宿主命令，也不接管全局宿主终端。
- 各环境保留自己的 `/usr`、`/lib*`、`/etc`、`/var`、软件源、包数据库和可变依赖。普通共享项目继续直接 bind；私有文件投影保持现有受限实现。
- 包格式只能选客体候选；签名、架构、依赖和版本仍交给目标原生包管理器验证。同为 DEB/RPM 不授予安装许可。
- 同派系不自动复用同一个容器。只有已有的 UUID/代际/CID、目标、版本、挂载和授权契约全部匹配时，多个应用/会话才能按现有租约共享一个环境。
- Ubuntu、RHEL、SUSE 等新增客体仍需独立镜像、身份验证和包驱动适配；宿主白名单不绕过 `resolve_target_contract()` 的三目标限制。

## 3. 明确拒绝的范围

| 分类 | 当前处理 |
| --- | --- |
| Fedora Atomic、Silverblue、Kinoite、CoreOS、IoT、OSTree/bootc 部署 | 保留基础派系并标出独立部署 profile，拒绝按传统 Fedora 放行 |
| SUSE MicroOS/Aeon/Kalpa、事务式更新宿主 | 独立适配，拒绝按可变 SUSE 放行 |
| Alpine | 已识别，musl 集成暂不准入 |
| NixOS | 已识别，Nix store/代际切换暂不准入 |
| Void | 已识别，XBPS/runit/glibc-musl 变体暂不准入 |
| Gentoo | 已识别，Portage/源码构建/profile/init 组合暂不准入 |
| 其他 ID，包括只声称 `ID_LIKE=debian` 的未知衍生版 | 不自动继承白名单；报告原 ID 与拒绝原因 |
| 非 Linux、非 x86_64、没有观察到 glibc | 不进入初版运行路径 |

Atomic 检查同时参考 `VARIANT_ID`、`/run/ostree-booted` 和事务式更新工具标记，避免仅看 `ID=fedora`。这些是首版已知排除规则，不能声称能够鉴别所有未来定制镜像；新部署机制仍需单独审查。

## 4. 接入位置和命令

```bash
python3 tools/unifier.py compat list
python3 tools/unifier.py compat check --target debian13
python3 tools/unifier.py compat matrix
python3 tools/lab.py doctor
```

`compat list` 显示精确 ID、派系、候选宿主及已实现客体。`check/matrix` 只读当前宿主，不创建服务、启动容器或要求镜像锁存在；策略拒绝返回 1。`--os-release /path/to/os-release` 可回放发行版资料，输出明确标记 `release-file-simulation`，机器架构、libc 和部署标记仍取当前机器，不能当另一宿主的实测。

`doctor` 增加宿主白名单检查及三目标关系，继续独立检查 rootless Podman、cgroup v2、工具和镜像锁。关系结果固定标记 `validation_scope=policy-only`，所列运行要求不能被 `allowed=true` 替代。

`EnvironmentService` 的创建、启动、直接命令、原生包查询和包事务都检查当前宿主。启动在生命周期锁和停止等待后重查；即使容器已经运行，包查询和执行也不能绕过准入。应用/文件路由绑定预检与项目会话环境预检也检查白名单，在 supervisor/portal bridge 创建之前拒绝。既有 UUID/代际/CID 和 app instance 验证继续生效。

新环境保存 `compatibility_at_creation`，只作来源快照；运行时不信任该快照，重新计算当前策略。旧记录无需迁移即可按当前宿主检查。`env inspect/list/plan` 显示当前关系；准入失效时计划返回 `refused`，查看、停止与删除仍保留，以便恢复和清理。

本轮只修改工作区源码/配置/说明；没有把新代码同步进两个日常部署副本，也没有变更默认应用、安装宿主包、提交或推送。

## 5. 本轮验证

- 新增 20 项离线契约测试，覆盖全部显式 ID × 三目标的策略组合、Ubuntu/Debian 同派系、RPM 派系区分、未知 ID_LIKE、Atomic 标记、错架构/libc、新客体拒绝、容器身份不放宽、当前宿主重查、旧记录兼容、应用/项目会话预检和 CLI 非零拒绝。
- 全量回归和本机预检结果见[验证报告](../evidence/distro-whitelist-2026-10-28/report.md)。
- 真实 Fedora 44 宿主复用三个缓存镜像，在独立临时 registry 中逐个创建/启动/执行/原生包查询/停止/删除；退出码 17 和共享内核检查通过，三目标均通过。附加未知宿主输入回放在实际运行容器上拒绝命令，仍只属于模拟策略输入。
- 原有 FreeCAD、腾讯会议的 CID、状态及 StartedAt/FinishedAt 前后相同，临时容器清理，无新下载。原工作区已有改动保留；本轮待修改文件先按 SHA-256 备份。
- Ubuntu、Mint、RHEL、SUSE 等真实宿主尚未跑；桌面、设备、SELinux/AppArmor、GUI/媒体和既有文件投影开放关口没有因该白名单变成已验收。

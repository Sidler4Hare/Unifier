# 包数据库写入中断恢复

依次使用 Ubuntu 原 Fedora 44、本机原 Debian 13、Ubuntu 原 Arch 测试实例。沿用上一轮完整 CID、原管理根、镜像和测试保护器，每次最多 180 秒。汇总 1 GiB/128 MiB swap/256 tasks/1 CPU，外部监督 64 MiB/16 tasks；原客体限额 384 MiB、768 MiB、384 MiB。宿主保留 1 GiB、连续 15 秒准入。新增容器 0，无 GUI、日常应用或宿主包变更。试验使用原有签名策略和已校验的小夹具，最多一个活动客体。

先记录实库、原登记清单及同伴状态，捕获真实原生写操作成功返回后且事务仍未返回的检查点，保持原生进程短暂等待。向核验身份的本轮 Unifier 进程发送一次 SIGINT，由产品取消客体进程树。记录原生写后状态、原生审计、锁、正式恢复、登记与停止态读取一致性。额外写入预算 1 GiB、下载 0、每命令日志 20 MiB。若正式恢复审计要求人为修复或锁遗留，保留屏障和现场，先停止该目标，禁止删除原生锁和数据库。

用户已批准按上述顺序各做一次。观测模块仅加载到本轮原生命令及其子进程，保存成功返回的写调用和写出位置，最长等待 10 秒；不修改原生库、数据库文件、锁或签名策略。Fedora 首个 SQLite WAL 页写之后检查，Debian 在正式安装状态日志改名成功后检查，Arch 在关闭本轮包 desc 文件成功时检查。正式信号只发给 PID/starttime/cgroup 复核后的本轮 Unifier 控制进程。

Fedora 首次写入命中后正式恢复误报 no-recovery-needed，停止态仍有 4152 字节 WAL。仅在无原生进程、原锁/绑定和 RPM 读库审计通过的条件下先备份标准 SQLite 主库、WAL、SHM（每个最多 32 MiB），核对摘要，借既有库上的原生 rpmdb --initdb 走正常读写打开和关闭以 checkpoint，前后对照清单。操作保留 WAL 原件的备份，不手工删除日志或重建数据库。若原生操作或后验失败，停止后续实机。

Debian 写入检查命中 dpkg 的 installed 状态日志。正式入口同样未处理编号 updates 文件。先备份并逐个确认日志属于唯一测试包，确认全库审计正常，原生 dpkg 空输入 --set-selections 使用正常读写数据库关闭路径同步日志，不提交选包记录。恢复后核对三方清单并正式移除夹具。

已批准精确恢复 Arch 原实例。只读审计锁、原生清单与日志，保留完整 overlay 可写层和 OCI userdata 的独立比较副本；备份总额低于 640 MiB，使用原存储用户命名空间保全所有者、硬链接、设备、ACL 和 xattr。原实例在备份阶段保持停止。只隔离已核验 inode 的 db.lck 和本轮不完整夹具记录/载荷（保留原件），使用同一验签包原生重装，保留原生系统 hooks 并追加唯一测试包专用的载荷验收 hook。核对 pacman -Dk/-Qkk、日志和同伴状态，最后走正式维护回执入口。

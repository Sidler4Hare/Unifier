# FIL-PORTAL-01 候选包实机验收

用户明确授权新增 1 个隔离 Debian 13 测试容器、真实应用选择/读取/撤销并复读拒绝。范围参见上级 gui-fixture-plan.md。镜像固定为本机已存在的 guarded Debian 镜像，保持原日用版本和原实例。执行目录和日志仅本轮所有。

创建阶段只创建停止态实例和专用管理记录，512 MiB、96 tasks、1 CPU、swap 0，独立 64 MiB/16 tasks，限 90 秒。使用现有离线保护器的监测核心，通过仅本次、仅该创建脚本的适配器设置明确作用域，不通过原 T1 启动容器。持久记录创建请求及完整 CID，复试不会再创建。只复制现有测试清单作为已知镜像基线，首次受保护启动后从真实 dpkg 查询及 Zenity 版本确认。

运行阶段复用现行固定实例保护器，汇总 1 GiB/256 tasks/1 CPU，客体 768 MiB/192 tasks，监督器 64 MiB/16 tasks，最多 180 秒。主机与客体分别使用私有 Xvfb，外部网络、设备、账号、宿主 IPC 禁用。仅桥接目录挂载至 /run/multilinux-portal；为使 SELinux 允许这一专用 IPC，使用产品桌面测试实例的 label=disable，宿主 SELinux 保持原状态。私有源文件及账本不挂载。使用候选包默认代理与桥接，真实 xdg-desktop-portal-gtk 后端和真实 Zenity。由于合成文件没有私人内容，留存小尺寸窗口截图与脱敏路径证据。

单次有效路径达到授予、应用读取、应用存活时撤销、重新 open 返回 ENOENT、正常退出及自动停止；维护完整 CID 并保留停止态实例。失败时按固定保护器收尾，只有确证驱动层问题且保全现场后才在同一 CID 上发起新尝试。产品代码、候选包、Git 索引、用户桌面和既有实例不作为测试写入对象。

创建动作完成，初次装置登记因目标目录层级键误读退出。已核验新 CID 仍为 created、PID 0，原保护器正常收尾，未启动任何实例。改用仅检查同一完整 CID、补齐记录的独立受保护步骤。

第一轮实机预检发现 Xvfb 仅存在于先前测试容器的可写层，本地镜像并未带入该包。该轮在显示和应用启动前结束，保护器未触发，新 CID 已停止、无租约。第二轮由宿主私有 Xvfb 提供显示，客体用已有 Python 在现有测试桥目录上转发 Unix 字节流。每侧最多 12 个连接，单方向缓存 64 KiB，无 TCP。候选文件桥继续按原样工作。不向客体安装包、不连用户桌面、不新增容器。

第二轮已验证私有 xdg-desktop-portal 和候选桥可以启动。实测 crun 因继承私有桌面 D-Bus 无法建立 systemd cgroup，未启动应用。记录保留，实例停止、租约与桥清零。第三轮只为经监督器核验的 Podman 子进程提供用户 systemd 控制总线，真实 Portal 和 GUI 进程仍严格使用私有总线。原守护和 cgroup 复核照常运行。

第三轮候选桥收到真实 Zenity OpenFile。驱动在任何输入动作前拒绝了随机 TMPDIR 路径中的下划线。第四轮只修正私有显示驱动对 ASCII 大写和下划线的按键编码，并清点前轮已证实死亡的显示转发端点。复用同一容器、应用记录及候选归档。

第四轮在实际选文件前，客体 GTK 报无法打开私有显示。前轮中断可能留下容器自身的 X11 socket 路径。第五轮在同一 CID 上仅认领本轮专用 X69 路径，若连接被明确拒绝才清理，校验新转发实际存活，并令转发收到 TERM 时正常删除自有路径。未遇内存、任务或 PSI 保护中止。

第五轮完成选择、真实读取、撤销、同 UID 重开 ENOENT 与正常退出。检查截图发现隔离的 X11 转发无法使用 Mesa 的共享内存绘制，捕获结果全黑。第六轮将 Zenity 的 GTK4 渲染切换至 Cairo 软件后端，再核对截图及相同验收条件。维持私有 IPC、同一受保护 CID、同一包。第五轮完整证据保留。

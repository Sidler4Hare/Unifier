日期：2026-10-30，Asia/Shanghai。当前工作区、两份日常部署及新版源码包的本机验证完成。没有提交或推送；本轮相关修复已暂存，其他工作区改动保留。

## 修复后的行为

- 宿主与客体同发行版或同派系时，镜像准备、创建、启动、命令执行、包操作和运行态目录浏览均拒绝，包括 Ubuntu → Debian。拒绝不会静默改用宿主执行。
- `unifier ls` 访问运行中环境前补上宿主关系检查；共享捕获执行入口 `_exec_record()` 也复查当前策略。停止环境仍可通过只读视图恢复文件，查看/停止/精确删除入口保留。
- 服务层限制同一安装根、每个 target 一个环境。`env create --id` 改名也不能重复创建；历史记录、缺失容器的保留记录和已停用的承接引用仍保留 target。创建锁跨进程覆盖检查、容器验证和持久登记；等锁后重新检查宿主政策。失败创建清理后可重试。
- `compat check` 继续对具体拒绝目标返回 1；`compat matrix` 有任一准入的跨派系目标返回 0，全部拒绝返回 1。
- 状态输出单列 `blocked`、行内 `policy_blocked` 及当前关系。被策略阻止的保留环境不再计入有效 enabled，也不误报为应通过 init 重装的安装失败；原 selected 和用户数据不改。

唯一性范围是安装根；独立实验根分别管理自己的环境。不封禁用户自行创建 Docker/Podman 容器。已有重复对象和旧同系对象不自动删除、合并或强停。

## 日常部署与保全

FreeCAD 和腾讯会议部署各只回填四个文件：旧命名空间下的 `compatibility.py`、`service.py`、`cli.py` 和 `tools/lab.py`。保留原目录结构、配置、镜像锁、桌面入口、应用注册、UUID、代际、CID 和数据。未把其他投影/文件操作改动整体同步进日常部署。

每份候选补丁先在独立部署副本进行语法与无运行时副作用的准入检查，全部通过后才原子替换现场文件；部署元数据记录新文件哈希、备份与范围。预部署脚本的重复装饰器问题在临时副本被拦下，修正后通过，未将失败候选写入现场。最终部署摘要见 `deployment.json`，两份现场策略复验见 `freecad-deployed-policy.json`、`wemeet-deployed-policy.json`。

两款日常应用用各自部署代码通过原绑定的只读启动预检。没有启动 GUI，也不把这项检查写成实际窗口验收。

保全核验：35 个配置、状态、安装选择及桌面入口文件与修前 SHA-256 一致；两个日常容器的 CID、完整 State、挂载、StartedAt、FinishedAt 均未变化。临时测试容器全部清理，最终仍只有原来的两个停止容器。细项见 `preservation.json`。

# Unifier 本机测试规范

状态：2026-11-03 制定，2026-11-04 纳入 [全项目测试禁令与规范](测试禁令与规范.md)。本页保留本机测量和功能验收细则，安全准入、进程控制、容器冻结与例外以全项目规范为准。实际完成范围以每轮证据目录为准；本文件不把计划项目标记成通过。

## 1. 适用范围与原则

适用于本机 CLI、包管理、共享文件、GUI 生命周期、资源对照和音视频验收。正式产品的资源策略与测试预算分别管理。

- 普通应用容器不因为本规范而默认增加 CPU/RAM 硬配额。无限额配置本身不能证明性能缺陷。
- 本机有且仅有一个活动测试负载；模型调用、安装/解包、编译、压力任务、GUI 测试分阶段串行执行。
- 不操作用户活动桌面的输入、窗口、合成器、会话或区域设置。GUI 自动化使用独立显示和独立配置。
- 不关闭用户应用来获取资源；余量不足就停止或不启动。停止不是性能通过，失败样本不得重命名成通过。
- 不运行全局 prune，不删除日常容器、用户配置、未提交修改或历史证据。不得为了测试退出登录或重启桌面。

## 2. 每轮启动前必须记录

| 项目 | 必须记录的内容 |
|---|---|
| 身份 | 时间/时区、boot ID、KWin PID、测试根目录、源码 HEAD 与脏文件列表 |
| 容器 | 完整 CID、名称、用途、镜像 digest、挂载、网络/IPC/PID 模式、现有资源配置、起始状态 |
| 宿主 | MemAvailable、swap/zram、memory PSI、已有测试进程和后台负载 |
| 应用 | 包来源、包/二进制哈希、版本、依赖库、组件模式、渲染方式、字体、配置、账号状态 |
| 工作负载 | 输入文档哈希、大小、动作序列、正确结果、轮数、最长运行时间、停止/回滚方式 |

拒绝同时启动第二个本机测试容器。优先复用与日常数据无关、没有宿主桌面挂载的旧测试环境。原生应用使用独立 HOME/XDG/TMPDIR；清除活动桌面的 Wayland、DBus 和会话管理变量。仅设置 DISPLAY 并不能证明没有访问宿主会话。

## 3. 本机资源保护

以下是这台约 7.4 GiB RAM 机器的起始规则，修改规则需要先说明证据和原因，不能为跑完一组数据自动降低保留线。

| 阶段 | 启动条件/上限 |
|---|---|
| 小工具准备 | 单任务；工具进程设置 128–512 MiB 预算、任务数和最长时间；只下载/私有解包，不修改宿主系统安装 |
| 单组件 GUI | MemAvailable 至少 2 GiB 宿主保留量 + 预估峰值 + 安全余量；没有峰值时先做小样本，本轮初始门槛约 2.83 GiB |
| 三组件同时运行 | 根据单组件峰值重新计算；必须能保留 2 GiB 宿主余量；不得仅凭“启动前有空闲”判定可运行 |
| 长时/压力 | 先在专用机或远端验证；本机需单独列出预算和目的，不自动延长短测 |

独立保护进程至少每 250 ms 检查宿主资源；连续两次 MemAvailable < 2 GiB 即停止本轮。memory PSI full avg10 > 3% 或 some avg10 > 10% 持续 2 秒，也停止。保护进程不依赖被测应用响应，设置总运行期限；控制器异常或失联也须有清理路径。

GUI 启动前还应有至少 30 秒的低压力窗口（full avg10 < 0.5%、some avg10 < 2%）；刚触发保护时不得立即重新尝试。MemAvailable 较高时仍可能发生回收/分配停顿，不能只看“空闲内存”。

保护应覆盖解包/字体缓存/辅助进程，不能只覆盖最后的 GUI 主进程。大包优先单线程、限内存、流式处理；避免同时保留压缩包副本和高并发解压缓冲。

必须核对实际 cgroup 路径。限制 Podman/控制器的 systemd 单元，不代表单独 scope 内的容器进程已被同一预算覆盖；复用容器的完整进程树必须已有可验证硬预算，并纳入本轮汇总约束和独立宿主保护。无法证明覆盖就阻断实机负载，不能只披露缺口后继续；不得为满足条件自动修改旧容器或产品配额。

测试必须使用覆盖整体作业的紧急硬预算，防止监测响应间隔内的失控增长；预算属于测试装置。性能比较采用可比的保护条件并证明本轮没有触发预算，不能据此报告无配额的极限吞吐；无法安全提供可比条件就延期。记录 cpu.stat 节流、memory.events/high/max/OOM、pids.events 和预算中止；这些保护事件使相应性能样本失效，不能直接判为产品缺陷。

停止顺序：停止应用负载 → 停止本轮独立显示/转发 → 按完整 CID 核对后停止测试容器 → 记录 boot/KWin 身份与资源 → 保留停止回执。只停止本轮明确登记的单元和 CID。需要继续时建立新尝试，保留先前失败和停止锁的审查记录。

## 4. 原生与容器的资源对照

### 配对条件

- 先做“实际安装版本”的描述性比较；版本不同就不能把差异归因于容器。
- 再用相同上游版本和相同核心二进制哈希做控制对照。允许私有解包/只在测试进程挂载命名空间内覆盖安装路径，不替换用户日常安装。
- 文档、字体、配置、独立/融合模式、账号状态、插件、窗口尺寸、显示协议、渲染后端、网络条件和预热方法一致。
- 分开测 Writer、Sheets、Slides；三组件同开单独列一项，不能用三项单开占用相加代替同开占用。
- 两侧先确认相同组件实际存活。辅助进程崩溃、插件加载不同、登录态不同都要披露；不得仅比较两个不同进程集合的合计并称为容器税。
- 独立 Xvfb/软件渲染结果只代表该条件，不外推为宿主 Wayland/GPU 帧率、功耗或音视频性能。

### 阶段与轮次

1. 容器停止态、启动后的无应用空闲态，分别采样；记录辅助进程。
2. 打开固定文档，确认窗口和内容，等待预定稳定时间。
3. 稳定空闲期每秒采样，保留逐点原始数据。
4. 执行固定编辑/保存动作；校验文档内容、公式、页/幻灯片结构和输出哈希/语义。
5. 正常关闭、重新打开核对，最后测关闭后的残留进程与资源。
6. 退出本轮测试并恢复停止状态。

小样本用于判断可行性和资源量级，必须标为 pilot。正式短命令至少 30 个有效样本；较长任务至少 7 对有效重复，使用交替/随机顺序，记录预热与缓存条件。宿主不执行全局 drop_caches。异常/预算中止单独计数并解释，不能静默剔除。样本不足时不报告可靠 p95、泄漏结论或普遍性能提升。

### 指标口径

| 指标 | 口径与限制 |
|---|---|
| 应用内存 | 所有应用主进程、CEF、云/插件辅助进程的 PSS；SwapPss 单列；权限错误必须显式 UNKNOWN |
| 框架开销 | PID1、conmon、网络助手、控制器、投影/代理等单列，不归入 WPS 进程 PSS |
| cgroup | memory.current/peak/stat/events/swap、pids.current/peak/events、cpu.stat、memory.pressure；记录基线及差值 |
| 缓存 | 区分 anon/file/shmem；包解压的页缓存和历史峰值不等于当前应用工作集 |
| CPU | CPU 秒、固定阶段墙钟时长、稳定期一个逻辑核百分比；100% = 占满一个核；记录节流 |
| 宿主影响 | MemAvailable 最小值、PSI、swap/zram、主要故障、同时运行的非测试负载；共享服务另计 |

PSS 不与 memory.current 相加。RSS 多进程简单求和会重复计算共享库。SwapPss 是逻辑换出量，不等于压缩 swap 的物理内存。Btrfs reflink 节约磁盘不代表文件映射自动共享 RAM。容器通常共享内核，不重复计算一套“客体内核内存”。

## 5. 功能验收与资源验收分别出结论

| 类别 | 最低验收动作 |
|---|---|
| CLI | 参数/退出码/stdout/stderr/超时与进程树清理，含真实错误路径 |
| 包管理 | 安装、实际运行、卸载、打断与恢复；核对实际清单和恢复状态，不只看命令返回 |
| GUI 文档 | 打开→编辑→保存→正常关闭→重开核对；中文和带空格/符号路径；GUI 截图与文件内容证据并存 |
| 文件共享 | 源/目标身份、写回一致性、冲突与失败保留；不得覆盖原始对照文件 |
| 会议 | 不同账号优先；双方真实确认双向音频、连续视频、共享、摄像头；同账号风控导致中止应标 UNKNOWN/BLOCKED |
| 长时 | 固定事务/循环、正确性 oracle、资源趋势、停止原因；短期增长不得直接叫泄漏 |

截图只用于验证所显示内容，不能证明保存成功。XML/哈希通过也不证明显示排版正常。测试通过、部署完成和用户真实工作流验收分别记录。

## 6. 容器保留与收尾

- 每个测试容器登记 owner/任务、用途、创建时间、关联证据、最后使用时间、是否含账号/用户数据、可复用条件和清理候选状态。
- 每轮结束默认停止。额外发行版容器用于特定兼容性矩阵，不因不同应用无限增加同发行版的常驻环境。
- 默认新增项目容器预算为 0；禁止因“重新测试”另建环境或另开管理根。确需新增，先交付复用失败证据、精确数量、用途、预算及保留/恢复方案，获得本次明确授权后才创建。
- 停止容器不运行应用进程，但镜像/可写层仍占磁盘，保留列表应说明原因；不能把磁盘层大小当作常驻内存。
- 测试容器退出保留周期后提出精确 CID 清单、数据/证据备份和恢复路径，经用户授权再清理。日常 FreeCAD/会议环境不属于测试清理对象。
- 最终回执：本轮容器数变化、所有测试进程/单元是否退出、容器是否停止、宿主安装/日常数据是否变化、残留临时文件位置、未完成项目。

## 7. 结果模板

每轮报告至少包含：问题与比较对象；输入/环境指纹；逐阶段动作；有效/无效样本数；正确性结果；资源原始数据位置与统计；保护触发与异常；宿主影响；可归因结论、不能归因的差异、未完成边界；清理和恢复状态。

结论等级固定为：PASS（定义内通过）、FAIL（可复现失败）、PARTIAL（仅完成部分边界）、NOT_RUN、UNKNOWN/BLOCKED（信息/条件不足）。不得把 UNKNOWN 改写成理论上可行。

# 共享内核多发行版子系统：性能验证方案

日期：2026-10-18，Asia/Shanghai。

当前实验目标固定为 Debian 13、Fedora 44、Arch 当前滚动版。环境准备工具、镜像锁和基础探针见 [第一版准备与实施](../设计/第一版准备与实施.md)。

本方案用于回答两个不同问题：兼容设施本身增加多少成本；不同发行版软件环境在本机提供怎样的实际体验。两类结果分别记录，避免将软件版本差异误算成设施损耗。

当前已完成主机基线、文件映射共享实验，以及 M4 首轮和一次复跑的状态、同二进制和更新峰值采集；M5 跨宿主矩阵尚未开始。机制与来源见 [调研分析](发行版差异与性能占用分析.md)。

## 1. 已执行的有界验证

### 1.1 主机基线

```bash
python3 tools/collect_host_baseline.py --output evidence/host-baseline-current.json
```

采集主机版本、CPU、内存、swap/zram、工作目录文件系统、cgroup、安全状态和少量工具版本。脚本不安装包、不拉取镜像、不启动容器，也不读取用户进程列表或凭据。

已有 [2026-10-18 基线快照](../../evidence/host-baseline-2026-10-18.json)。注意：桌面快照包含当时其他应用的活动，不能用于计算尚未运行的子系统开销。

### 1.2 同 inode、普通副本与 reflink 的内存共享

```bash
python3 tools/probe_file_sharing.py --output evidence/file-sharing-probe-current.json
```

需要 Linux `/proc`、GNU `cp`、`btrfs` 工具和支持 reflink 的工作目录。默认文件大小 8 MiB，每组两个短暂子进程，只读取实验子进程对应文件映射的 `/proc/PID/smaps`。临时文件在工作目录中创建并自动清理；不修改缓存、KSM、挂载和安全设置。每组内源文件与目标文件的 SHA-256 一致。

已有 [实验原始数据](../../evidence/file-sharing-probe-2026-10-18.json)，时间为 2026-10-18 09:51:59 +08:00：

| 条件 | 文件身份 | 数据区段关系 | 两个映射 RSS 合计 | 两个映射 PSS 合计 |
|---|---|---|---:|---:|
| hardlink | 同设备、同 inode | 同一文件 | 16 MiB | 8 MiB |
| 普通复制 | 不同 inode | 两份独立区段 | 16 MiB | 16 MiB |
| reflink | 不同 inode | FIEMAP 统计显示共享 8 MiB 区段 | 16 MiB | 16 MiB |

**该实验支持的结论：本机上的 reflink 磁盘区段共享没有合并这两个文件的映射页；同 inode 则能够共享这些页。** 三组映射均无匿名页或 swap。本轮没有测时延，也没有测进程总内存或容器内存；每组一次，结果不构成全部文件系统、存储后端或应用负载的性能结论。

`btrfs filesystem du` 的每个文件统计不可简单相加当成唯一物理空间：例如两个硬链接路径对应同一个 inode，却会分别列出该文件的区段。原始表保留供复查。统计字段说明见 [Btrfs filesystem du](https://btrfs.readthedocs.io/en/latest/btrfs-filesystem.html#subcommand)。

## 2. 后续固定的实验身份

每条结果都记录以下字段；缺失时应标记未知，不自动填默认值：

| 类别 | 必须记录 |
|---|---|
| 宿主 | 发行版版本、内核、架构、CPU、电源状态、内存、swap/zram、文件系统与挂载选项 |
| 安全与资源策略 | SELinux/AppArmor 状态、user namespace、cgroup 控制器、有效 CPU/内存限制 |
| 运行时 | Podman 等运行时版本、rootless/rootful、存储驱动、网络后端、是否完整 init |
| 环境 | 发行版及版本、镜像 digest、仓库或快照时间、安装后完整包清单与版本 |
| 工作负载 | 二进制/输入校验值、版本与构建选项、命令、线程数、数据目录和输出验证 |
| 生命周期 | 是否首次初始化、环境是否已运行、进程是否首次启动、缓存状态是否受控 |
| 指标 | 原始样本、单位、测量区间、采集方式、失败和不可读字段 |

不要使用未固定的 `latest` 标签作为可复现实验身份。滚动仓库需要记录一致的快照或实际包集合；固定版本也不等于可以长期跳过安全维护。

## 3. 第一条实验线：设施成本

使用相同二进制与输入，尽量只改变一个设施。CPU/系统调用探针可使用同一个静态构建；真实动态应用则必须携带匹配的依赖组合，不能为了凑出“相同程序”而混用不兼容库。

| 编号 | 执行方式 | 用来回答的问题 |
|---|---|---|
| A0 | 宿主直接执行 | 当前硬件和系统的对照 |
| A1 | 通过统一入口仍在宿主执行 | 入口解析和代理本身的成本 |
| A2 | 相同二进制处于 namespace / 明确挂载视图中 | 环境建立与视图变化的增量 |
| A3 | 最小普通应用环境，数据目录直接绑定 | 实际容器环境与管理进程的合计成本 |
| A4 | 同一环境，改变可写存储路径 | 内核 OverlayFS、其他后端与直接数据目录的差异 |
| A5 | 同一环境，启用内部 init 与必要服务 | 完整服务环境的常驻和启动增量 |
| A6 | 同一环境，改变网络后端 | host、用户态网络等路径的差异 |

A2 并不自动代表 A3：真实运行时还可能创建监控进程、设置资源策略并使用不同存储或网络路径。A4/A6 必须分别固定其他条件；不能一次改变权限、存储和网络后只归因于某一个组件。

这些编号是实验条件。A0 和 A3 已在 M4 的同二进制实验中形成首轮结果，统一入口叠加 A3 的结果也已记录；A1 只以统一入口与直接 `podman exec` 的差值近似，A2 没有单独拆分，A4–A6 仍没有实现或跑分结果。

## 4. 第二条实验线：实际发行版体验

在目标版本各自的原生环境中安装软件，不混改包数据库或执行不支持的部分升级。该实验线允许使用各发行版自己的库和构建，回答实际体验，不用于单独求 namespace 成本。

| 负载 | 选择标准 | 验收内容 |
|---|---|---|
| 短 CLI 命令 | 确定性输出、短生命周期 | 入口开销、错误码、信号、工作目录、输出一致性 |
| 长 CPU 任务 | 可控制线程数和输入 | 正确结果、吞吐、用户/内核 CPU 时间、温度和频率背景 |
| 开发负载 | 固定源码版本和构建参数 | 全量/增量构建、小文件 I/O、产物校验、缓存目录 |
| GUI 应用 | 能完成实际打开、编辑、保存流程 | 首次可交互、文档路径、窗口、字体、音频与剪贴板 |
| 语言扩展 | 实际依赖本地扩展 | 解释器与扩展加载、计算结果，防止误用宿主模块 |
| 图形/视频 | 能报告实际渲染或解码后端 | 硬件加速、帧时间、首帧、设备可访问性 |
| 后台服务 | 需要服务生命周期管理 | 启停、重启、端口、持久数据、退出后的回收 |
| 安装/升级 | 固定来源和包集合 | 下载与本地阶段、脚本状态、失败恢复、峰值内存和磁盘 |

首轮覆盖 Fedora 44 宿主上的 Debian 13、Fedora 44 独立环境及 Arch rolling 环境。应用清单由具体软件目标决定，不通过一次示例成功推断“任意 deb 可用”。Ubuntu 不进入首版实验范围。

## 5. CPU 与启动时间的采样规则

- 启动类区分首次准备、环境启动、已运行环境内启动、应用可交互四个阶段；GUI 可交互不能用命令返回时间替代。
- 短命令建议至少 30 个有效样本；长负载建议至少 7 次。均保留原始数据，先看噪声和离群原因，再决定是否需要增加样本。
- 交替或随机安排对照条件，记录电源、频率、温度及后台更新，避免顺序热机造成固定偏差。
- 报告样本数、p50、范围；样本足够时再报告 p95 和置信区间，不能让少量样本产生虚假的精度。
- 进程首次启动与冷文件缓存分别命名。当前交互桌面上不通过清空全局页缓存制造“冷启动”；受控冷缓存测试应安排到独立实验条件。
- 所有性能数字先要求工作负载结果正确；启动快但功能缺失的记录不能算性能胜出。

耗时类增量：`(测试耗时 / 对照耗时 - 1) × 100%`。吞吐类应另外说明方向，例如 `1 - 测试吞吐 / 对照吞吐`；不能沿用耗时公式后又把正负号混用。

## 6. 内存的五个状态

对单环境以及两个外来环境组合分别测量：

1. 仅保存在磁盘、环境进程未运行。
2. 启动并稳定空闲，普通应用环境。
3. 一个应用执行指定任务后保持打开。
4. 多个应用并发，必要时启用完整 init 或服务。
5. 退出应用并停止环境，观察哪些服务和驻留数据仍存在。

freeze/pause 单列为可选状态，不视为停止或内存释放。

为环境建立独立、互不嵌套的 cgroup，并在进程启动时归属，避免之后频繁迁移。读取权限不足或某控制器不可用时如实记录，不能用 0 填补缺失值。

| 指标 | 用途 | 解释边界 |
|---|---|---|
| `memory.current` / `memory.peak` | 环境整体资源与峰值 | 有文件缓存和内核计费；峰值应采用新测试组或有效重置 |
| `memory.stat` | anon、file、内核对象等结构 | 字段可能存在包含关系，不全量相加 |
| `memory.events` | high、max、oom 等事件 | 限额造成的退化应独立解释 |
| `/proc/PID/smaps_rollup` PSS | 进程工作集和共享页分摊 | 权限受限时标记缺失；不包括全部环境资源 |
| PSI、换页活动、应用延迟 | 交互压力 | 通过区间增量与对照判断，不能只看累计总数 |
| 宿主共享服务 | 归属在环境外的增量 | 显示、音频等服务应另列；不声称环境 cgroup 已覆盖全部成本 |

PSS 与 cgroup 内存不能相加为总量。多个环境共享文件页时，cgroup 归属与 PSS 分摊方式不同；对照解释需同时保留宿主侧观测。

小内存主机先测一个环境，再逐步增加并发。先找出稳态和峰值，再选择 `memory.high`、`memory.max` 等策略；不预先猜一个很小的硬限额后，将 OOM 误算成发行版不兼容。

## 7. 磁盘、I/O 与更新峰值

每个环境至少保留四个时点：导入后、首次初始化后、安装目标应用后、更新并保留回退点后。同时记录更新中的最高占用。

分开记录镜像压缩下载量、解压后的逻辑体积、运行时存储、下载缓存、应用数据、旧环境独占空间与元数据。以实际文件归属避免重复计数，尤其不要把已包含缓存的整个根目录再加一次缓存目录。

Btrfs 环境记录 FIEMAP 的共享区段信息及相应限制；普通 `du`、运行时的空间报告与整个文件系统增量可互相参照，但它们都不是无条件精确的“删除后可回收字节”。压缩、共享区段、元数据、后台写入和事务时点需要说明。

I/O 条件至少包含直接数据目录与环境可写层，使用相同输入与写入语义：

- 大文件顺序读写。
- 小文件创建、查找、删除和源码构建。
- 需要同步提交的写入任务。
- 首次修改 lower 文件与已经进入 upper 后的修改。

不在宿主正在使用的数据库或系统目录上施加测试写入。应用数据、环境系统状态和桌面导出入口的回退能力分别验收；根目录快照不能撤销已经发生的共享数据库迁移。

## 8. 本机优先验证的假设

| 优先级 | 假设 | 支持或否定它需要的证据 |
|---|---|---|
| P0 | 普通应用环境比完整服务环境更适合本机常驻预算 | A3/A5 空闲内存、服务树和前台体验 |
| P0 | 同环境复用依赖比默认每应用一份环境更节省资源 | 相同应用集合的逻辑/物理磁盘、PSS、更新量与冲突记录 |
| P1 | 频繁写入放到直接数据目录可减少存储层影响 | A4 的小文件、构建、同步写入及首次 copy-up 对照 |
| P1 | 短命令对统一入口更敏感 | A0/A1/A3 的启动样本以及批量执行对照 |
| P1 | 串行更新更适合当前内存余量 | 完成时间、峰值内存、PSI、前台响应与更新峰值空间 |
| 已取得局部证据 | reflink 节省磁盘不自动节省文件映射 RAM | 第 1.2 节单机实验；后续仍需实际镜像后端与应用验证 |

第一轮结束的标准是：给出明确配置下的功能结果、设施增量、环境空闲与活动资源、更新峰值及主要限制。没有跨宿主证据时，保持“三类宿主待验证”的状态。

## 9. M4 首轮有界结果

2026-10-21 09:32–09:45 +08:00，在 Fedora 44 宿主、load 1.5–2.8、内存 PSI some avg10 约为 0 的窗口，用锁定镜像完成了停止/空闲/活动、同二进制和更新峰值三类实验。状态采样显示三个环境的空闲 PSS 为 1.56–2.19 MiB，16 MiB 匿名页活动负载使 PSS 增加 16.02 MiB，退出后回落到空闲值；同二进制实验每个环境 111 个样本，长负载中探针 CPU 时间与宿主直跑基本一致，直接 `podman exec` 的墙钟约为宿主 2.1 倍，统一入口约为 9.9 倍；更新峰值为 Debian 134.1 MB、Fedora 164.8 MB、Arch 50.1 MB（Arch 的完整升级在安装阶段完成）。

这些数字来自一次串行运行，宿主不是专用性能机器；它们用于验证采集与功能，不作为发行版性能排名或最终基线。完整方法、表格和限制见 [第一版准备与实施 §13](../设计/第一版准备与实施.md#13-m4-资源验证结果)，原始数据见 [状态采样](../../evidence/m4-states-2026-10-21.json)、[同二进制](../../evidence/m4-same-binary-2026-10-21.json)、[更新峰值](../../evidence/m4-update-peak-2026-10-21.json)。

2026-10-21 10:10–10:20 用同一锁定镜像复跑了三组。活动 PSS 增量仍是 16.023 MiB；长负载进程 CPU 比仍约为 1，`podman exec` 墙钟约 2.1 倍，统一入口约 9.3–10.5 倍。状态窗口的 1 分钟负载低于 1.6，内存 PSI 为 0；同二进制进行时负载升到 3.9，内存 PSI `avg10` 短时到 0.74。governor 仍是 `powersave`，活动频率约 1.8–1.9 GHz，封装温度 51–67°C。更新阶段的 cgroup 寿命峰值都从约 1 MB 升起来：Debian 134.5 MB、Fedora 151.9 MB、Arch 48.8 MB。Arch 的 48.8 MB 是空同步读库，上午漏采了对应的 `memory.current` 短峰。细节见 [§13.6](../设计/第一版准备与实施.md#136-复跑)。

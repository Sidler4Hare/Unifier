# 跨应用保存原型

日期：2026-10-23，Asia/Shanghai。承接[文件层可行性评估](文件层可行性与性能评估-2026-10-23.md)第 8 节第 2 项：宿主项目交给 Arch 里的程序保存回原文件，并查看相邻文件、临时文件 rename、新建默认位置，以及另一进程改源文件时的结果。

结论：**在已经共享的宿主项目目录里，Arch FreeCAD 和同目录临时文件 rename 都会把结果写回原路径，属主仍是宿主 uid 1000。** 第二次保存会把上一版留成同目录备份，旁边的 STEP 不会跟着更新。没有文件名的保存不会落盘；相对路径和 `~` 跟随进程的工作目录和容器私有家目录。另一进程若先换成新文件，随后的 rename 会盖掉它；若只是向替换前打开的描述符写入，目录里的新文件保持不变。

这是保留环境 `ml-edae1d18-complex-arch` 上的一轮实测，不是新的 GUI 验收，也不是产品文件层验收。FreeCAD 1.1.4 revision 45040，容器用户 uid 1000，对应宿主 uid 1000。没有装包、没有 pull、没有改这只容器的挂载。样本只写在它原先共享目录下的 `work/cross-save-2026-10-23/`。该目录外原有的 7 个证据文件哈希不变。容器开始和结束都是停止状态。历史 Xauthority 路径已经丢失，本次为了能启动放了一个空文件，结束时删除。FreeCAD 使用 `freecadcmd` 和 offscreen Qt，没有打开桌面窗口。

文本部分没有调用 Mousepad 或 Kate。这只容器里没有这些程序。文本用例是容器内 Python 做的两种保存：同目录临时文件加 `fsync` 再 `rename`，以及截断同一文件描述符。FreeCAD 自己的保存由 inotify 记录。

## 1. 保存回宿主项目

共享目录里的文件由宿主创建，容器以 uid 1000 修改。宿主直接读回的属主是 uid 1000、gid 1000，SELinux 类型是 `container_file_t`。

| 保存 | 观察到的动作 | 结果 |
|---|---|---|
| 临时文件 rename | 创建 `笔记.txt.editor.tmp`，写完后 `moved_to` 原名 | inode 从 3052133 变为 3052167，内容是新文本 |
| 截断同一描述符 | 只有 `modify` 和 `close_write` | inode 保持 3052167 |
| FreeCAD 第一次 `saveAs` | 写入 `零件.FCStd.<uuid>`，再改名为 `零件.FCStd` | 文件在宿主项目路径 |
| FreeCAD 第二次 `save` | 先把现有 `零件.FCStd` 改名为 `零件.20261023-030530.FCBak`，再把新的 uuid 临时文件改名为 `零件.FCStd` | 新进程重新打开，边长 11，体积 6600 |

备份名里的 `030530` 用的是容器时钟。同一时刻宿主是 `2026-10-23T11:06:53+08:00`，容器是 `2026-10-23T03:06:53+00:00`。

模式 444 只挡住截断写入，错误是 `EACCES`。目录仍属于同一用户时，临时文件 rename 能换掉这个只读文件，新文件模式是 644。

## 2. 相邻文件

`旁注.txt` 在全部文本保存和两段交错写入之后哈希不变。

FreeCAD 在边长 10、体积 6000 时导出了 `零件.step`。随后只把模型保存为边长 11。STEP 没有再次写入。回读 STEP 体积仍是 6000，形状有效。`零件.20261023-030530.FCBak` 是第一次保存：边长 10，体积 6000。它留在项目目录中。

项目共享范围之外的 `outside-marker.txt`，容器按绝对路径检查为不存在。

## 3. 另一进程改源文件

两段都用标志文件排好顺序，不是碰时机的并发。

容器读入“容器读到的原文”并写好临时文件后，宿主先把目标换成另一个 inode。容器接着 `rename`。最终文本回到容器读到的旧内容，inode 从宿主写入的 3052249 变为 3052247。宿主那一版没有留下。

容器先打开描述符，宿主再换成新 inode，容器向旧描述符写入 40 字节并成功返回。路径上的文本仍是“宿主换了新 inode”，inode 仍是 3052547。写到旧描述符不会改变目录项现在指向的文件。

第一次描述符测试在写入前因 `lseek` 参数错误退出，结果文件不采用那一次。上面的数字来自修正后的重测。

## 4. 新建文件的默认位置

容器用户的 `HOME` 是 `/home/multilinux-1000`，不是宿主家目录。

| 操作 | 工作目录 | 结果 |
|---|---|---|
| 新文档直接 `save()` | `/` | `ValueError`，`FileName` 没有设置，没有产生文件 |
| `saveAs("相对零件.FCStd")` | `/` | `OSError: Failed to open file`。项目和容器根下都没有这个文件。文档对象的 `FileName` 仍被写成这个相对路径 |
| `saveAs("~/默认家目录.FCStd")` | `/` | 写到 `/home/multilinux-1000/默认家目录.FCStd`。宿主项目里没有同名文件。记录哈希后已从容器家目录删除 |
| `saveAs` 到项目绝对路径 | 项目目录 | 文件留在宿主项目里，见第 1 节 |

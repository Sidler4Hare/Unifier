# 投影对象与目录修复（Unifier 只读 live 投影）

日期：2026-10-26。范围：把已授权停止环境的只读 FUSE 投影，从“路径即身份、每次读取重新打开路径”改为“对象锚点 + 独立句柄 + 共享 MountGraph”。不改变 lease、storage broker、环境身份、视图撤销与只读边界。

旧实现完整保留为 `src/multilinux/fuse_view_legacy.py` 与 `src/multilinux/view_backend_legacy.py`。legacy worker 只导入 legacy backend，仍可用原参数启动：

```text
python3 -m multilinux.fuse_view_legacy --mountpoint ... --merged-fd ... --spec ...
```

当前入口 `python3 -m multilinux.fuse_view` 使用新实现。两者不共享节点表或句柄。

主控已完成本机受限验收：真实 FUSE 22/22、三套客体完整 broker 链路各 17/17、7 项补充反例，以及 399 项全量回归（395 通过、4 条件跳过）。源码冻结、失败历史、一次 EBUSY 清理重试及保全记录见[本轮验收报告](../../evidence/projection-objects-2026-10-26/report.md)。这不关闭 watcher、快照、性能或跨宿主关口。

## 1. live read-only 契约

本投影是**运行中可变数据的只读入口**，不是快照：

- `readonly=true`，所有可写 OPEN/写/创建/删除/改名/设置属性等返回 EROFS。
- `live=true`，`snapshot=false`。停止环境不会冻结 bind、volume 或 merged root 的其他写入者。
- `watcher=false`。没有后端 inotify 桥、事件队列或 FUSE 主动失效通知，不承诺任意宿主 IDE 的 watcher 完整收到 create/modify/rename。
- `cross_volume_consistent=false`。不同 mount provider 之间不提供跨卷时间点一致性。
- 不启用 `default_permissions`。guest UID/GID 是呈现元数据，实际可读性仍由宿主 worker 凭据决定；不能把数字 UID 直接当作宿主权限判断。
- xattr 契约明示为 `unsupported`；ACL 为 `unknown`，不能把“当前接口看不到 ACL”解释成源对象没有 ACL。
- 内核缓存：entry/attr TTL 均为 0；文件 OPEN 返回 `open_flags=0`，保留普通 page cache 以支持 mmap，不设置全局 `FOPEN_DIRECT_IO`。
- 内核若提供 `FUSE_AUTO_INVAL_DATA`，INIT 只协商该位；属性/数据刷新依赖内核在 mtime/size 等属性变化后的自动失效，而不是产品 watcher。
- 同一 inode 的原地写仍按底层文件系统语义可见；只固定对象身份，不冻结内容。

已验证的 live 行为：

- lookup 后、首次读取前替换同名文件：旧节点旧 handle 读旧对象；新 lookup 得到新节点。
- 已读一次后同大小或变大小替换：旧 handle 继续旧对象；新 lookup 看新对象。
- 原地写、截短、增长：旧 handle 的属性来自 `fstat(handle fd)`，数据来自 `pread(handle fd)`，看到的是同一对象的当前内容。
- mmap：handle 是真实 O_RDONLY fd，可 mmap；replace 后 mmap 仍映射旧 inode，不会被新路径重定向。原地写对同一映射按底层 page cache 语义可见。
- 局限：不提供历史版本、快照读、事件流；外部原地写和 mmap 的一致性由底层文件系统与内核决定。

## 2. 对象身份与锚点

节点 key 是：

```text
(provider instance, mount identity, st_dev, st_ino)
```

- `provider instance` 对 merged root、每个持久 mount 条目分别唯一；两个 provider 即使指向同一底层对象也不合并节点，避免权限域/挂载域被数字 ino 混淆。
- `mount identity` 使用打开时的 `mnt_id`，同一 provider instance 内配合 dev/ino 防止重新挂载误认。
- 同一 provider 内硬链接 dev/ino 相同，因此是同一 node，`st_ino`（投影空间中的 nodeid）也相同。
- 每个真实对象节点持有一个 `O_PATH | O_CLOEXEC | O_NOFOLLOW` anchor。旧对象被 replace/unlink 后 anchor 仍持有原 inode，既保证旧句柄语义，也防止 inode 复用被误认为同一节点。
- nodeid 从 1 起单调分配，root 固定为 1；FORGET 回收后编号不复用。
- 合成目录（缺失祖先、被文件占位的祖先）没有 anchor，使用独立 key，不伪装成底层对象。

lookup 每次都从**当前名称绑定**辨认新对象：从 pinned 父目录 anchor 执行 `openat(O_PATH|O_NOFOLLOW)`，再 `fstat` 形成 key。同一名称已替换时旧 anchor/节点不被改写；内核之后通过新 lookup 得到新 node。

## 3. 打开、读取与属性

- `OPEN` 只接受只读 flags；从节点的 pinned O_PATH anchor 通过 `/proc/self/fd/<anchor>` 的内核 magic link 打开一个新的 `O_RDONLY` fd。该过程不按路径重新解析，因此 lookup 与 open 之间替换路径不会把请求重定向到新对象。
- 每次 `OPEN` 都建立独立 handle 和独立底层 fd；同一节点多次打开互不共享 fd。
- `READ` 只对 handle fd 执行 `pread`，不 lookup、不 walk、不重新 open。
- `GETATTR` 只有当协议 `getattr_flags & FUSE_GETATTR_FH` 时才使用 fh；否则忽略 fh 字段并对节点 anchor 执行 `fstat`。带 fh 时对同一 handle fd 执行 `fstat`，不会把新对象属性配到旧对象数据上。真实节点的权限位来自当前 `fstat` 的 `st_mode`，不使用 lookup 时的权限快照；合成目录使用明确的 `S_IFDIR|0555`。
- `READLINK` 从 pinned symlink anchor 调用 `readlinkat("", dir_fd=anchor)`，不重新解析名称。
- 文件 mount 的节点 anchor 来自 mount source 的 pinned root fd；OPEN 同样从 anchor 打开。
- 失败回滚：node/handle/目录快照在预算不足、类型错误或 `fstat` 校验失败时关闭已打开的 fd，不保留半成品。

`default_permissions` 仍未启用。`ACCESS` 只做与投影只读边界一致的显式检查：写掩码返回 EROFS，R/X 位明显缺失返回 EACCES；它不是宿主权限判断的替代品。

## 4. 已打开对象与 provider 不健康

政策明确如下：

- **新名称解析**（LOOKUP、路径级 read/readdir/readlink、读取目录内容）会验证 provider source 身份。持久 mount source 被替换、消失或 mnt_id 变化时返回 EIO，不回退到 merged root 或其他 provider。
- **已 pin 对象**继续按自己的 anchor 工作：已经打开的 handle 的 READ/GETATTR(fh)，以及从已 pin 节点 anchor 进行的新 OPEN/READLINK，不因 source 路径后来变化而改读别的对象。
- 已 pin 的目录流是 OPENDIR 时的稳定快照，后续 source 路径变化不把它切到新目录。
- **新的** OPENDIR/目录快照会重新验证注入 provider 的身份；source 被替换时 fail closed（EIO），不会展示“看似有效”的新目录。已打开的旧快照按自己的条目继续，不中途切换。
- 不允许“mount 失效后退回底层 merged 文件”的路径 fallback；缺失 provider 的拓扑节点仍可显示，但访问其 provider 内容会失败。

## 5. MountGraph 与目录

lookup 与 readdir 共用一张 MountGraph：

- 最长 destination 前缀胜出；同深度 mount 覆盖 capability。
- 为每个 mount destination 合成必要祖先。祖先在 merged 中缺失或是文件时，也按目录呈现，否则嵌套 mount 不可达。
- readdir 列出的子项类型由 MountGraph 的覆盖结果决定，而不是底层同名占位对象：文件 mount 必须显示为 file，目录 mount 显示为 dir。
- 文件 mount 没有子项；对子路径返回 ENOTDIR，不偷偷穿透底层同名目录。
- capability 路径（默认 `/proc`、`/sys`、`/dev`、`/run`）在无更深 mount 覆盖时不可用：lookup 返回 ENOTSUP，readdir 不把它伪装成普通条目。更深 mount 可以覆盖 capability 子树，此时为到达该 mount 的祖先按必要目录注入。
- provider 失效时显示拓扑条目但不回退底层。

每个 `OPENDIR`：

- 从 pinned 目录对象打开真实 O_RDONLY|O_DIRECTORY fd；
- 用 `os.scandir(fd)` 增量扫描，合并底层条目与注入的 mount/祖先条目，形成该句柄的稳定列表；
- 每个非 `.`/`..` 条目都解析成对应投影 node，并持有该 node 的 internal ref，因此 dirent `ino` 与 `GETATTR` 的投影 `st_ino/nodeid` 一致；同一 provider 的硬链接条目共享 node，多个硬链接条目分别持有/释放 internal ref；
- cookie 基于该列表位置，分页期间删除/新增不会导致无关条目漏读或重读；
- `RELEASEDIR` 清空列表、释放所有条目 internal ref、回收 entry/byte 计数；失败路径按已持有列表逆序回滚；
- 目录条目数、字节数、handle 数均有**跨流聚合**预算，超限返回 ENOSPC/EMFILE；不驱逐仍活跃的目录流，释放旧流后容量恢复。

`FORGET`/`BATCH_FORGET` 不回复，但会减少 nlookup。节点只有在 `nlookup`、文件/目录 opens 和 internal refs 均为零时才关闭 anchor 并回收；root 固定保留。卸载/close 关闭全部 handle、目录流、节点 anchor 和本 backend 拥有的 mount provider root fd，可重复调用。

## 6. 预算与错误

默认预算在 `projection.py`：

```text
nodes        65536
handles       1024（文件句柄 + 目录句柄）
dir entries  65536
dir bytes        8 MiB
```

- 新节点预算耗尽：ENOSPC。
- 文件/目录 handle 预算耗尽：EMFILE。
- 目录快照条目或字节预算耗尽：ENOSPC。预算检查使用所有已打开目录流的聚合 `dir_entry_count`/`dir_bytes_used`，新快照还必须在扫描过程中尽早停止；已打开目录 fd、新建条目 node/internal ref 和计数全部回滚。
- 活跃 node/handle/dir 不因预算压力被驱逐；只能通过内核 FORGET/RELEASE 或关闭整个投影释放。
- **字节预算是账面记账，不是实际 RSS、slab 或内核内存上限。** 每个条目按名称长度加固定开销估算；node、anchor、Python 对象和内核 dentry 的真实内存另有开销。真实资源耗尽仍可能先以 EMFILE/ENFILE 等系统错误出现。
- 资源错误（EMFILE/ENFILE/ENOMEM 等）保留实际 errno，不转换成“provider 身份被替换”的 EIO。已打开的 handle 在 fd 耗尽期间继续用既有 fd 读取，释放后新 OPEN 恢复。

## 7. control status

`status` 在原有 worker 身份/初始化字段之外增加：

```text
consistency: {
  mode: "live-readonly", readonly, live, snapshot: false, watcher: false,
  cross_volume_consistent: false, entry_ttl: 0, attr_ttl: 0,
  direct_io: false, mmap: "page-cache",
  auto_inval_data, kernel_offered_auto_inval_data,
  xattr: "unsupported", acl: "unknown",
  permissions: "not-default_permissions"
}
counters: {
  nodes, node_budget, handles, file_handles, dir_handles, handle_budget,
  dir_entries, dir_entry_budget, dir_bytes, dir_bytes_budget,
  next_nodeid, next_handle
}
```

control thread 通过 backend/ProjectionObjects 的锁读取 counters；FUSE 请求循环与 control 状态读取不会直接共享无保护的节点/句柄字典。

## 8. 验证边界

本轮 unittest 使用临时目录、真实 backend、真实 FD 和 FUSE handler 调用，不创建真实 FUSE 挂载、不创建容器、不读取凭据。覆盖：

- replace/unlink 前后旧 handle、未读/已读、同大小/变大小、原地增长/截短、mmap；
- LOOKUP 子项使用 pinned dirfd、目录 rename/replacement 后不跳新路径；
- READLINK 使用 pinned symlink；
- 硬链接同 node/st_ino、跨 provider 独立、nodeid 不复用；
- nlookup/opens 引用、FORGET/BATCH_FORGET、RELEASEDIR；
- nodes/handles/dir entries 预算与失败回滚；
- 嵌套 mount、缺失/文件祖先、文件 mount、失效 provider、capability；
- 稳定目录 cookie 与每句柄快照；
- control status 一致性字段、counters、并发读取；
- legacy 入口与 legacy backend 绑定。

以上 unittest 是机制与协议层测试，不能替代真实内核挂载、GUI/IDE 或性能验收。主控独立 contract probe（聚合预算、dirent 身份、路径 API 回收、required ancestor 不跨 provider、失效 provider 新快照、失败路径回收、资源 errno）7/7 通过；另行执行的真实挂载与三客体 broker 验收见本轮报告。

最终全量 unittest（`MULTILINUX_INTEGRATION` 未设置）共 399 项，395 通过、4 项条件跳过。最终日志为 `evidence/projection-objects-2026-10-26/unittest-verified.log`；dsh 中间轮次日志保留在 `.lab/agents/projection-objects-20261026/`。

## 9. 未完成与风险

- 没有实现 watcher、主动 invalidation 队列、事件丢失降级；普通应用 watcher 仍应由真实数据根满足。
- 没有快照/跨卷版本协调；严格导出需要真实快照或协调复制。
- READDIRPLUS 仍为 ENOSYS；普通 READDIR 的 dirent `ino` 已是投影 nodeid，但 READDIRPLUS 未提供。每个打开目录条目会持有对应 node anchor/internal ref，超大目录可能因 node 预算或进程 fd 上限先返回 ENOSPC/EMFILE，而不是无声降级。
- 相对 symlink 被硬链接到不同目录时，READLINK 缺少别名上下文，当前明确返回 EOPNOTSUPP，避免按首次路径静默投影到错误目录。复杂 symlink 与 `..` 的通用语义仍待单独验收。
- 路径级兼容 API 的临时节点在成功或失败后回收；`resolve_path` 返回的 bare Node 只供短期管理调用，不是跨后续路径操作的持久引用。持久引用应使用 lookup/open/internal 引用。
- 未重跑 F 阶段性能矩阵；新实现保留 provider 身份检查，未以性能为验收目标。
- 本轮已验证本机内核下的替换/大小刷新/mmap 和三套客体视图；GUI/IDE、其他宿主内核、长时间负载仍待验收。

# 只读投影目录与 FD 预算修复

依据 `evidence/projection-fd-analysis-2026-10-29/report.md`，本轮处理目录浏览的 FD 放大和整个 worker 的资源准入。沿用现有 live 只读对象语义；本轮结果见[验收报告](../../evidence/projection-fd-repair-2026-10-29/report.md)。

## 目录记录与活对象分离

每个打开目录继续持有自己的 O_RDONLY FD，名称清单和固定索引 cookie 保持稳定。逐条使用原 MountGraph / `_lookup(count_ref=False)` 的 provider 身份校验和 O_NOFOLLOW 路径规则取得属性，形成 name/kind/外部 inode 记录后立即收集无引用的临时 Node。目录记录不再持有子对象 internal 引用、Node 或 anchor FD。

已 lookup、open 或被其他内部操作引用的 Node 按原引用规则存活。目录历史名称不承诺固定底层对象，后续 LOOKUP 使用当时的名称绑定；旧打开文件、GETATTR(fh)、mmap 仍基于原对象。provider 失效时新目录 fail closed；旧名称流继续按固定清单分页。READDIR 不替代 LOOKUP，不人为减少 nlookup。

## inode 碰撞所有权

继续使用原 view/provider/mount/dev/ino 的对外 inode 计算。`_inode_owners` 加 `_inode_refs` 同时覆盖活跃 Node 和目录条目记录：扫描条目先认领 inode 元数据，再释放临时节点；同一硬链接/多个目录流分别计数，最后一份 Node 或目录记录释放时删除所有权。整个目录构建期间及其返回后，碰撞检查都不会因临时节点回收而失效；碰撞仍明确 EOVERFLOW，失败回滚已建立的记录与 FD。

所有权表规模受 node 与目录条目总预算共同限制，无永久历史字典。路径兼容 API 的一次性清单现在也执行目录预算。bytes 仍是 `UTF-8 name length + 64` 的原有账面预算，不是 RSS 上限。仍然 O(N) 名称/身份元数据，未实现流式合并、磁盘溢出或 READDIRPLUS。

## worker FD 准入

在 provider 初始化、根创建、新 LOOKUP、文件/目录 OPEN 和一次性目录操作前，读取当前 RLIMIT_NOFILE 并枚举进程的实际 FD。计入 provider、anchor、handle、FUSE、控制、日志和其他进程内 FD；枚举自身 FD 不计入常驻数。若外部降低 soft limit，只统计其下的已占用槽位用于准入，同时报告整个进程的实际 FD 数。

准入保留当前操作所需的 1 或 4 个槽位，另留 16 个控制/启动/退役余量。当前对象操作串行；provider 验证最多 source probe + fdinfo 两个临时 FD；目录额外一个流 FD，scandir 自身的副本在逐项 lookup 前已关闭。provider 相对路径 walk 改为至多保留前一个/当前组件两个 FD，不随深度增长。控制端只串行接受一个 peer，状态读取及 readiness journal 使用短生命周期 FD；启动/退役的 socketpair、pipe 和 error pipe 留在余量内。16 是针对这些调用链的保守预算，已测低限额与并发控制查询；不承诺任意外部线程或全系统 ENFILE 下始终可建立新连接。

预算不足时返回 EMFILE，不驱逐活跃对象；OS 实际 EMFILE/ENFILE/ENOMEM 保留错误。READ/pread、GETATTR(fh)、RELEASE、FORGET 不需要新对象准入。控制 accept 遇瞬时 EMFILE/ENFILE/ENOMEM/EINTR 后有界等待重试，避免资源恢复后控制服务仍永久退出。

路径级 read 复用原对象 OPEN/READ/RELEASE，避免绕开准入或 handle 计数。未改变宿主或日常 worker 的默认 NOFILE；256 仅用于隔离测试 worker。

## 观测和限制

status 新增 actual soft/hard limit、进程 FD 当前值及采样峰值、预算拒绝次数、测量 errno、anchor/provider/handle FD、lookup-only nodes、lookup/internal refs、目录 identity refs。FD 测量失败明确 `null` 加 errno；峰值是采样峰值，不是内核精确高水位。

纯 READDIR 持久 FD 随打开目录数增长；stat、ls -l、文件管理器元数据读取仍创建实际 lookup Node。内核保持 nlookup 时仍需 anchor：本机低限额下大规模 stat 明确达到预算，关闭普通文件不等于收到 FORGET。禁止通过强制清零、LRU 关活锚点或按路径重开“恢复”容量。真实文件句柄压力关闭后释放 FD 可恢复请求；lookup-only 压力需内核 FORGET 或正常视图退役。

每次准入枚举进程 FD 带来额外开销；本轮没有吞吐/时延 A/B 或长时性能结论。外部 watcher、严格快照/跨卷、ACL/xattr、跨宿主、通用 IDE/索引验收仍开放。普通项目仍使用 bind 热路径。
